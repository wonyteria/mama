# 나는 엄마다 — 엄마 중심 UX 개선 명세

> 이전 초안 — 구현 기준으로 사용하지 않는다. [최종 제품 설계 V2](DEVIN_PRODUCT_DESIGN_V2.md)가 이 문서를 대체한다. 대화는 제외되며, 지난 기한의 미완료 일은 숨기지 않고, 확실한 필수 일은 자동 등록한다.

## 제품 원칙

엄마가 앱을 읽고 판단하게 만들지 않는다. 모모가 여러 출처를 확인한 뒤 **누구의 일인지, 무엇을 해야 하는지, 언제까지인지**를 먼저 보여주고, 필요한 행동은 한 번에 끝내게 한다.

화면에서 기술 용어, 수집 방식, 내부 상태 코드는 감춘다. 불확실한 정보만 짧게 이유와 원문 확인 경로를 제공한다.

## P0: 출시 전에 반드시 수정

### 1. 홈의 할 일 개수와 내용 일치

현재 `곧 챙길 일 2개`라고 표시하면서 한 건만 보여준다. 숫자는 실제 화면에서 확인 가능한 항목 수와 항상 같아야 한다.

- 카드에 우선순위 순으로 최대 3건을 제목과 기한까지 표시한다.
- 4건 이상이면 `그 밖에 N개`와 `모두 보기`를 표시한다.
- 공지에서 찾은 일과 이미 모모에게 맡긴 일을 중복 계산하지 않는다.
- 완료, 취소, 지난 기한, 정정 전 공지는 개수에서 제외한다.
- 개수를 누르면 같은 항목이 같은 순서로 나오는 `챙길 일` 화면으로 이동한다.

검수: 홈 숫자, 표시된 목록, 전체 목록의 미완료 개수가 모든 상태에서 일치해야 한다.

### 2. 알림 상세를 행동 중심으로 재설계

현재 원문과 분석 설명이 섞여 있어 핵심 행동을 찾기 어렵다. 다음 순서로 고정한다.

1. `모모가 정리했어요`
2. 자녀 이름과 출처
3. 한 문장 결론: `율이는 내일까지 체험학습 동의서를 제출해야 해요.`
4. 핵심 정보: `할 일`, `기한`, `준비물`, `장소` 중 존재하는 것만 표시
5. 주 행동 버튼: `모모에게 맡기기`, `캘린더에 넣기`, `신청하러 가기` 중 한 개
6. 보조 행동: `원문 보기`
7. 접힌 영역: `공지 원문`, `모모가 이렇게 판단한 이유`

`근거 확인`, `원문 날짜 표현`, `수집 내용`, `정확한 시각` 같은 내부 용어는 사용자 문구에서 제거한다.

본문이 없는 푸시는 `내용이 없어요`로 끝내지 말고 `e알리미에서 이 공지를 열어볼게요`처럼 가능한 다음 행동을 제공한다.

### 3. 받은 알림 정보 구조 변경

탭 이름 `받은 알림`은 운영체제 알림함처럼 느껴지고 앱의 가치가 드러나지 않는다.

- 화면 제목: `모아본 소식`
- 보조 문구: `모모가 앱과 학교 사이트에서 확인했어요`
- 탭: `전체`, `해야 할 일`, `일정`, `참고 소식`
- 출처 필터가 필요하면 두 번째 필터로 실제 앱 이름을 사용한다.
- 패키지명, 임의로 잘린 앱 이름, 내부 source ID는 표시하지 않는다.
- 각 카드에는 출처보다 `해야 할 행동 + 기한`을 우선 표시한다.
- 같은 공지의 수정본은 하나의 카드로 합치고 `내용이 바뀌었어요`를 표시한다.

### 4. 모모 대화는 이번 버전에서 제외

현재 규칙 기반 문장 분류는 표현이 달라지면 답이 어색해질 수 있다. 이번 버전에서는 대화 진입점과 관련 문구를 제거하고 정보 수집, 요약, Todo, 반복 알림 완성에 집중한다. 대화 기능은 이 네 기능의 신뢰성과 사용성이 검증된 이후 별도 버전에서 다시 검토한다.

## P1: 엄마의 일상을 실제로 줄이는 개선

### 오늘 브리핑

앱 첫 화면은 공지 피드가 아니라 `오늘의 브리핑`이어야 한다.

- 오늘 반드시 할 일
- 내일 준비할 일
- 이번 주 신청·납부 마감
- 새로 바뀐 공지

새 소식이 여러 개 와도 건별로 울리지 않고 아침·저녁 브리핑에 묶는다. 당일 마감이나 등교 이상처럼 긴급한 일만 즉시 알린다.

### 하나의 완료 흐름

공지에서 발견한 일은 `발견 → 모모에게 맡김 → 알림 → 완료` 상태를 갖는다. 어느 화면에서 완료하더라도 홈, 브리핑, 위젯의 숫자가 동시에 바뀌어야 한다.

### 출처와 신뢰도 표현

엄마에게는 `일부 확인`, `DOM 계약`, `API 키 없음` 대신 다음 세 상태만 보여준다.

- `방금 확인했어요`
- `다시 로그인해 주세요`
- `일부 소식을 확인하지 못했어요` + `다시 확인`

판단이 불확실하면 모모가 확정하지 않고 `2학년 대상인지 원문에서 확인이 필요해요`라고 정확히 말한다.

### 오류 복구

오류 문구마다 사용자가 할 수 있는 버튼을 한 개 제공한다. 예: `다시 시도`, `로그인하기`, `알림 허용하기`, `원래 앱 열기`. 단순히 설정으로 가라고 지시하지 않는다.

### 초기 설정

권한을 한꺼번에 요구하지 않는다. 앱 연결을 켜는 순간 알림 접근을, 첫 브리핑을 켤 때 알림 권한을, 첫 일정 저장 때 캘린더 권한을 요청한다. 권한 요청 전에는 `왜 필요한지`를 한 문장으로 설명한다.

## 문구 기준

- `공지 분석 결과` → `모모가 정리했어요`
- `받은 알림` → `모아본 소식`
- `곧 챙길 일 2개` → 실제 항목 2건을 함께 표시
- `날짜 확인하고 모모에게 맡기기` → `이 일 모모에게 맡기기`
- `원문 날짜 표현` → `언제`
- `후보 1 · 부탁 1` → `새 소식 1 · 맡긴 일 1`
- `수집 상태` → `마지막 확인` 또는 복구가 필요할 때만 상태 표시

문장은 엄마에게 말하듯 짧게 쓴다. 한 화면에서 같은 정보를 제목, 설명, 상태 문구로 반복하지 않는다.

## 구현 순서

1. 홈 개수 산정과 전체 목록을 하나의 데이터 projection으로 통합
2. 알림 상세 화면을 요약 우선 구조로 변경
3. 받은 알림의 분류와 명칭 변경
4. 모모 대화 진입점 제거와 기존 부탁의 Todo 이전
5. 브리핑 우선순위와 묶음 알림 적용
6. 로그인 만료·수집 실패의 사용자 복구 흐름 통일
7. 실제 기기에서 큰 글자, 잠금 화면, 오프라인, 권한 거부 상태 검증

## 완료 조건

- 홈의 숫자와 목록이 100% 일치한다.
- 엄마가 알림 상세를 연 뒤 5초 안에 `무엇을 언제 해야 하는지` 말할 수 있다.
- 주요 공지에서 앱 진입 후 2번 이내의 탭으로 맡기기·일정 저장·원문 이동을 끝낸다.
- 같은 공지를 중복으로 할 일에 만들지 않는다.
- 기존 대화로 저장한 부탁을 보존하고 Todo에서 확인할 수 있다.
- 모모 대화로 연결되는 홈·알림·위젯의 진입점이 남아 있지 않다.
- 글자 크기 150%, 작은 화면, TalkBack에서도 핵심 행동을 사용할 수 있다.
- 수집 실패, 로그인 만료, 권한 거부마다 화면 안에서 복구 경로가 보인다.

## 사용자 검증 시나리오

실제 엄마 5명에게 설명 없이 다음을 요청한다.

1. 내일까지 할 일을 찾는다.
2. 준비물을 모모에게 맡긴다.
3. 공지 원문을 확인한다.
4. `토요일 3시 소아과`를 캘린더에 넣는다.
5. 완료한 일을 처리한다.

각 과업의 성공 여부, 탭 수, 소요 시간, 망설인 지점, 잘못 이해한 문구를 기록한다. 성공률 90% 미만이거나 한 과업이 평균 30초를 넘으면 출시 전에 다시 고친다.
