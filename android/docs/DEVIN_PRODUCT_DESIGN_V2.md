# 나는 엄마다 — 수집·정리·챙김·체크 최종 제품 설계 V2

문서 상태: 개발 인계용 설계. 구현·실기기 합격 보고서가 아니다.
개발 담당: Devin. 이번 작업의 범위: 제품 검토와 설계만.
우선순위: 이 문서가 DEVIN_CORE_PRODUCT_SPEC.md와 DEVIN_UX_IMPROVEMENT_SPEC.md를 대체한다.

## 1. 제품 목표와 범위

**내 아이의 소식을 모아 해야 할 일을 자동으로 정리하고, 끝낼 때까지 잊지 않게 챙겨주는 앱.**

엄마가 반복해서 해야 하는 행동은 원칙적으로 두 가지다. 실제 일을 처리하고 체크하기, 예외적으로 로그인이나 권한을 복구하기. 확실한 공지마다 추가·확인·판단 버튼을 누르게 하지 않는다.

이번 버전 필수: 자녀별 수집 범위 확인, 푸시 없는 자동 조회, 근거 있는 공지 정리, 자동 할 일 생성, 준비물 부분 체크, 묶음 브리핑, 미루기, 완료와 알림 취소, 정정 공지 반영, 실패 복구.

제외: 자유 대화·대화형 명령·마이크 진입점·자동 구매·자동 동의/제출·사진첩 수집·학부모 공유. 모모 캐릭터는 브리핑과 상태 안내에 작게 사용한다.

성공 경험: ‘여러 앱을 뒤지지 않고 오늘 할 일을 알았다. 끝낸 일은 다시 신경 쓰지 않아도 됐다.’ 지원하지 않는 출처까지 모두 확인했다고 말하지 않는다.

## 2. 기존 개선안 검토와 수정 결정

| 기존 문제 | 왜 불편하거나 위험한가 | V2 결정 |
|---|---|---|
| 공지마다 할 일에 추가/맡기기 | 판단과 입력을 엄마가 반복 | 대상·행동이 명확한 필수 일은 자동 등록. 일정이 불분명하면 날짜 없는 할 일로 보존 |
| 후보 개수 + 부탁 개수 | 중복·누락, 제목만 하나 표시 | 저장된 동일 할 일 집합에서 숫자·카드·브리핑 생성 |
| 모든 화면 숫자는 항상 같음 | 오늘 목록과 전체 목록은 기간이 다름 | 같은 자녀·기간·상태 필터에서는 같아야 함. 기간을 화면에 명시 |
| 지난 기한은 목록 제외 | 미완료 일이 사라짐 | ‘기한이 지났어요’ 묶음으로 유지. 완료·제외는 명시적 행동 |
| 세 번 미루면 알림 중단 | 잘 잊는 사용자에게 가장 필요한 안내가 끊김 | 횟수 대신 방해를 줄이는 빈도 정책. 할 일은 유지 |
| 읽음·완료 혼용 | 공지만 봐도 일을 끝낸 것처럼 보임 | 읽음은 소식 상태, 완료는 할 일 상태로 독립 |
| 선택 활동·대상 불명 모두 참고 소식 | 중요한 불확실 공지를 묻어버림 | 선택 활동과 확인하지 못한 필수 가능 정보를 구분 |
| 제목이 비슷하면 공지 병합 | 형제·날짜·반이 다른 일이 사라질 수 있음 | 식별자/공식 원문 연결 우선, 불확실한 병합은 금지 |
| 앱만 표시하기 위해 웹 작업도 중지 | 앱 푸시에 없는 본문을 얻을 경로 상실 | 서비스 행은 하나. 검증된 본문 조회 경로는 내부에서 병행 가능 |
| 연결 화면에 제목·건수·기술 상태 전부 표시 | 설정 화면이 다시 복잡해짐 | 기본은 토글+짧은 상태. 확인 시각·범위·실패는 행 상세에 표시 |
| 로그인 만료·오늘 마감이면 모두 긴급 | 같은 문제가 반복해서 울림 | 사건별 한 번의 안내와 묶음 복구. 실제 긴급 변경만 즉시 |
| 자유 질문 품질 개선 | 이번 목표에 개발 집중이 분산 | 대화 경로 제거. 기존 저장한 부탁 데이터는 Todo로 이전 |

## 3. 현재 코드에서 확인한 출발점

다음은 저장소를 읽어 확인한 구현 구조다. 실제 사용자 휴대폰 재현 결과와는 구분한다.

- `ui/ProbeScreens.kt`: 홈은 공지 후보 수와 별도 부탁 수를 더하고 대표 공지 한 건에 우선 버튼을 제공한다. 목록의 출처명은 SourceCatalog의 대체 이름으로 바뀔 수 있다. 상세에는 원문과 판단 설명이 함께 노출된다.
- `task/AssistantTaskStore.kt`: 완료 여부·기한·알림·suspended·알림 발생 식별자는 존재한다. 하위 준비물과 읽음/완료 분리, 명확한 제외 사유와 정정 이력은 설계를 보강해야 한다.
- `reminder/BriefingReminders.kt`: 브리핑용 선별 함수가 별도로 존재한다. 홈·브리핑이 같은 기준을 사용하도록 통합 필요.
- `connector/ConnectorModels.kt`, `sync/SourceSyncScheduler.kt`: 앱 우선 표시 규칙이 웹 작업 제외와 연결되어 있다. 표시 정책과 수집 가능성 정책을 분리할 필요가 있다.
- `sync/SourceStatusPresentation.kt`: 여러 출처 상태를 한 문장으로 합친다. 어떤 출처의 어느 범위가 확인됐는지 별도로 보존해야 한다.

Devin은 최신 브랜치를 다시 확인해 위 위치를 출발점으로 삼는다. 본 문서의 코드를 그대로 가정하거나 로컬 미커밋 변경을 덮어쓰지 않는다.

## 4. 정보 구조

하단 메뉴는 세 개로 고정한다: **오늘 / 할 일 / 소식**. 상단 설정 버튼 안에 자녀, 연결, 알림 시간을 둔다. 자녀가 한 명이면 선택기를 숨기고 두 명 이상일 때만 전체/자녀 필터를 제공한다.

| 화면 | 목적 | 중심 행동 |
|---|---|---|
| 오늘 | 지금과 내일 준비에 필요한 일을 한눈에 | 체크, 미루기 |
| 할 일 | 남은 일·기한 없는 일·완료 이력 관리 | 체크, 직접 추가, 수정 |
| 소식 | 수집한 원문과 정리 내용을 다시 찾기 | 읽기, 검색, 원문 열기 |
| 소식 상세 | 공지 하나에서 무엇을 해야 하는지 이해 | 해당 할 일 체크, 원문 보기 |
| 연결 | 서비스별 지원 범위와 문제 복구 | 연결 켜기, 로그인 복구 |
| 알림 설정 | 생활 시간과 알림 강도 선택 | 아침/저녁 시간 변경 |

소식 필터는 ‘전체 / 학교·기관 / 관심 소식’으로 제한한다. 소식의 완료 탭은 만들지 않는다. 완료 여부는 할 일 화면에만 존재한다. 출처가 많으면 고정 폭 칩을 나열하지 말고 ‘출처 선택’ 바텀시트로 제공한다.

## 5. 수집 설계: 보이는 서비스와 수집 경로 분리

### 5.1 연결 단위

엄마에게 e알리미는 한 행만 보인다. 내부적으로는 앱 푸시·검증된 개인 공지 조회·첨부 읽기가 서로 다른 기능이다. 앱 설치 여부만으로 본문 조회가 된다고 판단하지 않는다.

연결 행의 상태 예:
- ‘알림 수신 중’: 푸시만 수신 가능. 전체 공지 확인을 의미하지 않음.
- ‘공지 자동 확인 중’: 인증·목록·상세 조회가 모두 검증된 출처.
- ‘본문을 확인하지 못했어요’: 목록/푸시는 있으나 본문 미수집.
- ‘다시 로그인’: 개인 공지 조회가 인증 만료로 중단.
- ‘자동 조회 미지원’: 검증된 조회 방법 없음. 작동하는 토글로 위장하지 않음.

지원되는 경로만 실제 가동한다. 원문 조회 경로가 없다면 ‘앱만 연결하면 모든 공지를 확인’이라는 안내를 쓰지 않는다. 사용자 요청 없이 다른 앱의 설치·로그인을 완료했다고 표시하지 않는다.

### 5.2 수집 범위 모델

서비스별로 다음을 독립 저장한다.
- `notificationListening`: 푸시 수신 준비 여부.
- `listingCoverage`: 조회한 게시판·기간·페이지와 조회 완료 여부.
- `bodyCoverage`, `attachmentCoverage`: 본문·첨부 확보 여부.
- `lastAttemptAt`, `lastSuccessfulListingAt`, `lastBodySuccessAt`, `lastNotificationReceivedAt`.
- `sessionState`, `failureKind`, `retryAt`, `supportedCapabilities`.

푸시가 조용한 것은 새 공지가 없다는 증거가 아니다. 제목 한 개를 받았다고 전체 목록 성공 시각을 갱신하지 않는다. 마지막 페이지까지 끝낸 조회와 중간 실패를 구분한다.

### 5.3 푸시 없는 자동 조회

푸시 도착과 무관한 주기 작업이 있어야 한다. 앱을 열지 않은 상태에서 새 공지 게시 → 목록 조회 → 본문/첨부 → 자녀 선별 → Todo 저장 → 브리핑 반영까지 시험한다.

초기 운영 목표: 공개 출처는 2시간 간격, 개인 출처는 지원 조건과 부하 제한 안에서 2~4시간 간격을 기본 후보로 삼아 기기에서 검증한다. 최초 연결·연결 복구·앱 복귀 시에는 오래된 출처만 추가 조회한다. 같은 출처 동시 실행은 하나로 합친다.

이는 목표 간격이며 실시간 보장이 아니다. Android 주기 작업은 절전 상태 때문에 지연될 수 있다. [공식 WorkManager 설명](https://developer.android.com/develop/background-work/background-tasks/persistent/getting-started/define-work)

기본 재시도 제안: 일시적 통신 실패 15분→1시간→4시간, 서버 재시도 지시 우선. 인증 실패는 반복 암호 시도를 멈추고 재로그인 1회 요청. 공식 세션 갱신 수단이 있을 때만 갱신하며 영구 로그인은 보장하지 않는다. 공개 조회는 사용자 개인정보를 보내지 않는 공유 서버 수집 방식도 검토 가능하나, 개인 세션은 별도 허가 없이 서버로 옮기지 않는다.

### 5.4 데이터 부족 시 홈 표현

| 수집 결과 | 홈 안내 |
|---|---|
| 지원된 자동 조회 범위 성공, 미완료 0 | ‘확인한 소식에서는 지금 챙길 일이 없어요’ + 확인 시각 |
| 푸시 연결만 있음, 미완료 0 | ‘받은 알림에서는 챙길 일이 없어요’ + ‘전체 공지는 확인하지 못했어요’ |
| 핵심 출처 조회 실패, 미완료 0 | ‘새 소식을 모두 확인하지 못했어요’ + 복구 버튼 |
| 저장된 미완료는 있으나 일부 실패 | 기존 할 일을 유지하고 작게 누락 가능성 안내 |
| 최초 조회 중 | ‘학교 소식을 확인하고 있어요’. 0개/문제없음으로 표시하지 않음 |

### 5.5 자녀 매칭과 출결

학교는 공식 코드로 구분한다. 정자초등학교처럼 동명 학교는 지역 확인이 끝나기 전에 자동 확정하지 않는다. 학년·반·교육기관·자녀 식별자가 충돌하면 개인 Todo로 확정하지 않는다.

판정은 APPLIES / EXCLUDED / UNKNOWN. 전체 학년 안내는 해당 학교 학생에게 적용. 명시된 타 학년 활동은 기본 개인 피드에서 제외하되 소식 검색의 ‘다른 학년 포함’에서 찾을 수 있다. UNKNOWN은 자동으로 더 읽을 수 있는 본문/첨부 경로를 우선 시도한다. 그래도 해결되지 않으면 ‘본문 확인 필요’ 카드 하나로 묶고 명령형 할 일·임의 마감은 만들지 않는다.

출결은 실제 제공된 등교/하교 확인 시각만 표시한다. 알림이 없다는 이유로 결석·미등교·안전 이상을 추론하지 않는다. 불확실할 때는 ‘등교 기록을 아직 확인하지 못했어요’라고 표현한다. 검증된 출결 출처가 없는 기기에는 등교 상태 카드를 만들지 않는다.

## 6. 공지 이해와 자동 할 일 생성

### 6.1 입력부터 저장까지

원문 수집 → 현재 수정본 선택 → 본문/이미지/PDF에서 근거 추출 → 자녀 매칭 → 필수/선택/참고 분류 → 행동·날짜 분리 → 근거 검증 → Todo/일정 저장 → 화면·알림 갱신.

모델을 사용하더라도 출력은 후보 자료다. 제목·날짜·준비물·대상마다 원문 위치(문장/페이지/표 셀)와 원문 버전을 연결한다. 허용된 출력 구조와 날짜 관계를 검사한 값만 제품에 반영한다. 원문 속 지시문은 데이터이며 도구 실행 명령으로 취급하지 않는다.

본문 표·이미지 공지는 글자 읽기만으로 끝내지 않는다. 학년 열, 날짜 열, 행 연결을 보존한다. 한 공지에 다른 학년 프로그램이 함께 있으면 자녀에게 맞는 행만 정리한다. 전체 이미지 보관함은 만들지 않되 필요한 공지 이미지/첨부는 근거 보기에서 열 수 있어야 한다.

외부 처리 시 인증정보·세션·다른 공지·불필요한 자녀 실명은 전송하지 않는다. 외부 처리 동의가 없다면 지원하는 로컬 처리만 수행하고, 읽지 못한 내용은 미확인으로 남긴다. 모델 성능·요금제 선택은 이 제품 설계의 완료 전제가 아니다.

### 6.2 생성 규칙

| 원문 상황 | 생성 결과 |
|---|---|
| 대상 명확 + 필수 제출 + 정확한 기한 | 제출 Todo 자동 생성, 기한 알림 예약 |
| 대상 명확 + 필수 준비물 + 행사 날짜 | 준비물 묶음 자동 생성. 행사 전날을 준비 권장일로 사용 |
| 대상 명확 + 해야 할 일 + 기한 없음 | 날짜 없는 Todo 생성. ‘기한 안내 없음’, 브리핑 포함, 임의 마감 금지 |
| 날짜만 있는 행사 | 앱 일정으로 보관. 할 일 숫자에는 넣지 않음 |
| 희망자 모집/선착순 신청 | 관심 소식. 사용자가 ‘신청 챙기기’를 누를 때만 Todo 생성 |
| 자녀 대상 아님 | 개인 Todo 생성 금지 |
| 본문 없음/잘못 읽음/기한 충돌 | 자동 복구 우선. 미해결이면 확인 필요 소식, 임의 제출/마감 금지 |
| 외부 앱 열기 | 제출 완료로 간주하지 않음 |

한 공지에서 동의서 제출과 준비물 챙기기는 서로 다른 할 일이다. 날짜가 없는 필수 업무를 없애지 않기 위해 ‘명확한 기한’은 자동 생성의 필수 조건에서 제외한다.

### 6.3 날짜 정책

`dueAt`(정확한 기한), `dueDate`(날짜만), `eventStart`(행사), `recommendedPrepareAt`(모모 권장 준비), `remindAt`(알림 시각)을 분리한다.

- ‘내일’은 수집 시각이 아니라 확인된 게시 시각과 원문 시간대를 기준으로 해석.
- 게시일이 불명확한 상대 날짜는 확정 금지.
- ‘금요일까지’는 날짜 기한으로 저장. 화면에 09:00/23:59를 원문 시각처럼 생성하지 않음.
- ‘다음 날 준비’와 ‘행사 신청 마감’을 혼동하지 않음.
- 준비 권장 시각에는 ‘모모가 저녁에 알려드려요’라고 표시하고 공식 기한과 구분.

### 6.4 요약 문구

요약은 1문장 결론 + 있는 사실만 최대 4줄. 빈 칸을 채우기 위한 설명, 내부 신뢰도 수치, ‘AI가 판단한 후보’는 넣지 않는다.

| 상황 | 권장 문구 |
|---|---|
| 준비물 | ‘내일 체험학습에 도시락과 물통이 필요해요.’ |
| 동의서 | ‘동의서를 9월 20일까지 제출해 주세요.’ |
| 선택 체험 | ‘2학년이 신청할 수 있는 체험이에요. 희망하는 경우에만 신청해요.’ |
| 기한 없음 | ‘동의서 제출 안내예요. 제출 날짜는 적혀 있지 않아요.’ |
| 본문 미확인 | ‘새 공지가 왔지만 본문을 아직 가져오지 못했어요.’ |
| 정정 | ‘제출 기한이 금요일에서 월요일로 바뀌었어요.’ |

## 7. 할 일 모델과 수량 규칙

### 7.1 상태를 서로 분리

Todo 기본 상태: OPEN / COMPLETED / EXCLUDED / CANCELLED.
- OVERDUE는 OPEN이면서 기한이 지난 경우 계산하는 표시 상태다.
- PARTIAL은 준비물 중 일부 완료인 경우 계산한다.
- 미루기는 `snoozedUntil`이며 완료 상태가 아니다.
- 정정은 `revision/changedFields`이며 진행 상태가 아니다.
- 공지 READ는 `readAt`에 별도 저장한다.

OPEN→COMPLETED: 사용자가 체크하거나 검증된 제출 완료 응답이 있을 때. 읽기·앱 실행·알람 끄기는 해당되지 않는다.
COMPLETED→OPEN: 되돌리기/완료 목록에서 복원. 미래에 유효한 알림만 다시 계산.
OPEN→EXCLUDED: 메뉴 ‘이번 일은 제외’. 이후 같은 수정본 재수집에도 복원하지 않음.
OPEN→CANCELLED: 원문에서 행사/요청 취소를 확인한 경우. 같은 행사에 연결된 일만 취소.

### 7.2 숫자와 묶음

표시 숫자는 준비물 개수가 아니라 부모 할 일 수다.

예: ‘동의서 제출’ 1건 + ‘준비물 챙기기’ 1건(물통·모자·도시락·돗자리) = 챙길 일 2개. 준비물은 별도 ‘2/4 준비’ 표시.

오늘 화면: ‘오늘·내일 챙길 일 N개’. 여기에는 기한 지남, 오늘·내일의 실행 권장일, 기한 없는 일을 포함한다. 각 일은 한 섹션에만 속한다. 3개까지만 보여주면 ‘3개 표시 · 전체 N개’와 같은 범위의 더 보기 링크를 제공한다.

전체 화면: ‘남은 일 N개’로 모든 OPEN 포함. 자녀/기간 필터를 바꾸면 숫자와 목록을 함께 계산한다. 위젯·브리핑도 범위와 전체 개수를 표시한다. 일정·읽지 않은 소식·확인 실패는 Todo 숫자에 더하지 않는다.

### 7.3 체크와 수정

- 체크 영역은 텍스트 열기와 분리. 누르면 로컬 저장 성공 후 완료 표시, 실패하면 이전 상태 복구와 짧은 안내.
- 작은 완료 확인창을 매번 띄우지 않는다. 하단에 ‘완료했어요 · 되돌리기’ 제공. 버튼은 8초 표시하되 완료 목록에서는 나중에도 되돌릴 수 있음.
- 체크 직후 같은 터치 위치로 다른 카드가 갑자기 이동하지 않게 짧게 완료 행을 유지한 뒤 이동.
- 준비물 하위 체크 완료를 모두 하면 부모 완료. 부모 전체 체크는 현재 하위 목록 전체 완료.
- 완료 묶음을 되돌리면 직전 하위 체크 상태를 복원. 2/4를 전체 완료했다 취소하면 2/4로 돌아감.
- 직접 추가는 제목만 필수, 자녀·기한·준비물 선택. 날짜 미지정도 저장 가능.
- 수정은 제목·기한·체크리스트·알림에 허용. 원문과 다른 사용자 수정은 출처 값과 분리 보존.
- 원문 소식 삭제가 할 일 완료를 의미하지 않는다. 연결 Todo가 있으면 삭제 범위를 명시하여 선택하게 한다. 일상 화면에는 ‘제외’를 우선 제공.

## 8. 중복과 정정

### 8.1 식별

Notice는 (서비스, 기관, 공식 문서 ID) 우선. 같은 제목의 다른 날짜 공지와 형제 공지는 자동 병합하지 않는다. 출처 간 병합은 동일 공식 링크/문서 ID 또는 검증된 동일 기관·본문·대상·행사일이 일치할 때만 수행하고 출처 목록은 남긴다.

Todo는 (Notice 그룹, 자녀 ID, 행동 종류, 행동 대상)으로 중복 방지 키를 만들되 기한 변경은 새 Todo 생성 조건이 아니다. 교체되는 준비물은 하위 항목의 의미 ID와 버전으로 구분한다.

### 8.2 정정 시 완료 보호

| 변경 | 처리 |
|---|---|
| 표현/오탈자만 수정 | 요약 갱신, 완료 유지, 별도 푸시 없음 |
| 미완료 제출 기한 변경 | 같은 Todo 갱신, 이전 예약 무효화, 새 예약 생성 |
| 완료한 제출의 기한만 연장 | 완료 유지. 다시 제출하라고 알리지 않음 |
| 준비물에 모자 추가 | 기존 체크 유지. 새 모자만 OPEN. 묶음이 완료였다면 새 필요 행동 때문에 다시 OPEN, 변경 이유 표시 |
| 물통이 보온병으로 대체 | 물통 완료 기록 보존, 새 보온병은 미완료. 의미가 달라 기존 체크 승계 금지 |
| 행사 취소 | 관련 미완료 Todo와 예약 취소. 완료 이력 보존 |
| 이미 제외한 일 정정 | 자동 부활 금지. 실질 변경은 소식 변경 표시로 남김 |
| 사용자가 고친 기한과 원문 충돌 | 사용자 값을 덮어쓰지 않음. 공식 변경을 보여주고 ‘공지 날짜로 바꾸기’ 한 번 제공 |

## 9. 알림과 브리핑

### 9.1 기본값

최초 요약이 준비되면 ‘아침 7:30 / 저녁 20:30에 챙겨드릴게요’와 시간 변경을 한 화면에 제공한다. 사용자가 알림을 켜면 권한 요청. 조용한 시간은 기본 22:00~07:00. 제안 기본값이며 출시 전 사용자 평가에서 조정 가능.

아침: 오늘 해야 할 일, 오늘 준비물, 기한 지난 일.
저녁: 내일 준비물, 다음 제출 기한, 미완료 정리.
내용 변화와 남은 일이 모두 없으면 알림을 보내지 않는다. 같은 시간대 여러 자녀는 한 브리핑에 묶는다.

### 9.2 반복과 긴급성

일반 안내는 하루 아침·저녁 두 브리핑으로 묶는다. 항목별 즉시 알림은 기본 하루 1회 이하, 같은 항목에 브리핑과 30분 안에 겹치면 합친다. 사용자가 직접 예약한 미루기 알림과 실질적 정정은 별도 사건으로 취급한다.

- 정확한 당일 마감: 마감 전 마지막 유효 안내를 보장하도록 예약 계획에 포함. 이미 같은 내용을 최근 안내했으면 중복 생략.
- 날짜만 있는 기한: 아침/저녁에 날짜로 안내, 가짜 ‘마감 1시간 전’ 예약 금지.
- 출결: 출처가 확인한 사건만 즉시 표시. 푸시 부재로 긴급 생성 금지.
- 로그인 만료: 출처별 한 번의 복구 알림. 미복구면 홈 안내와 다음 브리핑에 합침.
- 기한 지남: 사라지지 않고 다음 브리핑에 ‘기한이 지났어요’로 한 번 정리. 계속 매시간 울리지 않음.

### 9.3 미루기

‘30분 뒤 / 오늘 저녁 / 시간 선택’. 현재보다 미래인 선택지만 노출. 미루기는 Todo를 숨기거나 완료하지 않는다.

기한을 넘기는 선택이면 ‘기한 이후예요’ 표시와 기한 전 대안 제공. 사용자가 기한 이후를 명시적으로 선택하면 저장하되 놓친 일은 유지한다. 3회 제한처럼 임의로 침묵시키지 않는다.

### 9.4 알림 액션

한 항목: 준비물은 ‘챙겼어요’, 제출은 ‘제출했어요’, 읽기 전용 소식은 ‘확인했어요’. 별도 ‘나중에’와 ‘내용 보기’. 확인했어요는 해당 소식 읽음만 바꾼다.

브리핑: ‘할 일 보기 / 나중에’만. 여러 일에 대한 일괄 완료 버튼은 제공하지 않는다.

잠금 화면은 기본 자녀명·학교·본문을 숨긴다. ‘모모가 챙길 일을 정리했어요’로 표시하고 내용 열기/완료는 잠금 해제 후 진행한다. 화면 잠금 또는 권한 없는 상태에서 민감한 체크 액션이 실행되지 않아야 한다.

전체 화면은 사용자가 알람형 안내를 켠 경우 중 Android 권한과 제품 사용 요건을 만족할 때만 사용한다. 일반 브리핑은 알림을 눌러 앱의 큰 요약 화면으로 진입한다. 전체 화면 권한이 없어도 알림·체크가 동작해야 한다. [Android 14 공식 안내](https://developer.android.com/about/versions/14/behavior-changes-14#secure-fsi)

### 9.5 완료와 예약 경쟁

체크 성공 시 DB에 완료+알림 세대 증가+취소 예정 이벤트를 함께 저장한다. 알림 발송 직전 최신 상태와 세대/발생 ID를 재검사한다. 이미 완료·취소·수정된 발생이면 표시하지 않는다. 이미 떠 있는 알림도 취소한다.

재부팅·시간대 변경·앱 업데이트 후 미래 알림을 재계산한다. 절전/권한/강제 중지 때문에 전달이 지연된 경우 복귀 후 유효한 내용만 한 번에 정리한다. 시스템에 게시 요청이 성공한 것을 사용자가 실제 보았다고 기록하지 않는다.

## 10. 텍스트 와이어프레임

### S0. 처음 설정

```text
[뒤로] 누구의 소식을 챙길까요?
아이 별명  [율이                  ]
학교       [정자초 검색            ]
           학교명 · 지역 · 공식 코드 확인
학년       [2학년 ▾]  반 [선택]
[이 아이 소식 확인하기]

다음: 사용할 서비스
e알리미      설치됨     [연결]
학교 홈페이지          [자동 확인 설정]
처음 수집 결과: 공지 4개 · 챙길 일 2개
[오늘의 할 일 보기]
```

필수 입력은 별명·학교·학년. 별명은 실명 강제하지 않음. 학교 미확정이면 해당 학교 수집 시작 금지. 앱별 토글 시 필요한 권한만 요청하고 돌아오면 실제 허용 결과 확인. 처리 중에는 진행 단계와 취소/나중에 경로, 실패 시 입력 유지와 재시도.

### S1. 오늘

```text
[오늘]                                  [설정]
모모가 정리했어요                  9월 19일
오늘·내일 챙길 일 2개

□ 동의서 제출                       내일까지
  율이 · e알리미                         [›]

□ 체험학습 준비                       내일
  율이 · 2/4 준비                         [⌄]
  ☑ 도시락  ☑ 물통  □ 모자  □ 돗자리

내일 일정
체험학습 · 오전 9시                    [자세히]

새로 바뀐 소식 1개                      [보기]
학교 소식 09:10 확인 · e알리미 본문 미확인 [연결]

[오늘]              [할 일]              [소식]
```

대표 마스코트는 작은 크기, 할 일보다 높은 시각 우선순위 금지. 2개라면 두 항목이 모두 보이거나 명확한 더 보기 제공. Empty는 수집 성공/실패/최초 조회별 별도 문구. Loading 중 저장된 목록 유지. Error는 화면 전체를 가리지 않고 영향 있는 출처와 복구 링크 표시.

```text
□ 학원 안내문 회신            기한 안내 없음
```

행 탭은 상세, 체크박스는 완료. 길게 누르기만으로 제공되는 필수 행동 금지. 메뉴는 수정/이번 일 제외/알림 시간. 완료 목록은 완료일과 되돌리기. 오프라인 체크·수정 지원. 저장 실패는 체크 원상복구하고 ‘저장하지 못했어요 · 다시 시도’ 표시.

### S3. 소식 목록

```text
[소식]                      [제목·내용 검색]
[전체] [학교·기관] [관심 소식]      [출처 ▾]

체험학습 준비 안내                    변경됨
율이 · 내일 도시락과 물통이 필요해요
챙길 일 2개 · 1개 완료          e알리미 · 09:10

학사 일정 안내
다음 주 월요일은 학교 재량휴업일이에요
학교 홈페이지 · 오늘
```

읽지 않음은 작은 점, 큰 배지로 압박하지 않음. 원문이 없으면 ‘본문 확인 중/미확인’으로 표시하고 요약을 날조하지 않음. 일괄 읽음은 할 일·알림 완료와 무관. 검색 결과 없음과 수집 자료 없음 문구를 구분.

### S4. 소식/할 일 상세

```text
[뒤로] 체험학습 안내                  [더보기]
율이 · e알리미 · 학교명
내일 체험학습에 도시락과 물통이 필요해요.

해야 할 일
□ 동의서 제출                 내일 오전 9시까지
□ 준비물 챙기기               2/4 준비
  ☑ 도시락  ☑ 물통  □ 모자  □ 돗자리

행사 날짜  9월 20일
장소       원문에 있는 경우만
다음 안내  오늘 저녁 8:30             [바꾸기]

[원문 보기]                        [전체 내용 ▾]
```

확실한 필수 일에는 ‘추가/맡기기’를 요구하지 않는다. 이미 자동으로 생성된 상태. 선택 행사일 때만 ‘신청 챙기기’ 주 버튼. 원문 링크가 없으면 ‘e알리미 열기’라고 표시해 특정 공지가 바로 열린다고 약속하지 않는다. 이미지 확대와 페이지 이동은 원문 영역에서 제공. 요약 실패 시 실제 확보한 원문과 실패 안내를 제공.

### S5. 브리핑과 알람형 상세

```text
[닫기/소리 끄기]               모모의 저녁 정리
내일을 위해 2가지만 챙겨주세요

□ 동의서 제출                내일 오전 9시까지
□ 준비물 챙기기              아직 모자·돗자리

[할 일 자세히 보기]
[30분 뒤 다시]
```

알람 모드의 ‘소리 끄기’는 알림 소리만 중단. 완료나 읽음을 몰래 바꾸지 않는다. 목록을 보고 체크할 때에만 개별 완료. 작은 화면에서 시간/캐릭터보다 내용이 먼저 보이게 하고 기기 큰 글자에서도 버튼을 가리지 않게 스크롤 영역과 하단 행동 분리.

### S6. 연결

```text
[뒤로] 소식 연결
e알리미            [켜짐]
알림 수신 중 · 본문 확인 필요           [›]
학교 홈페이지      [켜짐]
오늘 09:10 공지 확인                    [›]
하이클래스         설치하면 연결 가능  [설치 보기]
```

행 상세에서 지원 범위, 마지막 성공 시각, 미수집 범위, 필요한 로그인 하나만 안내. 재로그인은 해당 서비스로 바로 연결하고 복귀 후 실제 목록 조회 성공으로 상태 갱신. 로그인 창을 닫았다고 성공 처리하지 않음.

### S7. 알림 설정과 직접 추가

설정: 아침/저녁 각각 토글+시간, 조용한 시간, 알람형 안내(지원될 때), 잠금 화면 내용 표시. 첫 화면에는 세부 재시도 횟수나 내부 정책 없음.

직접 추가 바텀시트: 제목(필수) / 자녀(기본값) / 날짜·시간(선택) / 준비물(선택) / 저장. 오류가 나도 입력 유지. 단일 체크/완료에 네트워크가 필요하지 않음.

## 11. 사용자 흐름

F1 최초: 자녀 입력 → 학교 지역 확인 → 가능한 출처 제안 → 연결 활성화와 필요한 권한 → 첫 조회 → 자녀별 Todo 자동 저장 → 오늘. 실패 출처는 복구 카드, 성공 출처 결과는 바로 사용.

F2 푸시 없는 수집: 예약 도래 → 인증 확인/가능한 갱신 → 목록/본문/첨부 조회 → 대상·행동 검증 → 중복 없이 저장 → 다음 브리핑. 본문 미확인은 재시도하고 이미 아는 일을 지우지 않음.

F3 알림 확인: 묶음 알림 → 잠금 해제(필요 시) → 브리핑에서 남은 일 → 준비물 개별 체크 → 저장 → 숫자/예약 즉시 반영 → 종료.

F4 완료: 어디서든 체크 → 최신 버전 확인 → 저장 성공 → 예약 취소 → 되돌리기. 체크 중 수정 공지가 도착해 새 행동이 생겼으면 최신 항목을 보여주고 새 행동까지 완료 처리하지 않음.

F5 미루기: 나중에 → 유효한 시각 선택 → 원래 미완료 유지 → 해당 시간 한 번 재안내. 이전 발생 버튼을 재클릭해 중복 예약하지 않음.

F6 재방문: 앱 열기 → 저장된 목록 즉시 → 필요한 출처만 갱신 → 바뀐 내용만 반영. 홈을 여러 번 열어도 같은 공지에서 새 Todo가 늘지 않음.

F7 로그인 만료: 조회 중 인증 만료 → 기존 데이터 유지 + 복구 안내 한 번 → 서비스 로그인 → 복귀 시 실제 조회 → 중단 기간 누락분 보충 → 정상 상태.

F8 선택 체험: 관심 소식 읽기 → 신청 챙기기 → 선택 활동 Todo 등록 → 신청 앱 열기 → 사용자 제출 체크 또는 검증된 외부 성공 확인. 앱 열기만으로 신청 완료 아님.

## 12. 개발 데이터·동작 계약

### 12.1 핵심 엔터티

| 데이터 | 필수 필드 |
|---|---|
| Child | id, 별명, 학교 코드/지역, 학교급, 학년, 반(선택), profileRevision |
| ServiceConnection | id, childScope, enabled, capabilities, authState, coverage, 각 성공/시도 시각, 오류 종류 |
| NoticeRevision | noticeGroupId, originIds[], revisionId, title, rawContentRef, 게시/수집 시각, 출처 링크, coverage, contentHash |
| ExtractedFact | noticeRevisionId, type, value, evidenceLocation, validationState |
| NoticeAudience | noticeGroupId, childId, APPLIES/EXCLUDED/UNKNOWN, 근거 |
| Todo | id, dedupeKey, childId, noticeGroupId(선택), actionType, title, status, 날짜 정밀도, dueDate/dueAt, prepareAt, userOverrides, version, completedAt |
| TodoItem | id, todoId, 의미 키, text, completedAt, sourceRevisionId, active |
| NewsRead | noticeGroupId, readRevisionId, readAt |
| ReminderOccurrence | id, todoId/briefingScope, taskVersion, generation, scheduledAt, state, postedAt, snoozedUntil |
| PendingEffect | idempotencyKey, 완료/수정에 따른 예약 생성·취소 이벤트, 재시도 상태 |

개인정보와 원문은 기존 암호화 정책을 유지한다. 핵심 상태·알림 세대 변경·후속 작업 기록을 원자적으로 저장할 수 있어야 한다. 기존 저장소가 이를 지원하지 않으면 Room 등 기존 프로젝트 수단을 확인하여 이행 설계를 먼저 작성한다. 임의 새 의존성 추가는 기본 해법이 아니다.

### 12.2 조회와 명령

조회 공통 입력: 자녀 범위, 현재 시각/시간대, 기간 필터, 상태 필터. 출력: 동일하게 정렬된 Todo ID 집합, 부모 건수, 각 부모의 준비물 완료 수, 기간 레이블, 수집 coverage.

명령 `completeTodo`, `toggleItem`, `undoCompletion`, `excludeTodo`, `editTodo`, `snooze`, `applyNoticeRevision`은 requestId와 expectedVersion을 받는다. 중복 명령은 같은 결과를 반환한다. version 충돌은 새 항목을 임의 체크하지 않고 최신 상태를 반환한다.

완료 결과에는 바뀐 Todo와 취소해야 할 알림 발생 목록이 포함된다. 저장 직후 화면은 갱신하고 OS 예약 취소가 지연돼도 발송 직전 DB 검사로 오래된 알림을 막는다.

### 12.3 예외·권한 계약

- 수집: 해당 연결/자녀 범위 동의 및 필요한 접근 권한. 끄면 새 수집과 관련 작업 중단, 기존 자료를 자동 삭제하지 않음.
- 체크/수정/직접 추가: 초기 로컬 저장소 준비 후 사용 가능. 네트워크 권한 불필요. 기기 잠금 상태에서는 내용 접근 정책 적용.
- 알림: 권한 거부 시 Todo는 저장하고 ‘휴대폰 알림은 꺼져 있어요’ 안내. 체크 기능 자체를 막지 않음.
- 원문: 검증된 https 링크 또는 해당 앱 열기. 임의 URL 스킴 실행 금지.
- 일정 내보내기: 선택 기능, 최초 한 번 캘린더 선택과 필요한 권한. 앱 내부 일정은 캘린더 권한 없이 표시. 내보내기 성공은 확인된 경우만 표시.
- 자녀 학교/학년 변경: 새 profileRevision으로 재선별. 이전 학교 할 일은 보존 후 ‘이전 학교’ 표시, 미래 자동 수집 범위만 갱신. 말없이 완료/삭제하지 않음.
- 로그아웃/연결 해제: Todo 삭제·완료와 다름. 마지막 출처 자료의 시각 유지, 더 확인되지 않는다는 상태 표시.
- 보관기간: 원문 만료와 Todo 수명을 분리. 미완료 업무는 14일이 지나도 자동 삭제 금지. 원문 삭제 시 최소 근거 요약은 기존 동의·보관 정책 안에서 유지하고 없으면 원문 만료 표시.

### 12.4 기존 사용자 이전

기존 AssistantTask ID·완료·기한·알림을 보존하여 Todo로 변환. 대화 제거로 이미 저장된 부탁이 없어지면 안 된다. 기존 sourceNotificationId로 공지 매핑, 불명확한 연결은 LEGACY로 유지. 기존 알림은 이전 완료 후 세대 갱신해 새 예약과 중복 실행되지 않게 한다.

이전은 재실행해도 항목이 늘지 않으며 중간 실패 시 이전 데이터를 보존한다. 체크/미루기 이력은 테스트에서 이전 전후 대조한다.

## 13. Devin 구현 작업 순서

모든 핵심 항목은 이번 버전의 필수 범위다. P0/P1로 표시해 브리핑·반복 알림을 다음 버전으로 밀지 않는다.

| 작업 | 결과 | 의존성/합격 근거 |
|---|---|---|
| D1 현재 기준선 | 실제 출처별 푸시/조회/본문/첨부 지원표와 재현 영상 | 동작하지 않는 경로를 정상으로 표시하지 않음 |
| D2 단일 Todo·이전 | 상태 모델, 부분 체크, 읽음 분리, 버전 명령 | 수량·완료·이전 회귀 테스트 |
| D3 수집 파이프라인 | coverage, 인증 복구, 푸시 없는 조회, 중복/정정 | D2와 통합, 게시 후 무푸시 시나리오 |
| D4 오늘/할 일/소식 | 위 와이어프레임과 상태별 화면 | 같은 필터의 숫자와 목록 일치 |
| D5 챙김 알림 | 묶음·미루기·완료 취소·재부팅 복구 | D2 필수, 완료/발송 경쟁 테스트 |
| D6 문구·사용성 | 일반 용어, 큰 글자, 접근성, 원문 경로 | 실기기 과업 검증 |

위젯 개선·외부 캘린더 확대는 핵심 흐름 합격 후 진행. 기존 위젯이 있으면 오래된 대화 링크를 제거하고 최소한 오늘 화면을 열도록 변경한다. 대화 Activity로 들어가는 모든 홈/알림/위젯/딥링크는 오늘 또는 할 일로 교체한다.

실제 출처가 없어 검증하지 못한 기능은 ‘미검증’으로 남긴다. 테스트용 가짜 공지의 성공을 실서비스 자동 수집 성공으로 보고하지 않는다.

### 실제 엄마 사용성 검증

5명은 탐색 조사이며 통계적 출시 품질 보증으로 취급하지 않는다. 실제 학교 계정은 소유자 동의 하에 사용하고 화면·기록 공유 시 아이 정보는 가린다.

과업: 내일 준비물 찾기 → 두 항목 체크 → 완료 되돌리기 → 미루기 → 원문 열기 → 수집 누락 상태 구분. 설명 없이 시행하고 성공 여부/소요 시간/탭 수/헷갈린 표현을 기록한다.

목표: 핵심 행동·기한을 5초 안에 이해, 체크는 목록에서 1탭, 참가자별 주요 과업 모두 완료 가능. 150% 글자와 좁은 화면에서도 모든 항목·버튼 도달 가능. 테스트 실패를 평균치로 숨기지 않고 실패 사례별 수정한다.

### 수집·정리 품질 검증

동의받은 실제 공지와 고정 검증 자료에서 사람이 정답 목록을 먼저 만든다. 분모에는 제목뿐인 알림·이미지·PDF·여러 학년·정정 공지·기한 없는 일도 포함한다.

- 수집 누락: 지원 범위의 실제 공지 수 대비 수집 공지 수와 본문 확보 수를 각각 보고.
- Todo 누락/오탐: 정답 필수 행동 대비 재현율/정밀도를 별도 보고.
- 필드 오류: 자녀 대상·제출 기한·준비물의 원문 대조 결과를 보고.
- 지연: 게시→조회→Todo 저장→알림 요청까지 각각 기록.
- 사용자 부담: 하루 앱/원문 왕복 횟수, 불필요한 알림 횟수, 직접 고친 항목 수 기록.

대상과 기한을 잘못 확정한 중대한 오류, 완료 후 재알림, 중복 생성, 데이터 손실은 출시 차단 조건이다. 검증 집합에서 오류 0건을 확인하더라도 모든 미래 공지가 무오류라고 홍보하지 않는다.

## 15. 설계 교차검수 결론

- 대화 제외가 화면·알림·위젯·테스트 범위에 반영됨.
- 자동 수집→자녀 선별→자동 Todo→브리핑→체크→예약 취소까지 연결됨.
- 읽음/완료, 행사일/기한/알림 시각, UI 표시/수집 경로, 조회 성공/푸시 수신을 분리함.
- 필수 업무의 날짜 미정·기한 경과·정정·부분 완료·복원·데이터 이전을 정의함.
- 화면이 없는 기능은 수집/예약 등 백그라운드 작업이며 오늘/연결에 상태를 노출함.
- 모든 주 행동에는 저장 실패·권한 부족·데이터 없음·로딩 상태와 복구 경로가 있음.
- 남은 기술 불확실성은 출처별 실제 자동 조회 지원과 Android 실기기 전달 지연. D1/A01~A03/A19에서 검증하기 전 완성으로 판단하지 않음.
