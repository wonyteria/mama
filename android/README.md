# 나는 엄마다 · 로컬 에이전트 시험판

## 0.9 푸시 없는 학교 소식 자동 조회

성남정자초등학교 공개 공지·가정통신문·초1~2 방과후 게시판을 푸시 알림과 별개로 주기 조회합니다. 학교·학년 범위를 확인해 암호화 저장하고, 같은 자료를 홈 일정·모모 대화·브리핑에서 사용합니다. HWP/HWPX의 텍스트도 기기 안에서 제한적으로 읽으며 그림·지원하지 않는 첨부는 `부분 확인`으로 남깁니다.

실제 Galaxy S24+에서 생산 WorkManager의 공개 학교 웹 조회·저장과 HWP/HWPX 추출을 확인했습니다. e알리미 개인 공지는 모모 안의 공식 웹 로그인 후 인증 화면 구조 검증이 남아 있어 아직 자동 조회 완료로 표시하지 않습니다. 이미지 OCR과 생성형 AI는 포함하지 않았습니다.

## 0.8 알람·캘린더 개선 — PC 검증 완료

[0.8 설계](design/ALARM_AND_CALENDAR_0.8.md)에 따라 알람 화면과 명시적 일정·알람 명령을 구현했습니다. 기기 CalendarProvider에 직접 저장하는 경로와 외부 앱에 설정을 요청하는 경로를 구분합니다. 자동 테스트 131개, debug/release 빌드, lint 오류 0을 확인했습니다(lint 경고 78개). [최종 검증 기록](design/VERIFICATION_0.8.md)과 [사용안내](dist/사용안내-0.8.md)를 확인하세요. 특정 앱 호환성과 실제 휴대폰 설치·알림 도착은 별도 검증이 필요합니다.

처음 선택한 캘린더가 동기화 계정이면 입력한 일정이 해당 계정으로 동기화될 수 있습니다. 앱 내부 자료 삭제는 외부 캘린더에 저장된 일정을 삭제하지 않습니다. 이전 버전의 테스트 결과를 0.8 검증 결과로 사용하지 않습니다.

## 0.7 로컬 비서 개선 기록

0.7은 공지의 대상·필수성·날짜 근거, 묶음 브리핑, 직접 부탁 저장·취소를 개선하는 버전입니다. 생성 AI, 이미지/PDF OCR, 개인 웹 공지 자동 조회가 연결된 완성형 비서라는 의미는 아닙니다.

- 현재 제품 설계: [AGENT_PRODUCT_DESIGN_0.7.md](design/AGENT_PRODUCT_DESIGN_0.7.md)
- AI 계정·원문·개인정보·화면 계약: [AI_CONNECTOR_AND_UX_CONTRACT.md](design/AI_CONNECTOR_AND_UX_CONTRACT.md)
- 첨부 공지 사례: [ATTACHMENT_CASE_20260915.md](design/ATTACHMENT_CASE_20260915.md). 수동 원문 분석이며 앱 OCR 검증이 아닙니다.
- 신규 OCR 도입 계획: [LOCAL_OCR_IMPLEMENTATION_PLAN.md](design/LOCAL_OCR_IMPLEMENTATION_PLAN.md)
- 등하교·사진·영상 추가 설계: [ATTENDANCE_AND_MEDIA_PLAN.md](design/ATTENDANCE_AND_MEDIA_PLAN.md). 실제 등하교 서비스 확인 전 연결 완료를 의미하지 않습니다.
- 독립 검토: [REVIEW_0.7.md](design/REVIEW_0.7.md). 1차 검토의 수정 요청은 후속 검토 결과와 함께 확인해야 합니다.
- 최종 검증·배포 범위: [VERIFICATION_0.7.md](design/VERIFICATION_0.7.md). 자동 테스트 83개 통과, 최종 실기기 검증은 재연결 대기입니다.

아래 내용은 0.6까지의 구현·검증 기록입니다. 실행 전 확인, 기한 추론, 개별 알림 등 변경된 동작은 0.7 설계 및 최종 검증 기록을 우선합니다. 이전 기기의 검증 결과를 새 버전 실기기 검증으로 간주하지 않습니다.

## 0.6까지의 구현 기록

Warm Agentic Clay와 Bento 구조를 적용한 Android 설치형 **엄마 로컬 에이전트 시험판**입니다. 알림 수집, 설치 앱 분석·추천, 준비물·제출·마감 후보 감지, 기한 확인·재알림, 알림·부탁 기반 모모 대화, 나이스 공개 학교정보와 아침·저녁 묶음 브리핑을 포함합니다. 개인 웹 공지 자동 조회·인증 갱신·외부 AI·구매 비교·결제는 아직 구현하지 않습니다.

## 구현된 동작

- 연구 목적·기기 내 보관·삭제 설명과 명시 동의.
- 자녀 이름/별칭·학교 이름·학년 등록. 학교 검색 결과가 하나면 나이스 공식 이름으로 정규화.
- 앱과 사이트를 한 목록에서 관리. 나이스 학교정보 공식 OpenAPI 연결과 향후30일 학사일정 표시.
- 설치된 학교종이/e알리미/하이클래스/키즈노트/클래스노트를 찾아 필요한 앱을 선택. 패키지 이름은 확인했지만, 각 앱의 실제 알림 본문 제공 여부는 아직 실측하지 않았습니다.
- 앱 스위치를 처음 켤 때만 알림 접근 이유 팝업 표시, OS 설정 왕복 자동 확인, 원 앱 로그인 안내와 실행.
- 사이트 스위치에서 허용 HTTPS 도메인의 공식 로그인 화면을 열고 WebView 쿠키 세션 유지. 로그인 세션 준비와 실제 정보 읽기 성공을 분리 표시.
- 홈 화면의 모모 위젯을 눌러 앱 전체를 거치지 않고 부탁을 적고 완료 처리.
- 비서 브리핑 시간 3개, 평일만 옵션, 10분 미루기, 직접 누르는 한국어 음성 읽기.
- 연결 화면에서 설치된 후보 앱과 미설치 후보를 구분해 보여주고, 미설치 후보는 Play 설치 페이지로 안내합니다. 앱을 자동으로 켜거나 알림 권한을 대신 허용하지 않습니다.
- 선택한 앱의 새 알림에서 준비물·제출·신청·회신·마감·납부 후보를 기기 안의 규칙으로 찾습니다. 평소 소식은 아침·저녁에 묶고, 오늘 안에 놓치면 안 되는 기한만 잠금화면 내용을 숨겨 바로 알립니다.
- 후보 상세에서 `모모가 챙기기`를 누르면 원문 알림과 연결된 부탁으로 한 번만 저장하며, 홈에서 같은 일을 후보와 부탁으로 중복 계산하지 않습니다.
- `오늘·내일·모레·9월16일·9/16` 기한을 공지 게시 시각과 서울 시간 기준 날짜 후보로 바꾸고, 엄마가 날짜·시간과 전날 저녁·1시간 전·기한 시각 재알림을 확인합니다.
- 모모에게 최근 알림, 준비물·제출·마감, 미완료 부탁을 질문할 수 있습니다. `챙겨줘·기억해줘·추가해줘`는 실행 전 확인 후 부탁으로 저장합니다.
- 검토 내보내기에 후보 감지 여부·종류·해석한 기한을 자동 포함해, 연구자가 원문 공지와 대조할 수 있습니다. 엄마에게 판단 평가를 요구하지 않습니다.
- 홈은 한 개의 강한 Agent 카드, 일정·챙길 일 Bento 요약, 평면형 최근 공지로 우선순위를 구분합니다.
- 12시간마다 웹 세션 쿠키 존재를 확인하고 쿠키가 사라지면 해당 연결만 ‘다시 로그인 필요’로 표시합니다. 쿠키가 있다고 개인 공지 조회 성공으로 표시하지 않습니다.
- 사용자가 정확한 알람·전체화면 권한을 직접 허용했을 때만 선택형 비서 알람 사용.
- 허용한 앱의 **새 알림만** 수집. 전체 알림, SMS, 연락처, 위치, 마이크, 접근성 권한을 사용하지 않습니다.
- Room DB의 원문과 설정을 Android Keystore AES-GCM으로 암호화. 14일 TTL, 앱/동의/권한 필터, 정확한 callback revision 중복 억제.
- 홈·받은 알림·상세·설정, 수집 일시정지, 앱 선택 변경, 개별/전체 삭제.
- 연구자료의 로컬 자동 가림, 추가로 가릴 문구·행 제외·기간/앱 필터, 명시 동의 후 JSON/CSV 파일 저장.
- 크림·세이지·살구색 클레이 카드, 큰 버튼, 스크롤 가능한 한국어 화면. 폰의 글꼴 확대 지원.

앱은 나이스 공식 OpenAPI와 사용자가 켠 사이트의 공식 로그인 화면을 위해 `INTERNET` 권한을 사용합니다. 입력한 학교명은 공식 학교 검색 요청에만 사용합니다. 계정 비밀번호를 앱 데이터로 저장하지 않고 사이트 쿠키 세션만 WebView 저장소에 유지합니다. 알림 원문은 서버·AI·분석 SDK로 자동 전송하지 않습니다. 파일 저장은 사용자가 선택한 문서 제공자가 처리하며, 외부 사본은 앱 전체 삭제로 회수할 수 없습니다.

## 빌드

Windows PowerShell에서:

```powershell
cd D:\Codex\mom-agent\android
.\scripts\bootstrap.ps1
.\scripts\build.ps1
```

도구는 `D:\Codex\.toolchains\mom-android`에 설치하며 프로세스에 필요한 환경변수만 설정합니다. Java17, Gradle8.13, AGP8.11.1, compile/target36, min33입니다. Compose·Room·WorkManager 등 앱 빌드에 필요한 공식 라이브러리를 사용하며, 첫 실행에는 다운로드가 필요합니다.

기본 검증은 APK 빌드·로컬 단위/UI 렌더링 테스트·Android Lint입니다. 빌드 결과는 `app/build/outputs/apk/debug/app-debug.apk`에 생깁니다. debug 키로 서명한 개발용 파일이며 Play 정식 배포/서명 설정과 별개입니다.

## 화면과 테스트

- `design/reference.png`: 클레이모피즘 디자인 참고. 실제 앱 스크린샷으로 표시하지 않습니다.
- `app/build/reports/screenshots/`: 실제 Compose 화면을 Robolectric Android34 native graphics로 렌더링하는 테스트 출력. 휴대폰이나 에뮬레이터의 실측 화면은 아닙니다.
- `app/build/reports/tests/testDebugUnitTest/index.html`: 최신 테스트 결과.
- `app/build/reports/lint-results-debug.html`: 정적 분석 결과.
- `VERIFICATION.md`: 수행한 검증과 미검증 범위를 기록합니다.

테스트용 `fixture`는 별도 앱이며 소비자 APK에 포함되지 않습니다. 합성 알림을 보내 실제 NotificationListener를 점검하기 위한 도구입니다. debug 빌드에서 이 도우미가 설치됐을 때만 테스트 대상 목록에 나타납니다. 정식 학교 앱을 가장하거나 실제 공지인 것처럼 표시하지 않습니다.

## 휴대폰에서 처음 사용하기

1. Android 13~16 개인 프로필 휴대폰에 `dist\나는엄마다-0.6.0.apk`를 전달하여 설치합니다. 기존 0.5 설치본은 삭제하지 말고 업데이트 설치합니다.
2. 연구 설명에 동의하고 아이 이름/별칭·학교·학년을 입력합니다.
3. 연결 화면에서 앱 스위치를 켭니다. 처음 한 번 이유 팝업을 본 뒤 OS의 알림 읽기 접근을 허용하고, 돌아오면 원 앱 로그인을 확인합니다.
4. 사이트 스위치를 켰다면 앱 안의 공식 화면에서 직접 로그인합니다. 현재 웹 연결은 시험 방문 저장이며, 개인 공지 자동 조회와 세션 자동 갱신은 지원 전입니다.
5. **그 이후** 선택한 학교/학원 앱에서 도착한 새 알림만 목록에 들어옵니다.
6. 원래 앱에 새 알림이 왔는데 목록에 없다면 읽기 권한·선택 앱·알림 모으기 상태를 확인합니다. 알림 본문이 부족하면 서비스별 허용된 원문 커넥터가 필요합니다.

APK 직접 설치 경로에 따라 Android의 ‘제한된 설정’ 안내가 나올 수 있습니다. 표준 설정에서 사용자가 허용해야 하며 앱이 우회/자동 허용하지 않습니다. 이후 일반 참가자 배포는 Google Play 내부 테스트를 준비하는 편이 설치 부담을 줄일 수 있지만, 현재 Play 등록이나 배포는 하지 않았습니다.

## 삭제와 복구

설정의 ‘참여 종료 · 전체 데이터 삭제’는 기록·아이 이름·앱 선택·동의·암호화 키를 지웁니다. 네트워크 승인을 기다리지 않습니다. 키를 지운 데이터는 복구할 수 없고 앱 백업/기기 이전도 제외합니다. 앱의 일반 데이터 화면은 release 빌드에서 화면 캡처/최근 앱 미리보기를 보호합니다. debug 빌드는 UI 검증을 위해 캡처를 허용하므로 연구자료 화면을 임의 공유하지 마세요.

## 남아 있는 검증

G0는 실제 엄마 5~10명, 7~14일, 중요 공지와 대조한 알림 300건 이상을 모아야 끝납니다. 0.6의 검토 내보내기에 후보 종류와 해석한 기한이 자동 포함되어 제품팀이 원문과 대조할 수 있습니다. 정상 빌드나 합성 알림 테스트만으로 학교 앱 연동/사업 가능성을 입증하지 않습니다.

나이스 공개 API 연동은 제거했습니다. 인증키를 APK에 넣을 수 없고 안전한 서버 프록시가 없어서, 학사일정은 확인된 학교 홈페이지 게시판 lane에서만 가져옵니다. 나이스 연동을 되살리려면 서버 측 프록시와 사용 제한을 먼저 만들어야 합니다.

release 빌드는 서명 자격 증명이 없으면 실패합니다. `MAMA_RELEASE_STORE_FILE`, `MAMA_RELEASE_STORE_PASSWORD`, `MAMA_RELEASE_KEY_ALIAS`, `MAMA_RELEASE_KEY_PASSWORD`를 Gradle property 또는 환경변수로 설정해야 `assembleRelease`가 진행되며, debug 서명으로의 대체는 없습니다.

참고: [NotificationListenerService](https://developer.android.com/reference/android/service/notification/NotificationListenerService), [Android 알림 권한](https://developer.android.com/develop/ui/compose/notifications/notification-permission), [Room](https://developer.android.com/jetpack/androidx/releases/room), [Robolectric](https://robolectric.org/getting-started/).
