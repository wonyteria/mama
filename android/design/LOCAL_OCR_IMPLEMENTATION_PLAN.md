# 로컬 첨부 OCR 구현 계획

상태: 설계만 작성. 신규 라이브러리 승인을 기다리는 단계이며 SDK 추가·코드 변경·빌드는 수행하지 않는다.
기준: `AGENT_PRODUCT_DESIGN_0.7.md`, 원본 재검수로 정정한 `ATTACHMENT_CASE_20260915.md`, 현재 `data/NoticeDecision.kt`.
문서의 선발 방식은 **선착순 마감**이다. 초안의 추첨 해석을 재사용하지 않는다.

## 1. 도입 범위와 실제로 가능한 것

승인 대상은 bundled `com.google.mlkit:text-recognition-korean:16.0.1` 한 개다.
한국어 모델을 앱에 포함해 공유받은 이미지의 문자를 기기에서 추출한다. API 키·생성 AI 계정·건당 추론료를 전제로 하지 않는다.
동적 모델 다운로드 방식과 섞지 않는다. 설치 후 첫 실행부터 비행기 모드에서 실제 OCR이 되는지를 확인한다.
공식 문서는 bundled 모델, 한국어 dependency, `KoreanTextRecognizerOptions`, 문자 블록·위치 반환을 설명한다. [ML Kit Android OCR](https://developers.google.com/ml-kit/vision/text-recognition/v2/android).
이 모델은 문자인식 엔진이다. 표 머리글 관계, 선착순/추첨 의미, 가족에게 필요한 행동을 검증하는 생성 AI가 아니다.
OCR 성공·전체 페이지 처리·내용 검증은 별개의 상태로 둔다. 자동으로 `VERIFIED`가 되지 않는다.
모모는 원문·OCR 문자열을 자체 서버나 생성 AI로 전송하지 않는다. SDK 진단 수집 조건은 별도 검토하므로 앱 전체 통신이 0이라고 주장하지 않는다. [ML Kit 개인정보 조건](https://developers.google.com/ml-kit/terms).

## 2. 사용 흐름

학교 앱의 공유 → “모모로 읽기” 또는 모모의 “첨부 읽기”에서 파일 선택 → 한 번의 로컬 읽기 → 근거를 볼 수 있는 소식 카드.
이미지/PDF 1개를 우선 지원한다. 여러 파일 공유는 첫 파일을 몰래 선택하지 않고 미지원 상태와 단일 파일 재선택을 안내한다.
가져오기 화면은 파일명·형식·크기와 “기기에서 읽어요”를 표시하고 페이지 처리 진행률과 취소를 제공한다.
완료 후 요약/대상/확인되지 않은 정보를 보인다. 별점·정확도 평가·모든 문장 확인 절차를 넣지 않는다.
불명확한 중요 정보는 보류한다. 실제 신청 등 사용자의 결정이 필요한 순간에만 관련 구절을 함께 보여준다.
이미 알림과 연결된 첨부는 같은 소식의 자료로 저장한다. 연결 근거가 없으면 독립 공유 문서로 둔다.
동일 바이트 hash는 중복 가져오기를 억제하되 문서 내용 변경은 새 개정으로 보관한다.

## 3. 입력·URI·파일 경계

`ACTION_SEND`의 `EXTRA_STREAM`/`ClipData`와 파일 선택의 `ACTION_OPEN_DOCUMENT`에서 받은 `content://`만 처리한다.
이미지 MIME은 PNG/JPEG/WebP, PDF는 `application/pdf`로 제한한다. MIME·확장자·실제 디코딩 결과를 함께 확인한다.
외부 HTTP URL, `file://`, HTML, ZIP, 암호화 PDF, 애니메이션/다중 프레임 이미지는 최초 버전에서 거절한다.
공유 URI는 받은 읽기 권한이 살아 있는 동안 한 번 열어 앱 소유 복사본으로 가져온다. 임의 경로 변환이나 전체 사진 권한을 요청하지 않는다.
문서 선택 URI도 최초 버전은 즉시 복사한다. 계속 읽을 필요가 없으므로 영구 URI 권한은 기본 보관하지 않는다.
후속 지연 가져오기를 지원할 경우에만 제공자가 부여한 persistable read flag를 확인해 보관하고 삭제 시 반환한다. [Android 파일 접근](https://developer.android.com/training/data-storage/shared/documents-files).
파일명은 표시용이다. 경로로 사용하지 않고 내부 UUID를 사용하며 제어문자와 지나치게 긴 표시명을 정리한다.
크기 메타데이터가 없거나 틀릴 수 있으므로 스트림 복사 중 실제 바이트 수로 상한을 강제한다.
권한 소멸·클라우드 제공자 오프라인·읽기 실패는 “파일을 가져오지 못함”이다. OCR 실패나 빈 문서로 위장하지 않는다.
파일명 날짜, 공유 시각, 발행일을 구분한다. 공유한 앱을 원문 작성 기관으로 단정하지 않는다.

## 4. 최초 제품 상한과 자원 관리

아래 숫자는 앱의 초기 제한이며 SDK 보장치가 아니다. 실기기 결과를 근거로 조정한다.

| 자원 | 최초 제한/처리 |
|---|---|
| 파일 | 이미지 15 MiB, PDF 25 MiB; 상한 초과 시 전체 거절, 조용한 자르기 금지 |
| 이미지 | 헤더 기준 40 MP·한 변 20,000 px 초과 거절; 전체 해상도 decode 전 검사 |
| PDF | 10페이지까지; 페이지 수 확인 후 초과면 읽기 시작 전 거절 |
| OCR bitmap | 한 페이지 최대 4 MP, ARGB_8888 약 16 MiB; 긴 변 최대 3,000 px |
| 동시성 | 가져오기 1건, PDF 페이지 1장, ML Kit 요청 1개씩 직렬 처리 |
| 메모리 | 앱 소유 bitmap 합계 32 MiB 이하 목표; 원본·회전본·전체 PDF 페이지 동시 적재 금지 |
| 추출 결과 | 페이지당 100,000자·전체 500,000자 초과는 제한 도달 상태; 자동 판단 금지 |
| 보관 용량 | 원문·결과 합계 100 MiB 초기 상한; 부족하면 새 가져오기 중단, 기존 자료 임의 삭제 금지 |
| 시간 | 페이지 OCR 30초, 전체 처리 120초를 넘으면 중단 요청·실패 상태; 성공 주장 금지 |

크기 계산은 Long으로 하고 가로×세로×bytes의 overflow를 차단한다. 이미지 크기는 bounds 조회 후 sample decode한다.
메모리 부족이면 한 번 더 큰 할당을 재시도하지 않는다. 자원을 해제하고 해상도/형식 제한에 걸렸음을 표시한다.
낮춘 해상도에서 작은 글자가 읽히지 않으면 결과에 품질 문제를 남긴다. 작은 글자를 추측해 보완하지 않는다.
숫자는 해상도·heap 운영 목표이며 ML Kit의 내부 native 메모리까지 제한한다는 뜻이 아니다. peak PSS/heap을 실측한다.

## 5. 이미지 회전과 PDF 페이지 처리

이미지는 OS decoder가 반영한 EXIF 방향을 확인하고 방향 보정은 한 번만 적용한다. 기존 decoder를 우선 사용해 새 EXIF 의존성을 늘리지 않는다.
90/180/270도와 mirrored EXIF를 각각 회귀 검증한다. 화면 회전은 사진 방향 판단에 사용하지 않는다.
좌표는 방향 보정된 페이지 좌표계를 기본으로 보관한다. 원본과의 변환 행렬·최종 크기를 함께 저장해 강조 표시 위치를 재현한다.
PDF는 플랫폼 `PdfRenderer`로 페이지를 직렬 렌더링하고 흰 바탕에 OCR한다. 페이지·renderer·descriptor는 항상 닫는다.
PDF 입력은 seek 가능한 앱 소유 descriptor를 사용한다. provider의 비탐색 stream을 직접 renderer에 넘기지 않는다.
외부 PDF 파싱은 권한 없는 별도 isolated process에서 수행하고 필요한 descriptor만 전달하는 구성을 구현 검토 기준으로 둔다. [PdfRenderer](https://developer.android.com/reference/android/graphics/pdf/PdfRenderer).
minSdk 33 전체에서 텍스트 레이어 추출 API를 사용할 수 있다고 가정하지 않는다. 최초 버전은 렌더→OCR를 명시하고 native 텍스트 추출 최적화는 후속으로 분리한다.
페이지 크기·렌더 배율을 저장한다. 확대·축소나 회전 이후에도 페이지 2의 근거가 페이지 1에 표시되면 실패다.
문서에서 읽힌 링크·QR·JavaScript는 실행하지 않는다. OCR은 링크 열기나 로그인 권한을 부여하지 않는다.

## 6. 자료형과 NoticeDecision 연결

새 자료형은 UI와 SDK를 직접 결합하지 않는 작은 입력 계약으로 시작한다.

| 자료 | 필수 정보 |
|---|---|
| AttachmentSource | attachmentId, sha256, importTime, MIME, byteCount, pageCount, 원본 표시명, 실제 연결된 notificationId nullable |
| ExtractionRun | runId/generation, sourceHash, engine/version, 상태, 처리·실패 페이지, 품질 이슈 |
| OcrPage | pageIndex, uprightWidth/Height, 변환 정보, block/line/element ID·text·bounding polygon |
| EvidenceLocation | sourceHash, pageIndex, OCR span IDs, quote, normalized polygon; 표 행/열은 확인된 경우만 |
| NoticeInput | 원문 종류, 구조화 페이지, 명시적 추출 상태·방식, 자녀 프로필, 알려진 날짜 기준 |

페이지 경계와 블록 위치를 유지한 채 `NoticeInput`을 공통 판단 엔진에 전달한다. 현재 알림용 `decide(record, child)`는 adapter로 유지한다.
첨부를 가짜 `ProbeRecord`로 만들거나 `.text`에 신뢰 플래그를 섞지 않는다. `NoticeSource`는 독립 첨부 출처를 표현하도록 확장한다.
`NoticeEvidence`의 claim/quote에 위치 참조를 추가해 카드의 `원문`을 누르면 해당 페이지·구절이 보이게 한다.
현재의 `manual_reference_transcription` 문자열로 `VERIFIED`를 만드는 경로는 선행 제거 대상이다. test 전사 방식은 테스트 metadata로만 남긴다.
처리 완료 여부와 의미 검증 여부를 나눈다. 예: `OCR_TEXT_EXTRACTED`는 “문자 추출 완료”, `PARTIAL_EXTRACTION`은 읽은 페이지 수를 표시한다.
`VERIFIED`는 OCR callback 성공·정규식 일치·두 번 OCR 일치만으로 설정하지 않는다. 근거 없는 검증 배지를 없앤다.
머리글과 행 연결이 불명확한 표는 연결을 추정하지 않고 layout issue를 기록한다. 날짜 인접 텍스트만으로 의미 역할을 강제하지 않는다.
최초 OCR 버전의 파생 행동은 브리핑 후보까지 허용하고, 검증되지 않은 첨부에서 자동 부탁·즉시 알림·신청을 생성하지 않는다.
완료된 필수 행동으로 연결하려면 기존 공통 판단의 대상·필수성·날짜 역할·불확실성 gate를 모두 통과해야 한다.
첨부 누락을 해소해도 다른 미확보 첨부가 있으면 문서 전체 확인 완료로 바꾸지 않는다.

## 7. 취소·수명주기·삭제

화면 회전은 같은 작업을 유지하고 OCR를 중복 시작하지 않는다. 앱이 백그라운드로 가면 새 페이지를 시작하지 않고 재개 가능한 중단 상태로 둔다.
취소는 즉시 UI에 반영한다. ML Kit의 이미 실행 중인 task가 실제 중단되지 않을 수 있으므로 결과 callback을 run generation으로 무효화한다.
task 처리 중인 bitmap을 먼저 recycle하지 않는다. 종료 callback 이후 해제하고 다음 페이지·재시도를 시작하지 않는다.
늦게 도착한 결과가 취소·삭제된 원문이나 철회된 동의를 다시 저장하지 못하게 commit 직전에 generation/동의/원문 존재를 다시 확인한다.
process death 시 완료된 원문 복사와 처리 결과의 원자적 저장 여부를 확인한다. 미완료 import는 삭제하고 임의로 완료 상태를 복원하지 않는다.
새 원문·OCR 결과·근거 좌표는 기존 기기 키 정책에 맞게 암호화한다. 전체 파일을 Base64로 거대 JSON에 넣지 않는다.
seek가 필요한 임시 평문 PDF는 앱 내부 전용 임시 경로에서만 짧게 사용하고 종료·취소·실패·다음 시작의 복구 청소 대상에 넣는다.
원문·썸네일·좌표·OCR 텍스트·중간 캐시 모두 14일 보관 정책과 사용자의 삭제 요청에 포함한다. 영구 삭제 보장 같은 표현은 쓰지 않는다.
삭제 후 연결된 파생 자동 예약은 취소하고 근거 열람 링크를 제거한다. 사용자가 직접 저장한 부탁은 보존하되 “원문 삭제됨”을 표시한다.
SDK recognizer, file descriptor, renderer, page, stream을 `finally` 경로에서도 닫는다. 원문·인식 문자열·URI·파일명은 로그에 남기지 않는다.

자동 검증은 자료형·좌표 변환·바이트 제한·중복·상태 전이·취소 경쟁·자동 행동 억제를 다룬다. OCR 정확도는 실 SDK·실 이미지로 따로 검증한다.
원본 이미지를 재검수한 정답과 OCR 결과를 비교한다. 수동 전사 역시 오독될 수 있으므로 설계 문장만을 정답으로 삼지 않는다.
동일 첨부 1건 통과를 모든 학교 공지의 표 이해 정확도로 일반화하지 않는다.
릴리스 보고는 파일 읽기/OCR/의미 판단/자동 행동을 분리하고, 측정한 기기·SDK 버전·통과한 자료·보류 사례를 명시한다.

## 9. 승인 후 구현 순서

1. 신규 dependency 승인 확인, magic text 신뢰 승격 제거, typed provenance와 상태 전이 회귀부터 구현.
2. 이미지 한 장의 URI 획득·제한·로컬 OCR·근거 보기·취소/삭제를 끝까지 검증.
3. 플랫폼 PDF 렌더 경로·격리·페이지별 결과·수명주기를 추가하고 실제 PDF로 검증.

5. 빌드·단위·lint·실기기 회귀 뒤 독립 검토. 검증 전에는 “첨부 자동 이해 완료”로 표시하지 않음.
