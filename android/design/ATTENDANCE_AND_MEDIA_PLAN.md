# 등하교 확인과 사진·영상 처리 계획

상태: 추가 설계. 이 문서만 작성하며 코드·Gradle·연결 설정을 변경하지 않는다.
구현 순서: GPT-5.5의 0.7 검토 수정 완료 → 실제 이용 중인 등하교 앱/서비스 확인 → 검증된 연결 범위에서 구현.
기준: `AGENT_PRODUCT_DESIGN_0.7.md`, `LOCAL_OCR_IMPLEMENTATION_PLAN.md`, 현재 `SourceCatalog`·`ProbeNotificationListener`.

## 1. 권장 기본값

등하교는 원문 서비스가 알려준 사실을 자녀별로 모아 보여준다. 미수신을 미등교·미하교로 해석하지 않는다.
공지의 핵심 이미지·첨부는 내용을 이해하는 로컬 읽기 경로로 보낸다. 활동 사진·영상은 새 소식을 묶어 안내하고 원문 앱/웹에서 본다.
전체 사진 다운로드는 기본 꺼짐이다. 원문 보는 데 불필요한 재로그인·파일 관리·사진 분류를 엄마에게 요구하지 않는다.
기본 아침·저녁 브리핑과 긴급한 일만 즉시 알리는 기존 원칙을 유지한다. 평범한 등교 확인과 새 사진은 긴급 사건이 아니다.
엄마가 등하교 확인 즉시 알림을 별도로 요청한 경우에만 해당 종류를 바로 중계한다. 원문 앱 알림과 중복될 수 있음을 설정에서 짧게 표시한다.
영상 분석·얼굴 인식·다른 아이 식별·자녀 위치 추적은 이 범위에 포함하지 않는다.

## 2. 현재 가능한 연결과 먼저 확인할 것

현재는 선택된 지원 앱에서 새로 도착한 알림을 수집한다. 과거 알림·앱 내부 기록·사진 원본을 자동 조회하지 않는다.
`SourceCatalog`는 등록된 앱 목록만 보여준다. 모든 설치 앱이나 모든 등하교 서비스를 이미 지원한다고 말하지 않는다.
실제 서비스 이름이 확인되기 전 packageName·API·로그인 주소·웹 수집 방식을 추측해 추가하지 않는다.
서비스 확인 뒤 공식 앱 식별자, 기기 설치 상태, 사용자의 선택, 실제 새 알림 payload를 순서대로 확인한다.
“등하교 앱 연결”의 MVP 의미는 해당 앱의 새 알림 수신이다. 기관의 출석 원장을 조회한다는 뜻이 아니다.
웹은 허용된 공식 인증 방식과 실제 읽기 성공이 있어야 조회 연결로 표시한다. 로그인 화면·쿠키만으로 연결 완료가 되지 않는다.
앱별 연결 카드는 읽을 수 있는 범위, 마지막 성공 시각, 현재 알림 권한/세션 상태를 표시한다.

## 3. 등하교 사건의 의미 계약

| 항목 | 보관·표시 원칙 |
|---|---|
| 원문 사건 | 원문 ID·개정, 기관/서비스, 알림 구절, 실제 명시된 사건 종류 |
| 장소·활동 | 학교 교문 도착 / 교실 출석 / 학교 출발 / 학원 입실·퇴실 / 버스 승차·하차를 구분 |
| 자녀 | 공식 연결 자녀 ID 또는 검증된 계정 매핑 우선; 이름만 애매하면 미확인 |
| 사건 시각 | 원문에 명시된 eventTime, 시간대, 날짜 근거, 시각 정밀도 |
| 수신 시각 | receivedAt을 별도 보관; eventTime 누락을 수신 시각으로 몰래 채우지 않음 |
| 개정 상태 | 새 사건 / 지연 수신 / 정정 / 취소 / 중복 후보를 구분 |
| 범위 상태 | 새 알림 수집 가능 / 연결 끊김 / 해당 기간 자료 없음 / 원문 조회 가능을 별도 관리 |

“08:21 교문 도착 알림”은 “08:21 수업 출석 확인”이나 “학교에 안전하게 있음”의 증거가 아니다.
“16:10 학원 퇴실”은 집 도착이 아니다. 버스 하차도 학교 도착으로 바꾸지 않는다.
예정·질문·부정 표현은 사실 사건으로 만들지 않는다. “내일 등교 예정”, “등교했나요?”, “등교 확인 안 됨”을 구분한다.
“등교 확인 안 됨”처럼 서비스가 명시한 상태는 그 출처의 문구로 표시하되 실제 결석 판정으로 확장하지 않는다.
자녀 매칭은 같은 이름·여러 자녀·여러 기관을 고려한다. 부모 프로필 자녀가 한 명이라는 이유만으로 수집된 모든 알림을 그 자녀에게 배정하지 않는다.
모호하면 개인 카드에 합치지 않고 “누구의 알림인지 확인되지 않음”으로 보관한다. 관련 자료를 묶어 필요한 경우 한 번만 매핑한다.
아이가 학교·학원 모두 다녀도 같은 “입실”로 합치지 않는다. 기관별 타임라인과 한 줄 요약을 함께 유지한다.

## 4. 날짜·지연·중복·정정 규칙

원문에 날짜가 있으면 그 날짜를 사용한다. 시간만 있으면 출처의 검증된 날짜 규칙이 없는 한 날짜 미확인이다.
한국 기관의 명시된 로컬 시각은 Asia/Seoul로 처리하되 출처의 다른 시간대가 있으면 보존한다. 휴대폰 시간대 변경으로 사건 날짜를 바꾸지 않는다.
23:59 사건이 다음 날 수신되어도 수신일의 등교로 만들지 않는다. 역순 수신은 eventTime 기준으로 정렬하고 수신 시각도 볼 수 있게 한다.
시각 누락은 “시각 미표기 · 08:25 수신”처럼 표시한다. “08:25 등교”라고 단정하지 않는다.
동일 출처 사건 ID·개정은 한 번 표시한다. 안정적 사건 ID가 없으면 원문 hash·자녀·종류·시각의 보수적 중복 판정만 한다.
같은 날 두 번 버스를 탄 사건이나 재입실은 삭제하지 않는다. 짧은 시간 간격만으로 합치지 않는다.
명시된 정정 대상 ID 또는 근거가 있을 때 이전 사건을 수정/취소하고 변경 이력을 유지한다. 상충하는 별개 원문은 둘 다 보존한다.
지연 기준은 출처별 설정 근거가 생긴 후 정한다. 임의로 5분을 안전 경보 기준으로 쓰지 않는다.
기기 재부팅·재연결 후 과거 사실을 새 긴급 사건처럼 울리지 않는다. 이미 전달한 개정의 알림을 반복하지 않는다.

## 5. 등하교 화면과 부모 행동

```text
오늘 · 지우
학교   08:21 교문 도착 알림       [원문 앱]
       학교 서비스 · 08:23 수신
학원   오늘 받은 입·퇴실 알림 없음
       새 알림 수집 중 · 실제 출결 상태는 미확인

오늘 챙길 일  1개                 [내용 보기]
새 사진 소식  학교 1개            [원문에서 보기]
────────────────────────────────────
연결 상태  학교 수신 가능 / 학원 재연결 필요
```

대시보드는 관측한 사건과 연결 상태를 분리한다. 연결 끊김을 결석·위험의 빨간 경고로 표시하지 않는다.
아침/저녁 브리핑은 “학교 교문 도착 알림을 받았어요”처럼 출처 수준에 맞춰 짧게 요약한다.
사용자가 “오늘 등교했어?”라고 물으면 “08:21 교문 도착 알림이 있어요” 또는 “오늘 받은 확인 알림은 없어요”라고 답한다.
원문이 명시한 긴급 변경/문제는 기존 긴급 판단을 거친다. 빈 타임라인·일정 경과만으로 보호자에게 경보하거나 기관에 연락하지 않는다.
연결이 끊겨 확인할 수 없으면 복구 조치를 브리핑에 한 번 묶는다. 매번 “확인해 주세요”를 푸시하지 않는다.
출석률 계산, 결석 신고, 교사 메시지, 일정 자동 변경은 추가 요청과 검증된 실행 경로가 있어야 한다.

## 6. 이미지와 활동 미디어의 분리

| 자료 | 기본 동작 | 모모가 저장하는 범위 |
|---|---|---|
| 준비물·신청 공지 이미지/PDF | 획득 권한이 있는 경우 로컬 읽기 계획 적용 | 필요한 원문·OCR·근거를 기존 14일 정책으로 보관 |
| 활동 사진 게시물 | 새 게시물 소식을 브리핑에 묶고 원문 열기 | 출처·게시물 식별자·제목·시각·읽음 상태 |
| 동영상 | 원문 앱/웹에서 재생 | 새 영상 소식 metadata만, 다운로드·프레임 추출·음성 분석 없음 |
| 공지와 활동 사진이 섞인 게시물 | 문서 이미지 역할이 명확한 자료만 읽고 나머지는 원문 열기 | 추측한 사진 분류로 일괄 다운로드하지 않음 |
| 종류·첨부 권한 미확인 | “새 자료가 있어요”로 원문 안내 | 실제 확인한 metadata만 |

활동 사진은 할 일이 아니다. 새 사진 소식은 같은 기관·게시물 개정 단위로 묶고 필수 준비 목록·즉시 알림에서 제외한다.
서버가 제공한 사진 개수만 표시한다. “사진이 올라왔어요”라는 알림만 받았으면 개수·사진 속 행동·자녀 등장 여부를 만들지 않는다.
내용이 필요한 공지 이미지는 `LOCAL_OCR_IMPLEMENTATION_PLAN.md`를 따른다. OCR 승인이 사진 전체 수집이나 영상 AI 분석의 승인이 되지 않는다.
여러 아이가 찍힌 사진에서 우리 아이만 자동 골라내거나 얼굴을 인식하지 않는다. 다른 아이의 정보를 요약·프로필화하지 않는다.

## 7. 원문 열기·인증·미리보기·캐시

검증된 게시물 URL/deep link가 있으면 명시적인 탭으로 연다. 없으면 확인된 설치 앱을 열고 “앱에서 소식을 찾아주세요”라고 한계를 표시한다.
현재 저장 모델에 없는 게시물 링크를 알림 제목으로 합성하지 않는다. 정확한 게시물 열기를 보장하려면 실제 payload/connector 검증이 필요하다.
원문 앱 실행·원문 페이지 열기와 읽음 완료는 별개다. 외부 화면을 열었다는 이유로 사진을 봤다고 단정하지 않는다.
앱에 없는 웹 로그인은 공식 서비스에서 진행한다. 세션 만료 시 로그인을 한 번 안내하고 원문을 읽었다고 표시하지 않는다.
서명 URL·access token은 자격 증명처럼 다룬다. 로그·분석 이벤트·공유 화면·일반 export에 남기지 않는다.
서명 URL 만료 후 쿠키를 우회하거나 URL을 조작하지 않는다. 검증된 connector가 다시 발급할 수 있을 때만 갱신한다.
개별 사진 읽기 scope와 전체 앨범 다운로드 scope를 구분한다. 로그인 가능하다는 이유로 전체 자료 수집 권한이 있다고 간주하지 않는다.
썸네일은 MVP에서 기본 꺼짐이다. 후속 활성화 시 공식 connector가 제공하는 허용된 축소 이미지만 받고 원본 다운로드로 대체하지 않는다.
후속 썸네일 제안 한도: 게시물당 1장·256 KiB·긴 변 512px, 전체 10 MiB, 보관 24시간 이내 또는 출처 만료 시각 중 빠른 쪽.
이 숫자는 제품 제한 제안이다. 만료를 모르는 서명 자료는 지속 캐시하지 않고 원문 열기만 제공한다.
썸네일 캐시는 앱 내부·백업 제외·암호화 대상으로 관리하며 앨범에 자동 저장하지 않는다. 용량 부족이면 미리보기를 생략한다.
연결 해제·동의 철회·원문 삭제·접근 권한 상실 시 캐시·서명 URL·관련 thumbnail 작업을 제거한다. 늦은 callback으로 자료를 복원하지 않는다.
사용자가 직접 사진 앱으로 저장한 외부 파일은 모모에서 회수할 수 없다는 기존 경계를 유지한다.
공지·파일·영상 설명의 지시는 신뢰하지 않는다. 링크 열기·다른 사진 수집·자격 증명 전송 명령으로 실행하지 않는다.

## 8. 기능 계약과 우선순위

| 단계 | 구현 계약 | 범위 밖 |
|---|---|---|
| P0 선행 | 실제 등하교 서비스/패키지 확인, 새 payload 검수, 대상 자녀 매핑과 사건·수신 시각 분리 | 임의 API·package 생성, 미수신 안전 추론 |
| MVP P0 | 알려진 source의 명시적 등하교 사건 파싱·출처 타임라인·중복/정정·연결 상태·대화 답변 | 출석 원장 완전 조회, 위치 추적, 기관 메시지 |
| MVP P0 | 새 사진/영상 metadata 소식을 정기 브리핑에 묶고 원문 앱 열기 | 사진 전체 다운로드·영상 분석·허위 정확한 게시물 링크 |
| P1 | 검증된 공식 connector의 게시물 URL·권한 갱신·선택적 제한 썸네일 | 인증 우회, 공유 앨범 전체 접근 가정 |
| 별도 후속 | 사용자가 요청한 특정 사진 저장·허용된 앨범 가져오기 범위 설계 | 기존 요청만으로 전체 미디어 수집 시작 |

자료 계약은 `AttendanceEvent`(source/revision/child/institution/type/eventTime/receivedAt/evidence), `AttendanceCoverage`(연결 상태·확인 가능 범위), `MediaNotice`(source/postRevision/kind/knownCount/originTarget/availability)로 나눈다.
등하교 사건은 완료해야 할 `AssistantTask`로 만들지 않는다. 브리핑은 사건·할 일·새 미디어를 각각 한 줄로 표현한다.
알림 수집을 위한 provider·출처 타입은 현재 공통 근거 모델을 재사용한다. 미디어 바이트는 `MediaNotice`에 넣지 않는다.
삭제·동의·generation 검사는 기존 수집/OCR 경계와 공유한다. 또 다른 독립 알림 스케줄러를 만들지 않는다.

## 9. 회귀·실기기 수락 기준

| 상황 | 기대 결과 |

등하교 parser 테스트는 실제 payload를 비식별화한 fixture와 provenance를 사용한다. 합성 알림 성공만으로 실제 서비스 지원을 선언하지 않는다.
실기기에서 새 사건 수신·지연·권한 철회·원문 열기를 확인한 서비스만 지원 목록에 포함한다.
완료 보고에는 지원한 실제 서비스와 읽는 범위, 사건 해석 검증, 사진/영상의 원문 열기 방식, 남은 미지원 기능을 명시한다.
