# 0.8.1 실기기 검증

상태: 진행 중. 2026-09-15, Galaxy S24+ (SM-S926N), Android 16, 1080×2340, density 450.

## 검증 경계

사용자용 `kr.mom.probe`는 기존 0.5에서 0.8 APK로 자료를 유지하는 업데이트 설치에 성공했다. 사용자용 화면의 FLAG_SECURE 때문에 캡처는 차단된다. 디자인 사진과 합성 자료 테스트는 같은 소스의 별도 `kr.mom.probe.qa`에서 수행한다. 두 결과를 혼동하지 않는다. 기존 개인 일정·메시지·사진은 검증 자료로 사용하지 않는다.

## 직접 관찰

- 사용자용 업데이트 설치와 시작 성공. 첫 설정 화면의 UI 구조 확인.
- QA 홈·모모 대화·키보드·설정·브리핑 설정·부탁 목록의 실제 화면 확인.
- 시스템 다크 모드에서 Main/Agent의 상태바 아이콘이 흰색으로 표시되어 밝은 앱 배경과 대비가 낮았다. 0.8.1 공통 테마 수정 대상으로 지정.
- 글자 크기를 임시 200%로 높여 확인한 후 원래 1.0으로 복구했다. 부탁 목록은 줄바꿈되며 완료·삭제가 보였다. 홈은 스크롤이 필요하다.
- QA의 정확 알람 권한 화면을 앱에서 열고 허용 후 복귀했다. 명시적으로 '전화처럼 알려주기'를 켰다.
- 합성 부탁의 3초 뒤 예약을 만들고 휴대폰 화면을 끈 뒤, 실제 TaskAlarmActivity가 전체 화면으로 나타났다. 잠금 상태에는 `QA_PRIVATE_REMINDER`가 드러나지 않고 일반 문구와 정지·다시 알림·잠금 해제 제어가 보였다. 소리의 실제 청취·음량 측정은 하지 않았다.
- 시계 앱 요청 처리기는 삼성 시계가 조회됐다. 캘린더 입력 화면 처리기는 구글·삼성·네이버·Outlook이 조회됐다. 처리기 조회만으로 저장 호환성을 승인하지 않는다.

## 사용자 추가 요구 반영

전체 화면의 '모모에게 부탁'은 잠금을 해제한 뒤 AgentActivity로 연결한다. 현재 발생한 알람만 정지하며 부탁 완료·미래 예약 삭제로 처리하지 않는다. 자유로운 생성형 AI 대화 도입과 구분한다.

## 남은 검증

수정 빌드에서 시스템 바 대비·새 버튼·큰 글씨를 재확인한다. Android 실제 프로세스에서 한국어 명령과 임시 LOCAL CalendarProvider 저장·조회·취소를 검증한다. 실제 사용자의 클라우드 캘린더나 외부 알람 앱에 저장 완료를 주장하지 않는다.

## 중간 실행 및 수정 기록

- 22:02 새 QA APK에서 상태바 대비 보정 확인. 22:03 새 전체 화면 CTA가 잠금 상태에 보이고 OS 패턴 해제를 요청했다.
- 사용자가 직접 잠금을 풀었지만 첫 요청은 알람 화면에 남았고, 잠금 해제 후 두 번째 탭은 AgentActivity를 열었다. 잠금 해제 callback과 후속 lifecycle 사이에 명시적 요청을 보존하는 수정 대상으로 지정했다. 잠금 패턴 입력은 사용자에게 맡겼다.
- 새 요청은 종료·취소·백그라운드의 늦은 callback이 화면을 열지 않도록 추가 검토한다. 최종 소스 판정은 `REVIEW_DEVICE_0.8.1.md` 마지막 절을 따른다.
- 예비 기기 테스트 3개 중 로컬 부탁 저장·취소 1개 통과. AM/PM 확인은 안내가 메시지와 dialog 두 곳에 있어 테스트 matcher가 실패했다. 특정 날짜 알람은 선호 앱 설정을 갖고도 앱 선택을 다시 요청하는 코드 경로를 발견했다. 예비 실행 결과를 최종 통과로 기록하지 않는다.
- 선호 알람 앱을 명시적 null 인자로 덮어쓰던 경로와 대화 화면의 구현 용어·포괄적 저장 취소 안내를 수정 대상으로 지정했다.
