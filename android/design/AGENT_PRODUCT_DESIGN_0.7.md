# 나는 엄마다 — 0.7 엄마 전용 에이전트 설계

작성: GPT-6 Astra High 설계 단계. 이 문서는 구현 완료나 실제 서비스 연동을 뜻하지 않는다.
범위: 현재 Android 소스의 로컬 수집·부탁·브리핑을 검토하고, 첨부 공지를 이해하는 제품 목표와 당장 검증 가능한 개발 단계를 분리한다.
후속 순서: GPT-5.5 구현 → 빌드·회귀 검증 → GPT-6 Astra High 독립 검토 → 근거가 있는 결과만 배포 보고.

## 1. 제품 약속

엄마가 알림을 분류하고 날짜를 옮겨 적는 일을 모모가 맡는다. 엄마에게 남길 일은 실제 준비, 선택, 외부 신청의 최종 실행이다.
기본 경험은 대화창이 아니라 아침·저녁에 읽고 바로 행동할 수 있는 짧은 브리핑이다.
평가, 별점, 만족도 질문, 매 공지 분류 요청, 반복 확인을 넣지 않는다.
아침에는 오늘 나가기 전 준비·이동·마감을, 저녁에는 내일 준비·가까운 제출을 모은다.
선택형 체험은 필수 준비에 섞지 않으며, 대상이 아닌 아이의 체험은 기본 브리핑에서 제외한다.
정보 부족은 엄마의 할 일로 무조건 넘기지 않는다. 필요한 결정에 영향을 주는 질문만 한 번 묶어서 한다.
“다 했어요”, “신청됐어요”, “첨부까지 확인했어요”는 각각 실제 완료 근거가 있을 때만 말한다.

## 2. 현 코드에서 확인한 출발점

`NotificationCandidateParser`는 키워드와 첫 날짜 표현을 찾는 규칙이다. 표, 대상 학년, 선택 여부, 날짜 역할을 이해하지 못한다.
시간 없는 날짜를 23:59로 만들고, 지난 월일을 다음 해로 넘긴다. 실제 마감 근거로 쓰기에는 위험하다.
`CandidateActionPlanner`는 제출·신청 제목과 날짜만 있어도 부탁을 자동 생성한다. 제목의 발행일을 신청 마감으로 오인할 수 있다.
`AssistantAlertNotifier`는 오늘 날짜이거나 12시간 이내이면 알린다. 오늘 이미 지난 기한도 통과하고, 선택 프로그램도 긴급해질 수 있다.
`BriefingActivity`는 공지 최대 3개와 부탁을 합산하므로 같은 출처가 이중 집계될 수 있고, 미래 부탁이 오늘 할 일처럼 보일 수 있다.
`LocalAgentEngine`은 저장된 알림·부탁의 제한된 질문에 답하는 로컬 규칙 엔진이다. 범용 생성 AI가 아니다.
`ProbeRecord`에는 알림 텍스트만 있다. 첨부 바이트·페이지·OCR 결과·실제 첨부 수집 경로는 없다.
웹 쿠키는 로그인 증명이 아니며, 개인 공지 수집은 아직 없다. `ConnectorCatalog.isLikelySignedIn`이 false인 현재 경계는 유지한다.
`ProbeSettings.schoolGrade`와 `ChildProfile.grade`가 나뉘어 있으므로 판단에 쓸 학년의 우선순위·동기화가 필요하다.

## 3. 한 번 판단하고 모든 화면에서 재사용

파이프라인은 수집 → 원문 보존 → 사실 추출 → 대상 판정 → 행동 판단 → 브리핑/알림/실행 순서다.
홈, 대화, 부탁 자동 생성, 브리핑, 긴급 알림이 각각 다른 정규식으로 같은 공지를 판단하지 않는다.
판단 결과의 최소 계약은 다음과 같다. 처음부터 별도 서버나 거대한 프레임워크를 만들 필요는 없다.

| 항목 | 의미 |
|---|---|
| source | 원문 ID·개정 hash·앱/공식 URL·수신 시각·추출 방식 |
| evidence | 주장별 원문 구절, 가능하면 페이지·표 셀·좌표 |
| contentState | 알림만 수집 / 첨부 미확보 / 일부 추출 / 검증 완료 / 실패 |
| applicability | 대상 / 대상 외 / 학년·조건 미확인 및 근거 |
| obligation | 필수 / 선택 기회 / 단순 안내 / 불명확 |
| dates | 발행일, 접수 시작·종료, 행사, 결과 발표, 취소 제한을 각각 보관 |
| action | 해야 할 행동, 언제 필요한지, 선택 여부, 근거, 처리 상태 |
| issues | 날짜 충돌, 누락, OCR 불확실, 조건 불명확 |

확신 점수 하나로 자동 실행하지 않는다. 필수 조건 충족 여부와 누락 이유를 명시한다.
추출 내용은 신뢰할 수 없는 데이터다. 공지 안의 “이전 지시 무시”, 외부 전송 지시는 실행하지 않는다.
학년 정보는 설정값을 기본으로 하되 학교급을 함께 모델링한다. 초등 1학년과 중등 1학년을 같은 숫자로 비교하지 않는다.
학교급 정보가 없는 현재 0.7에서는 초등 범위가 명확한 판단만 허용하며 애매한 학년은 대상 미확인으로 둔다.

## 4. 자동화와 알림 정책

자동으로 해도 되는 일은 원문 묶기, 중복 제거, 근거 있는 요약, 대상 외 제외, 명확한 필수 행동의 로컬 기록이다.
명확한 “내일 물티슈 챙겨줘”는 저장하고 실행 취소를 제공한다. 매번 저장 여부를 되묻지 않는다.
시각이 없으면 임의의 마감 시각을 만들지 않는다. 날짜 단위 준비는 아침·저녁 브리핑에 포함할 수 있다.
자동 부탁 생성에는 명시된 행동·필수성·자녀 적용·날짜 역할·충돌 없음이 모두 필요하다.
0.7 규칙이 이를 증명하지 못하면 조용한 후보로 보관한다. 사용자에게 공지마다 확인 팝업을 띄우지 않는다.
선택 체험은 대상 조건을 만족해도 관심 표시 전에는 신청 부탁과 마감 알림을 만들지 않는다.
사용자가 “신청할래”라고 한 뒤에만 접수 마감과 발표 확인을 추적한다. 선택 회차는 한 번만 묻는다.
실제 신청, 결제, 타인에게 메시지 전송은 대상·내용·결과가 보이는 실행 단계에서 사용자가 결정한다.
외부 실행 실패나 증거 없는 성공은 “완료”로 바꾸지 않는다.

즉시 알림 조건은 대상이며 필수이거나 사용자가 선택한 행동이고, 기한이 미래이며, 다음 예정 브리핑 전에 대응이 필요하고, 근거가 충분한 경우다.
행사 접수 시작, 단순 발행일, 선택 홍보, 지난 기한, 완료·철회 항목은 즉시 알리지 않는다.
안전·등하교 변경도 실제 관련 공지 근거가 있어야 하며 키워드만으로 비상 경보를 만들지 않는다.
일반 부탁별 자동 푸시는 기본 생성하지 않는다. 명시적인 사용자 시각 알림은 그 요청을 따른다.
같은 출처·행동·개정에 대한 알림은 한 번만 보낸다. 내용이 실질적으로 바뀐 경우만 다시 알린다.
일반 브리핑은 낮은 방해 수준을 기본으로 하고, 사용자가 선택한 알람 모드만 별도 유지한다.

## 5. 홈과 브리핑 UX

홈 첫 화면: “오늘 챙길 일” → 최대 3개의 구체적 행동 → 필요한 선택 1묶음 → 접힌 새 소식.
행동 카드에는 “무엇 / 언제 / 누구 / 근거”를 짧게 표시하고 `완료`, `원문`을 제공한다.
평가용 버튼을 만들지 않는다. 완료·관심 없음은 실제 상태 변경이며 답변 품질 평가가 아니다.
아침 예: “지우 물티슈 1개 챙기기 · 오늘 등교 전 / 학교 알림 9월 15일”.
저녁 예: “내일 준비 1개, 금요일 회신 1개예요.” 완료·대상 외·중복 소식은 읽어주지 않는다.
선택 예: “신청 가능한 과학 체험 1개가 있어요.” 상세를 열면 대상·선정 방식·접수 기간·회차 선택을 보여준다.
해당 없음 예: “저장된 소식에서 지금 챙길 일은 없어요.” 마지막 수집 시각과 첨부 미확인 상태는 작은 상태줄에 둔다.
수집이 끊기면 “할 일 없음”과 구분한다. 복구할 수 있는 조치만 한 번 안내한다.
브리핑을 열었다고 행동을 완료하지 않는다. 화면에서 보여준 범위의 열람 상태와 완료 상태를 분리한다.
출처 공지와 그 공지에서 만든 부탁은 같은 항목으로 표시한다. 완료된 출처 행동을 새 후보로 되살리지 않는다.
엄마가 질문하면 동일한 판단 결과로 답하고, 판단에 없는 내용은 “원문에 없어요/아직 읽지 못했어요”로 답한다.

## 6. 첨부·OCR·표·멀티모달 설계

1. 획득: 공식 API 또는 검증된 인증 세션으로 첨부를 받는다. 미지원 앱은 Android 공유/파일 선택으로 최초 1회 전달한다.
2. 검증: MIME·크기·페이지 수·출처 호스트를 제한하고, 인증 실패/만료 링크/손상 파일을 별도 상태로 남긴다.
3. 추출: PDF 텍스트 레이어가 있으면 먼저 사용한다. 이미지 페이지는 로컬 OCR 가능 여부를 확인한다.
4. 구조: 문단, 표 행·열, 병합 셀, 머리글 연결을 보존한다. 평탄화 텍스트에서 날짜 하나만 뽑지 않는다.
5. 시각 확인: 지원되는 멀티모달 경로가 있다면 숫자·시각·대상 셀을 원본 이미지와 대조한다.
6. 검증: 요일 일치, 날짜 순서, 신청/행사 구분, AM/PM 대안, 학년 조건, 누락·충돌을 검사한다.
7. 결정: 근거 있는 사실만 행동으로 만들고, 중요 셀이 읽히지 않으면 자동 기한·알림을 보류한다.
8. 보존: 암호화 원문과 최소 파생 사실을 보관하며, 원문 만료 뒤 근거를 볼 수 없다는 상태를 표시한다.

페이지별 성공/실패를 관리한다. 일부 페이지만 읽었으면 전체 첨부 확인으로 표시하지 않는다.
표의 “오전/오후 동일 프로그램”은 선택지 두 개다. 행사 두 건이나 두 회차 모두 참석으로 변환하지 않는다.
인원 40명의 범위가 애매하면 “정원 40명 표기, 회차별 여부 미확인”을 유지한다.
추출·실행 로그에 원문, 자녀명, 토큰을 기록하지 않는다. 캐시·썸네일·파생 요약도 삭제 정책 대상이다.
0.7에 OCR 엔진이 없으면 상태·경계만 제공하고 “OCR 지원 전”으로 표시한다. 테스트용 수동 전사는 OCR 성능 증거가 아니다.

## 7. 실제 첨부를 기준으로 한 정답 계약

참조: 사용자 제공 1페이지 “2026 토요미래산책(10월) 학생체험 프로그램 신청 안내”. 아래 내용은 설계 입력의 판독 결과다.
앱이 실제 파일을 수집하거나 OCR에 성공했다는 의미가 아니며, 회귀 fixture에는 `manual_reference_transcription` 출처를 붙인다.
정확한 첨부 판독 계약은 같은 디렉터리의 `ATTACHMENT_CASE_20260915.md`를 함께 사용한다.

| 구분 | 보존할 사실 |
|---|---|
| 문서 날짜 | 본문 2026-09-17, 전달 파일명 날짜 2026-09-14: 충돌 표시, 발행일 확정 보류 |
| 대상 | 초등 5~6학년, 중등 1~3학년; 초등 1~2학년이면 대상 외 |
| 성격 | 선택형 체험 모집; 학교 필수 준비물/필수 신청으로 만들지 않음 |
| 행사 | 2026-10-17, 2026-10-31 |
| 회차 | 각 날짜 오전 10:00~12:30 또는 오후 14:00~16:30; 동일 프로그램 중 선택 |
| 10월 17일 | 초등 생태계 병 만들기 / 중등 AI 정조대왕의 힙한 환영 |
| 10월 31일 | 초등 로봇 공룡 / 중등 반도체 |
| 장소 | 수원 장안구 미래과학교육원 전시관 3층 융합과학체험교실 |
| 정원 | 각 프로그램 40명 표기; 회차별 40명인지는 추가 근거 없이 단정 금지 |
| 신청 기간 | 2026-09-28 월 17:00 ~ 2026-10-02 금 09:00 |
| 선정 | 원문 ‘선착순 마감’, 선정 발표 2026-10-07 수; 추첨이라고 해석하지 않음 |
| 신청 경로 | gise.kr → 체험활동 → 체험학습신청 |
| 취소 | 체험 3일 전까지 가능; 정확한 마감 시각이 없어 23:59 생성 금지 |
| 결석 | 무단 불참 시 불이익 표기; 세부 수준은 원문 근거 없이 확장 금지 |
| 미기재 | 비용·교통편 없음; 무료/차량 제공을 추측하지 않음 |

초등 1~2학년 엄마에게는 기본 브리핑·부탁·긴급 알림을 모두 생성하지 않는다.
직접 물으면 “이 안내는 초등 5~6학년과 중학생 대상이라 지금 아이 학년에는 해당하지 않아요.”라고 근거와 함께 답한다.
학년 미등록이면 안내 상세에 “대상 학년 확인 필요”를 두되 선택 홍보 하나 때문에 전체 사용을 막지 않는다.
초등 5학년이 관심 표시하면 “9월 28일 17시에 접수가 열리고 10월 2일 09시에 끝나요. 선착순 마감이에요.”라고 답한다.
접수 시작을 마감으로, 발표일을 행사일로, 행사일을 신청 기한으로 바꾸지 않는다.

## 8. AI 계정·무료 사용의 현실적인 선택

| 경로 | 가능한 것과 제품 결정 |
|---|---|
| 현재 로컬 규칙 | API 계정·전송 비용 없이 제한된 추출/분류/브리핑 가능. “생성 AI 연결”로 표시하지 않음 |
| OpenAI API | API 키 기반 연동. 일반 ChatGPT 로그인/구독을 이 앱의 무료 범용 API로 전환하는 경로는 전제하지 않음 |
| Gemini API 무료 구간 | 프로젝트·키·모델별 할당량이 필요. 무제한·평생 무료 보장 금지 |
| Gemini 무상 서비스 데이터 | 개인·민감·기밀 원문을 보내는 기본 경로로 채택하지 않음. 학습·검토 조건 때문에 아동 공지 자동 전송 부적합 |
| 유료 또는 개인정보 보호 계약 AI | 향후 선택. 서버 자격 증명 보호·최소 전송·삭제 정책·요금 한도 검증 후 활성화 |
| Android 온디바이스 생성 AI | 기기 지원·모델 다운로드·전경/백그라운드 제약 확인 필요. S24+ 지원이나 백그라운드 추론 가능성을 가정하지 않음 |

기본값은 로컬 처리다. 개인정보를 지운 일반 공개 프로그램 텍스트도 완전 익명화가 증명되지 않으면 무료 원격 AI로 보내지 않는다.
원격 경로를 도입할 때 전체 알림함·자녀 프로필·쿠키를 보내지 않고 해당 작업의 최소 발췌만 전송한다.
LLM 출력은 JSON 계약·원문 대조를 통과해야 하며 모델이 직접 작업 저장이나 네트워크 실행 권한을 갖지 않는다.
연결 실패, 429, 키 만료, 비용 한도 도달 시 로컬 브리핑은 계속 동작하고 “고급 분석 대기”로 남긴다.
지금 자격 증명이 없으므로 가짜 provider 응답, 성공 연결 배지, 숨은 유료 호출을 추가하지 않는다.
Apps SDK OAuth는 ChatGPT가 우리 서비스에 인증하는 방향이다. Codex 전용 로그인도 일반 Android 추론 API의 사용 권한 증거가 아니다.
ML Kit 한국어 로컬 OCR은 검토 가능한 후속 경로이나 새 SDK 의존성 승인이 필요하며 표 의미 해석을 보장하지 않는다. [Android Text Recognition](https://developers.google.com/ml-kit/vision/text-recognition/v2/android).
근거: [OpenAI quickstart](https://developers.openai.com/api/docs/quickstart), [Gemini billing](https://ai.google.dev/gemini-api/docs/billing), [Gemini terms](https://ai.google.dev/gemini-api/terms), [ML Kit GenAI](https://developers.google.com/ml-kit/genai).
이 링크들의 외부 사실은 상위 작업에서 확인한 자료를 사용했으며 실제 연동 시점에 조건을 다시 확인한다.

## 9. 커넥터의 연결 완료 기준

앱 알림 접근은 “새 알림 수집 중”이다. 앱 내부 과거 공지·첨부까지 연결되었다고 말하지 않는다.
공개 나이스 API 성공은 공개 학교정보 연결이며, 학부모 성적·출결 계정 연결과 별개다.
웹 로그인은 공식 사이트에 직접 입력한다. 앱은 비밀번호를 수집·저장하거나 인증을 우회하지 않는다.
쿠키 있음, 로그인 페이지 이동, 사용자 “로그인했어요”만으로 `CONNECTED`를 만들지 않는다.
실제 인증된 읽기 요청과 예상 데이터 검증이 모두 성공해야 개인 공지 연결 완료다.
상태는 로그인 대기 / 세션 저장됨·조회 미검증 / 조회 가능 / 재로그인 필요 / 일시 오류를 구별한다.
마지막 조회 성공 시각, 읽을 수 있는 데이터 범위, 첨부 지원 여부를 연결 카드에서 보여준다.
세션 만료 시 무한 재시도하지 않는다. 한 번 묶어서 재로그인을 안내하고 기존 로컬 기록은 유지한다.
개인 커넥터는 공식 허용 방식과 실계정 읽기 검증 전까지 준비 중이다. 웹페이지 렌더링 성공을 수집 성공으로 대체하지 않는다.

## 10. GPT-5.5가 구현할 0.7의 완료 가능한 범위

1. 근거·추출 상태·대상·필수성·날짜 역할을 담는 작은 자료형과 공통 로컬 판단 함수를 도입한다. 초등 학년 범위·복수 날짜·원문 누락을 보수적으로 판정한다.
2. 기존 자동 생성과 즉시 알림을 공통 판단으로 제한한다. 일반 자동 작업의 개별 예약 알림을 제거하고 브리핑으로 묶는다.
3. 시간이 없거나 역할이 불명확한 날짜로 자동 마감을 생성하지 않는다. 모호한 복수 날짜는 첫 날짜를 선택하지 않는다.
4. 홈·브리핑·대화가 대상 외/선택을 필수로 표시하지 않도록 통합하고, 출처가 같은 부탁과 공지를 중복 제거한다.
5. 브리핑을 오늘/내일/가까운 마감으로 정렬하며 완료·만료·대상 외를 제외한다. 정보 없음과 수집 실패를 구분한다.
6. 명확한 로컬 저장 명령의 불필요한 재확인을 줄이고 실행 취소를 제공한다. 외부 신청 성공을 흉내 내지 않는다.
7. 현재 기능에 맞게 온보딩·개인정보·상세·대화 문구를 일치시킨다. 자동 생성함/안 함이 모순되는 문구를 고친다.
8. AI·첨부·개인 웹 조회의 실제 미지원 범위를 정직하게 표시한다. 이 단계에서 새 API/OCR 의존성이나 허위 서버를 추가하지 않는다.

레거시 자동 부탁은 출처와 생성 경로가 충분히 구분되지 않는다. 기존 명시적 사용자 부탁을 일괄 삭제하지 않는다.
이전 자동 생성 경로가 남긴 불확실한 알림은 재판정해 예약을 해제하되 기록을 보존하고 사용자가 상태를 볼 수 있게 한다.
현재 저장 모델로 자동/사용자 출처를 구별할 수 없으면 무리한 추정 마이그레이션 대신 앞으로의 생성 경로부터 구별한다.
수정 대상 중심: `data/NotificationCandidateParser`, `task/CandidateActionPlanner`, `reminder/*`, `agent/LocalAgentEngine`, `ui/ProbeScreens` 및 대응 테스트.
이 단계 완료는 “로컬 비서 판단·브리핑 개선”이다. 실제 OCR·생성 AI·개인 공지 커넥터 완료와 구분해 보고한다.
다음 단계는 공유 파일 획득+로컬 OCR의 기기 검증, 그다음 개인정보 조건을 충족하는 provider, 마지막으로 사이트별 실계정 커넥터다.

## 11. 수락 테스트와 Astra 검토 기준

| 시험 | 기대 결과 |
|---|---|
| 위 체험 공지 + 초등 1 또는 2학년 | 자동 부탁·일반 행동 브리핑·즉시 알림 모두 0; 질문에는 대상 외 근거 |
| 위 체험 공지 + 초등 5학년 | 관심 전 선택 소식; 필수 준비나 자동 신청으로 만들지 않음 |
| 접수 시작·종료·발표·행사 날짜 혼재 | 역할 유지 또는 불확실로 보류; 첫 날짜 자동 마감 금지 |
| 오전/오후 동일 프로그램 | 두 개의 대안; 양쪽 모두 참석으로 생성 금지 |
| 문서/파일명 날짜 충돌, 비용 없음 | 충돌·미기재 유지; 발행일·무료·교통 추측 금지 |
| 시간 미기재, 지난 날짜, 복수 의미 날짜 | 23:59/내년/첫 날짜를 확정 기한으로 자동 생성하지 않음 |
| 명확한 필수 물품 + 일치 학년·행동 날짜 | 브리핑 한 항목; 같은 공지 업데이트 시 중복 생성 없음 |
| 오늘 이미 지난 기한 | 즉시 알림 0 |
| 다음 브리핑 전에 끝나는 검증된 필수 기한 | 즉시 알림 한 번; 완료·철회·다른 학년은 제외 |
| 공지와 연결 부탁, 완료 후 같은 공지 재수신 | 한 번만 표시; 완료 항목 자동 부활 금지 |
| 첨부 미확보/일부 페이지만 성공/키 없음 | 읽은 범위만 표시; 확인 완료·AI 연결 성공 주장 없음 |
| 쿠키만 있음/로그인 화면 이동 | 개인 공지 연결 완료 금지 |
| 연결 해제·동의 철회·알림 권한 없음 | 수집·예약·전송 경계 유지; 가능한 로컬 상태는 정직하게 표시 |
| 명확한 “내일 물티슈 챙겨줘” | 중복 확인 없이 로컬 저장·취소 가능; 외부 실행 없음 |

회귀 검증은 parser/planner/briefing/agent/store의 의미 있는 단위 테스트와 기존 UI 렌더 테스트를 우선한다.
테스트 fixture의 수동 전사를 실 OCR 검증으로 보고하지 않는다. 실기기 첨부·권한·백그라운드 동작은 별도 증거가 필요하다.
Astra 검토는 틀린 자동 행동, 정보 누락의 은폐, 개인정보 외부 전송, 허위 연결, 알림 피로, 반복 사용자 노동을 우선 차단한다.
최종 보고에는 변경 파일·검증 결과·남은 미지원 기능을 짧게 명시하고 “완전한 AI 비서 구현 완료”로 과장하지 않는다.
