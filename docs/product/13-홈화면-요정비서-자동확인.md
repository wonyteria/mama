# 홈 화면 요정 비서와 자동 확인

2026-09-13 · 후속 제품 설계. 현재 APK에 구현된 기능을 뜻하지 않는다.

## 홈 화면에서 바로 부르기

## 첨부 시안의 사용자 검토

세 시안 중 알림 화면으로는 1번의 정보 구조가 가장 적합하다. 상단에서 ‘내일 준비물’이라는 결론을 크게 보여주고, 아래에 제출·준비·일정처럼 행동 단위를 나눈 뒤 주 CTA와 미루기를 둔 흐름이 엄마의 즉시 판단에 맞다. 2번은 한 항목을 처리하기 위한 상세 화면으로 적합하다. ‘무슨 일·누구·언제까지·해야 할 일’의 고정 필드는 신뢰를 높인다.

3번은 홈 대시보드 후보로는 풍부하지만 첫 알림 화면에는 정보가 많다. ‘AI가 확인한 해야 할 일’, ‘이 모든 것을 알아서 처리해줘’, 캘린더 추가·학부모 공유·쇼핑 버튼은 실제 구현과 승인 범위를 넘어설 수 있다. 현재 버전에서는 이 문구와 버튼을 사용하지 않고, 확인된 알림·사용자가 적은 부탁·실제로 가능한 행동만 표시한다.

최종 알림 레이아웃은 다음 순서로 고정한다.

```text
┌──────────────────────────────┐
│ 모모 · 분당초등학교       닫기 │ 정보원/닫기
│                                │
│ 내일 준비할 것이 있어요        │ 한 문장 결론
│ 준비물 4개 · 오전 9시 마감     │ 기한/수량
│                                │
│ ○ 체험학습 동의서 제출         │
│ ○ 도시락 · 물통 · 모자         │
│ ○ 일정 확인                    │
│                                │
│ [지금 확인하기]                │ 주 행동 1개
│ [30분 뒤]                      │ 부 행동
│ 원문 보기 · 원래 앱 열기        │ 근거/복구
└──────────────────────────────┘
```

상단 알림에는 아이 이름·학교·준비물 원문을 숨기고, 앱을 열어 잠금을 푼 뒤 상세를 보여준다. ‘알아서 처리해줘’는 실제로 가능한 행동이 여러 개이고 외부 제출·구매 성공을 자동 확인할 수 있을 때만 사용한다.

기본은 홈 화면 위젯이다. 클레이 질감의 작은 캐릭터와 ‘다음 할 일 1개’, 미완료 개수, 마지막 확인 상태를 보여준다. 사용자가 위젯 추가를 선택하면 런처의 추가 확인 절차를 따른다. 위젯은 다른 앱 위에 떠 있는 화면이 아니다.

캐릭터 탭은 앱의 일반 홈을 거치지 않고 작은 비서 전용 화면으로 연결한다. 빠른 행동은 ‘오늘 챙길 것’, ‘말하기’, ‘완료’다. 대화 입력·음성은 이 화면에서 수행한다. 위젯 안에서 상시 대기하며 대화를 듣지 않는다. 음성은 말하기를 눌렀을 때만 마이크 권한과 녹음을 시작한다.

다른 앱 위에도 항상 보이길 원하는 사용자를 위해 가장자리의 작은 떠다니는 캐릭터를 후속 옵션으로 검증한다. 다른 앱 위에 표시 권한을 별도로 요청하고, 이동·접기·오늘 숨기기·끄기를 제공한다. 운영체제와 앱이 오버레이를 막는 화면에서는 표시하지 않는다. Android 대화 버블은 대화 요건이 있으므로 범용 캐릭터를 항상 띄우는 기능으로 가정하지 않는다.

## 캐릭터 기준

- 초기에는 한 캐릭터로 일관성을 검증한다. 후보는 잎사귀 요정·작은 토끼·고양이이며 이름을 바꿀 수 있게 설계한다.
- 취향을 성별로 단정하지 않고, 차분한 캐릭터 보기와 캐릭터 없이 카드만 보기를 제공한다.
- 표정/짧은 동작은 기다리는 중·새 소식·준비 완료를 돕는 정도로 제한한다. 지속 애니메이션을 전제로 하지 않는다.
- 늦었다고 혼내거나 캐릭터를 슬프게 만드는 보상/벌 시스템을 넣지 않는다.
- 상태는 색·표정만으로 전달하지 않고 읽을 수 있는 짧은 문구와 접근성 설명을 함께 제공한다.

## 자주 챙겨주는 방식

‘자주 보임’과 ‘자주 소리냄’을 분리한다. 캐릭터와 미완료 항목은 위젯에 남고, 주의를 끄는 알림은 사용자가 고른 빈도로 보낸다.

| 강도 | 브리핑 제안 | 중간 알림 |
|---|---|---|
| 조용히 | 저녁 1회 | 사용자가 지정한 일정 알람 |
| 기본 | 아침·저녁 | 중요한 변경·당일 마감 |
| 꼼꼼히 | 아침·점심·저녁 | 미완료 중 기한이 가까운 항목, 항목별 재알림 최대 1회 |

시간은 변경 가능하며 새 소식과 미완료가 없으면 생략한다. 완료·취소하면 예약을 제거한다. 조용한 시간, 하루 알림 상한, 오늘 쉬기를 적용한다. 무응답만으로 알림 빈도를 자동으로 높이지 않는다. 아침·점심·저녁 문구는 11번 문서의 비서 알람과 같은 Action 저장소를 사용한다.

## 웹 자동 확인: 주기적 로그인 대신 인증을 관리하는 조회

1. 서비스별 새 공지 이벤트/API가 있으면 우선 사용한다. 없으면 사용자에게 안내한 주기와 제공자 호출 한도 안에서 읽기 전용 조회를 예약한다.
2. 예시 시작 일정은 아침·점심·저녁 브리핑 전 확인이다. 하루 3회만 조회하면 조회 사이의 공지는 지연될 수 있음을 지원표에 표시한다. 급한 변경은 푸시 감지 후 조회 등 별도 경로가 필요하다.
3. 매번 ID·비밀번호로 로그인하지 않는다. 기존 세션 검증→유효하면 조회→지원하는 토큰/자동 로그인 갱신→필요할 때만 재인증 순서다.
4. 알려진 만료시각에 따라 갱신을 예약할 수 있지만, 브리핑/조회 주기와 인증 갱신 주기는 별개다. 서버 절대 만료를 keep-alive로 막는다고 약속하지 않는다.
5. CAPTCHA·OTP·동의 재요청이면 반복 로그인 시도를 멈추고 한 번의 재인증 안내를 보낸다. 실패 재시도는 횟수 제한과 지연을 적용해 계정 잠김·과도한 요청을 방지한다.
6. 브리핑 시점에 확인 실패면 기존 할 일은 보여주되 ‘e알리미는 어제 저녁 이후 확인하지 못했어요’처럼 정보가 오래됐음을 표시한다. 미확인을 ‘새 소식 없음’으로 표현하지 않는다.
7. 재연결하면 마지막 성공 이후 공지·변경·첨부를 회수하고 원래 ID로 중복을 막는다. 다른 앱·사이트의 정상 확인은 계속한다.

폰 내부 예약은 절전·오프라인·강제 종료 영향을 받는다. WorkManager 주기는 최소 15분이며 정확한 시각 실행을 보장하지 않는다. 허용된 서버 연동은 폰이 꺼진 동안의 조회를 보완할 수 있지만, 제공자 인증·개인정보 처리·서버 저장 설계를 먼저 검증해야 한다. 서버가 조회해도 오프라인 폰에 즉시 알려줄 수 있다는 뜻은 아니다.

## 백로그와 합격 기준

- B19/P1 홈 위젯: 런처 추가, 정확한 미완료/확인시각 표시, 앱 전체 탐색 없이 완료 처리, 늦은 탭의 상태 충돌 처리.
- B20/P1 비서 호출 화면: 위젯에서 바로 열기, 오늘 할 일/명시 음성 입력, 실행한 행동을 확인 가능하게 표시.
- B21/P1 알림 강도: 조용히/기본/꼼꼼히, 시간 편집·조용한 시간·재알림 상한이 실제 예약에 반영.
- B22/P2 떠다니는 캐릭터: 선택 권한·숨기기·끄기·서비스 종료·권한 철회·회전·접근성·배터리 검증.
- B23/P2 캐릭터 선택: 우선 한 캐릭터 검증 후 변형, 캐릭터 없는 모드 유지.
- B24/P0 조회/갱신 일정 분리: 앱 닫힘·만료·오프라인·복구 실측, 최신 상태 오표시 없음. B02/B03에 종속.
