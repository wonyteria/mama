# 나는 엄마다 — V0 기능명세서

버전 1.2 · 2026-09-13 · 통합 연결 목록과 상황별 권한 요청 반영. 개발 기준은 이 문서의 상태·데이터·동작 규칙이다.

## A. 공통 계약

### A1. 제품·권한 경계

- 소비자 V0는 자체 회원가입 없는 단일 설치·자녀 1명·앱 Source 최대 2개·무료 베타다. 외부 사이트 로그인은 공식 화면과 제공자 세션만 사용하며 우리 앱 계정·범용 비밀번호 금고·클라우드 기록 동기화·결제 API를 만들지 않는다.
- 앱 재실행은 로컬 상태를 복원한다. 앱 제거/데이터 초기화/새 기기는 새 사용자 상태로 시작하며 복구하지 않는다. 민감 DB·설치 자격증명은 OS 백업·기기 이전 대상에서 제외한다.
- 최초 동의 뒤 설치별 키를 생성한다. AI 요청용 설치 토큰 발급/갱신은 백그라운드 인증이며 회원가입이 아니다. 설치 토큰 만료는 로컬 조회·수정·완료를 막지 않는다.
- 로컬 기기 잠금 해제를 신뢰 경계로 삼는다. 앱 내부 별도 PIN·가족 권한은 없다. 운영자는 사용자 Action을 원격 열람하는 기능이 없다.
- 수집 허용 조건 C = 필수 동의 유효 AND Memory ON AND 자녀 존재 AND 해당 Source ON AND 알림 접근 허용. 네트워크는 수집 조건이 아니고 서버 전송 조건이다.
- 전송 직전과 결과 저장 직전에 C 및 `collection_epoch`를 다시 검사한다. OFF/삭제/동의 철회 이후 도착한 응답은 폐기한다.
- 발송 조건 R = Memory ON AND 자체 알림 권한/채널 허용 AND 유효한 미완료 Action 또는 확인 후보 AND 해당 리마인더 버전 유효. Source OFF는 기존 Action의 R을 끄지 않는다.
- 권한 거부 시 자동으로 재요청 루프를 돌리지 않는다. 설명과 수동 ‘설정 열기’를 제공한다.
- 사용자 표시 용어: Source→‘챙길 앱’, Memory→‘자동 챙김’. 리스너/epoch/토큰은 UI에 표시하지 않는다. 기술 상태는 내부 진단값으로만 사용한다.
- 소비자 신규 동선은 S01→S02→S10→S05다. S04는 앱 스위치 최초 ON에만 표시하는 이유 팝업과 OS 알림 접근 화면이다. 사이트 스위치는 허용 도메인의 공식 로그인 화면으로 직접 이어진다.
- 홈 진입 조건은 자녀와 앱 알림 연결 또는 사용 가능한 사이트 연결 하나다. 앱 권한·사이트 로그인을 취소하면 S10에 머물고 해당 스위치를 OFF로 복원한다. 중간 종료 후에는 저장된 자녀와 완료된 연결만 복원한다.
- 앱 스위치 ON은 알림 접근 확인 전 pending 값이다. 권한 복귀 성공 뒤에만 Source 선택을 확정하고, 첫 새 알림 전 ‘첫 알림 기다리는 중’, 수신 뒤 ‘알림 연결 확인됨’으로 표시한다. 이미 OS 읽기 권한이 남아 있어도 사용자가 켜지 않은 package는 수집하지 않는다.
- 최초 null이던 학교/학원 정보를 추가하는 행위만으로 Source를 OFF하지 않는다. 이미 지정되어 있던 Source의 기관이 실제로 변경/삭제됐을 때만 F03의 재지정 규칙을 적용한다. 새로 입력한 기관과 앱의 연결은 임의 추측하지 않고 선택 정보를 통해 지정한다.

### A2. 저장과 오류의 공통 동작

- 사용자가 명시적 저장을 누르기 전 폼 변경은 임시값이다. 뒤로가기는 변경이 있을 때만 ‘변경을 버릴까요?’를 묻는다. 저장 실패 시 입력 유지·재시도 제공.
- 로컬 저장·Action 버전 증가·리마인더 변경 의도(outbox)는 같은 트랜잭션으로 확정한다. 실제 OS 예약은 outbox 재처리로 복구한다. 발송 시 DB를 다시 읽어 취소된 알림을 차단한다.
- 버튼 연타는 비활성화와 작업 ID로 한 번만 처리한다. 저장 성공 후에만 완료 화면/토스트를 표시한다.
- `version`이 편집 진입 때와 다르면 덮어쓰지 않고 ‘새 정보가 있어요. 다시 확인해주세요’와 최신값을 표시한다. 같은 키 재시도는 동일 결과를 반환한다.
- 오프라인에서도 기존 기록 조회·수정·완료·삭제 가능. AI 생성만 대기한다. 처리 실패를 빈 목록과 혼동하지 않는다.
- 시각 저장은 UTC instant + 해석 시간대 `Asia/Seoul`; 날짜만 있으면 `local_date`와 `precision=DATE`를 저장한다. 가짜 00:00 마감을 만들지 않는다.
- 입력 공통: 앞뒤 공백 제거, 제어문자 제거, 길이 초과 거부, HTML 실행 없음. 필수 오류는 필드 바로 아래. 민감 내용은 URL·분석 이벤트·일반 로그에 넣지 않는다.
- `reminder_hold`는 독립 토글이 아니라 **해당 Action을 참조하는 PENDING 변경 후보가 하나 이상 존재함**으로 계산한다. 후보 승인·무시·만료·Source OFF·권한 철회·Action 삭제 때 참조를 정리하고 모든 관련 Action의 hold를 같은 트랜잭션에서 재계산한다. 아래 ‘hold 해제’는 다른 대기 후보가 없을 때만 해제한다는 뜻이다. 여러 제안 중 하나 적용으로 Action 버전이 바뀌면 나머지 제안은 최신값과 다시 비교한 뒤 승인해야 한다.
- 실행 진입 우선순위는 삭제 진행 상태→읽을 수 있는 로컬 설정→온보딩/홈/딥링크다. 삭제 도중 재실행이 새 수집을 시작해서는 안 된다.

## B. 기능별 명세

### F01. 시작·설치 인증·재방문

1. **기능명:** 로그인 없는 시작과 설치 상태 복원.
2. **목적:** 계정 입력 없이 핵심 설정으로 진입.
3. **사용자 행동:** S01 ‘이 기기에서 시작’; 다음 실행 시 앱 또는 알림 탭.
4. **시스템 처리:** 동의 전 네트워크 식별자 생성/전송 금지. 동의 후 설치 키·토큰 생성. 설정 완료/명시적 나중에 선택이면 S05, 중간 종료는 마지막 저장 단계. 딥링크 대상은 로컬 존재/상태 확인 후 S06. 최초 동의 뒤에는 S03 앱 선택부터 시작하며 기관 입력을 선행 조건으로 요구하지 않음.
5. **입력값:** 시작 클릭, 로컬 onboarding_step, 선택적 action_id/candidate_id.
6. **출력값:** 신규 S03 또는 복원된 화면. 삭제된 딥링크는 ‘삭제되었거나 보관 기간이 끝난 항목’ 후 S05.
7. **필요 데이터:** Installation, Consent, Preferences, 로컬 DB 스키마 버전.
8. **예외 상황:** 토큰 만료→한 번 갱신 후 같은 요청 재시도; 실패→추출 대기, 기존 사용 유지. 기기 키 손실→수집 중단·S12 초기화 안내, 읽을 수 없는 기록을 복구했다고 표시하지 않음.
9. **권한 조건:** 사용자 로그인/로그아웃 없음. 토큰 발급은 필수 동의 후 TLS 연결. 다른 설치 토큰으로 요청 상태 접근 불가.

### F02. 동의·초기 설정 저장

1. **기능명:** 개인정보 처리 설명과 동의.
2. **목적:** 수집·AI 전송·보관·복구 제한을 이해한 상태에서 시작.
3. **사용자 행동:** S01 필수 설명 열람·동의, 선택적 베타 측정 동의, 계속.
4. **시스템 처리:** 선택 기본값 모두 OFF. 필수 동의 없으면 진입 버튼 비활성화. 동의 버전·시각 로컬 저장. 범위 확대 시 새 동의 전 수집 중단.
5. **입력값:** service_consent, ai_processing_consent, optional_metrics_consent Boolean.
6. **출력값:** 저장 성공 시 S03. 거부는 S01 유지/앱 종료 가능. 소비자 최초 선택 측정 안내는 기본 OFF로 ‘선택 설정’ 안에 접고 서비스 시작을 방해하지 않는다.
7. **필요 데이터:** Consent(version, purposes, granted_at, revoked_at).
8. **예외 상황:** 문구 로드 실패 시 내장된 동일 버전 설명 제공; 유효 버전 확인 불가면 새 수집 금지. 선택 동의 미허용도 서비스 정상 사용.
9. **권한 조건:** 약관·데이터 설명은 동의 없이 열람. 철회는 F18에서 처리.

### F03. 아이 등록·조회·수정

1. **기능명:** 자녀 프로필.
2. **목적:** 공지를 등록한 아이에게 맞게 연결.
3. **사용자 행동:** S02에서 이름/별칭 하나 입력, 원하면 ‘정보 더 입력하기(선택)’에서 학년·학교·학원 입력; S11에서 편집.
4. **시스템 처리:** 자녀 최대 1명, 기본값 없음. 수정은 앞으로의 매칭에 적용하며 기존 Action 내용/대상을 자동 변경하지 않음. 학교명/학원명 변경·제거로 Source가 참조하는 기관이 달라지면 프로필 저장 전 영향을 안내한다. 저장 시 해당 Source를 OFF로 전환하고 F04의 대기 정리를 함께 실행, S10 ‘기관 다시 지정 필요’를 표시한다. 사용자가 새 기관을 지정한 뒤 ON해야 재수집한다. 기존 Action의 출처 스냅샷은 유지한다.
5. **입력값:** name 1~20자 필수, grade nullable(입력 시 1~4), school_name nullable(입력 시 1~60자), academy_names 0~5개·각 1~60자. 생년월일·주소·연락처 미수집. 선택값 공란은 오류가 아니라 null.
6. **출력값:** 저장된 프로필; 최초 S04 읽기 안내, 편집 S11 복귀. 선택된 앱 초안이 없으면 먼저 S03으로 안내. 선택 Source가 있으면 프로필 저장과 함께 자녀 연결을 확정.
7. **필요 데이터:** Child(id, name, grade, school_name, academy_names, created_at, updated_at).
8. **예외 상황:** 두 번째 아이 추가 버튼 없음. 입력한 학년이 범위 밖이면 베타 미지원 안내. 이름·학교 근거가 없거나 별칭만으로 대상 확인이 불가능하면 확인 후보 생성. 학교/학년을 비웠다는 이유로 임의의 아이에게 자동 확정하거나 이름을 추측하지 않음.
9. **권한 조건:** 같은 설치의 데이터만 편집. 아이 삭제는 F19.

### F04. Source 선택·연결·ON/OFF

1. **기능명:** 분석 앱 관리.
2. **목적:** 사용자가 허용한 앱만 처리.
3. **사용자 행동:** S03에서 자동으로 표시된 지원 앱의 아이콘·이름을 보고 최대 2개 선택, 저장; S10에서 ON/OFF·제거. 기관 지정은 ‘연결 정보 더 보기’ 안의 선택 입력이며 처음 시작의 필수 단계가 아님.
4. **시스템 처리:** packageName으로 식별. 기본 OFF. ON 시 enable 시각 이후 알림만 수집. OFF/제거 시 epoch 증가·해당 앱 미처리 원문/후보 삭제·진행 응답 폐기. **기존 확정 Action과 리마인더는 유지**하며 변경 수집 중단 배지 표시.
5. **입력값:** catalog_source_id, package_name, institution_type(검증 카탈로그 값 또는 UNKNOWN), institution_name nullable, enabled. 제거 후 새 Source 선택 가능. 기관을 입력했으면 등록한 학교/학원 선택 또는 먼저 S02 선택정보 편집. 앱 유형을 실제 아이의 기관 정보로 추측하지 않음.
6. **출력값:** 자녀 전에는 선택 초안과 S02. 자녀가 있는 설정 편집은 S10, 홈의 설정 이어하기 경로면 빠진 읽기 단계 S04 또는 완료 S05. 작동 상태는 ‘설정됨·새 알림 기다리는 중’ 또는 마지막 수신 시각. OFF 확인에 기존 일정은 계속 알려준다는 설명. 첫 선택이 1개여도 계속할 수 있음.
7. **필요 데이터:** Source(id, package_name, child_id, institution, enabled, enabled_at, epoch, last_received_at, removed_at), SourceCatalog.
8. **예외 상황:** 설치된 지원 앱만 우선 표시하며 미설치 목록은 ‘지원 앱 보기’로 접음. 0개면 미지원 이유·다시 확인·나중에 제공. 3번째 선택→2개 제한. 수신 없음만으로 장애 단정 금지. 앱 삭제 감지 시 해당 Source OFF. 제거된 출처 라벨은 기존 Action에 남음. 설치 탐지가 되더라도 자동 체크/허용하지 않음.
9. **권한 조건:** C가 모두 충족되어야 수집. 앱 선택 자체는 알림 접근 권한 전에 가능. 전체 앱 목록 무제한 수집 대신 검증된 패키지 설치 여부만 확인.

### F05. 권한 요청·상태 진단

1. **기능명:** 알림 접근과 리마인더 발송 허용.
2. **목적:** 읽기와 보내기 실패를 구분하고 복구.
3. **사용자 행동:** 첫 S04에서는 읽기 권한 하나만 설명을 보고 OS 설정으로 이동, 돌아오기. 자체 알림 받기는 첫 실제 Action/후보를 앱에서 본 후 S05/S06/S08의 간단한 안내에서 ‘알림 받기’ 또는 ‘나중에’ 선택. S10에서는 언제든 재설정/테스트 가능.
4. **시스템 처리:** foreground 복귀·수집·발송 때 실제 권한 재조회. 최초 읽기 허용이 확인되면 재확인 버튼 없이 S05로 이동; 리스너 연결은 별도 관측하며 연결 전에는 준비 중으로 표시. 읽기 철회 시 대기 원문/후보 폐기·수집 중단, 확정 기록 유지. 보내기 미허용/거부 시 생성 계속·기기 알림 중단. OS 채널 차단도 별도 표시. 첫 실제 결과에 대한 앱 내 발송 안내는 자동 노출 1회만, ‘나중에’/거부 뒤 재팝업 금지. 권한이 이미 허용돼 있으면 안내 생략. 이후에는 홈 상태/설정에서 사용자가 직접 켜기.
5. **입력값:** 설정 열기, 테스트 클릭, OS 권한/연결 상태, foreground_first_real_result_visible. notification_prompt_seen을 안내가 실제 표시될 때 원자 저장하여 두 결과 동시 도착/재실행에도 자동 1회를 보장. 앱 전체 알림은 허용이고 채널만 차단이면 runtime 권한 대신 해당 채널 설정을 안내.
6. **출력값:** 사용자에게는 ‘설정을 이어주세요/연결 준비 중/새 알림 기다리는 중/새 알림을 확인했어요’와 필요한 행동 1개 우선 표시. 내부에는 읽기/보내기·리스너·관측 시각을 각각 기록. 테스트는 개인정보 없는 ‘테스트 알림’ 1개이며 실제 Source 수신 성공과 구분.
7. **필요 데이터:** PermissionSnapshot(observed_at, access_allowed, listener_connected, notifications_allowed, channel_allowed).
8. **예외 상황:** 시스템 화면 호출 실패→검증한 OS별 일반 설정 경로를 그림/짧은 단계로 제공. S04 ‘어디를 누르나요?’에 앱 선택→허용→앱으로 돌아오기 안내. OS별 버튼명을 모르면 정확한 명칭을 단정하지 않음. 거부/설정에서 길을 잃음→‘나중에’로 홈 진입. 리스너 연결 안 됨→재연결 시도 후 준비/문제 상태 유지. 강제종료·OS 제한 중 누락분 복구를 약속하지 않음. 접근성으로 대신 클릭하거나 권한 자동 허용하지 않음.
9. **권한 조건:** 읽기/보내기 독립. 정확 알람·접근성·연락처·SMS·위치·마이크 권한 요청 안 함.

### F06. 새 알림 수집·정규화·대기열

1. **기능명:** 자동 알림 수집.
2. **목적:** 반복 입력 없이 판단 재료 확보.
3. **사용자 행동:** 별도 행동 없음. 원래 학교/학원 앱을 평소대로 사용.
4. **시스템 처리:** 콜백에서 package 허용 검사 후 본문 처리. 자기 앱·ongoing·그룹 요약은 제외, 개별 자식 알림만 처리. title/text/bigText/textLines를 순서 있는 중복 제거 텍스트로 정규화. 명백한 광고 채널 외에는 키워드가 없다는 이유만으로 제외하지 않음.
5. **입력값:** packageName, notification key/id/tag, postedAt, title, text, bigText, textLines, subText, summaryText, category, channelId, isOngoing, isGroupSummary.
6. **출력값:** CanonicalNotification 및 QUEUED 상태. 본문 없음/잘림은 F08 확인 후보, 불허 Source는 저장·서버 전송 0건.
7. **필요 데이터:** Source, CanonicalNotification, CollectionEpoch, ProcessingJob.
8. **예외 상황:** 권한 이전/Source OFF 기간 알림은 소급 수집하지 않음. 같은 key라도 내용 변경은 새 revision. 오프라인은 암호화 로컬 큐 최대 24시간·500건. 넘으면 오래된 미처리부터 폐기하고 누락 수만 S10 표시. 원문은 로그에 넣지 않음.
9. **권한 조건:** C 필수, 네트워크 없어도 로컬 큐 가능. 수집 당시에 허용됐어도 나중에 철회되면 전송 금지.

### F07. AI 추출·날짜·대상 검증

1. **기능명:** 알림을 행동 후보로 구조화.
2. **목적:** 행동과 참고를 구분하고 날짜 추측 방지.
3. **사용자 행동:** 자동 처리; 필요한 경우 F08 확인.
4. **시스템 처리:** 정규화 본문·게시 시각·허용 기관/아이 최소 정보만 추출 서버로 전송. AI JSON 배열을 스키마 검사하고 코드로 날짜 해석. 모델 confidence 외 필드별 근거·날짜/대상 충돌 검사. 한 알림의 여러 행동은 각각 Action으로 저장하되 같은 항목의 준비물들은 한 PREPARE의 items로 묶음.
5. **입력값:** request_id, source_type, child_context, posted_at, text, schema_version. 최대 본문 16KB; 초과 시 자르지 않고 확인 후보로 처리.
6. **출력값:** 후보 배열(kind, title, items, date_expression, time_expression, location, child_evidence, change_reference, evidence, confidence, requires_action). 날짜 확정은 A3 적용.
7. **필요 데이터:** ExtractionResult, Candidate, Action, DateResolution, 추출 버전·모델 식별자.
8. **예외 상황:** JSON 오류/timeout/429/5xx→F20 재시도. 0.80 이상이고 모든 검증 통과→자동 저장. 0.60~0.80 미만 또는 필수 검증 실패→확인 후보. 0.60 미만·내용 부족→구체 Action 생성 금지, Source별 일일 ‘원문 확인 필요’ 1개로 묶음. 확실한 광고/참고는 후보도 생성하지 않음. 임계값은 G1으로 교정하되 릴리스별 고정.
9. **권한 조건:** 유효 C·설치 토큰·AI 처리 동의. 서버 비밀키는 앱에 포함하지 않음. 외부 본문 속 지시를 명령으로 실행하거나 URL을 자동 열지 않음.

### F08. 확인 후보·원문 확인

1. **기능명:** 불확실한 추출 확인함.
2. **목적:** 모르는 내용을 확정 사실로 등록하지 않음.
3. **사용자 행동:** S08 목록→후보 선택→‘맞아요’, ‘수정 후 저장’, ‘이 아이와 관련 없어요’, ‘무시’, ‘출처 앱 열기’. 내용 부족 후보는 ‘확인했어요’로 종료만 가능.
4. **시스템 처리:** 날짜/대상 불확실 사유 표시. 승인 시 Action을 원자 저장하고 후보 RESOLVED; 수정은 S07 사용. 대상은 등록 아이 1명 또는 관련 없음만 선택. 정보 부족을 보완하려고 새 공지 입력 폼을 만들지 않음.
5. **입력값:** candidate_id, version, decision, 선택적 수정 필드. 날짜 미정 유지 선택은 허용하며 자동 예약 없음 안내.
6. **출력값:** 확정 Action 상세 S06 또는 다음 후보/빈 확인함. 무시는 DISMISSED.
7. **필요 데이터:** Candidate(id, reason, proposed_fields, source_refs, status, created_at, expires_at), Action.
8. **예외 상황:** 원문 열기는 보장되지 않음(F15). 미처리 후보는 7일 후 만료·삭제. 날짜가 이미 지나면 ‘지난 정보로 저장’ 재확인 후 저장, 소급 알림 없음. 모든 확인 후보는 반복 푸시 없이 다음 일반 묶음에 한 번만 포함.
9. **권한 조건:** 로컬 조회·확인은 읽기/발송 권한 없이 가능. Memory OFF에서는 기존 후보 조회만, 새 Action 저장은 다시 켠 뒤 가능. Source OFF/제거로 삭제된 후보는 조작 불가.

### F09. 중복 억제·변경/취소 적용

1. **기능명:** 같은 일 중복 방지와 변경 제안.
2. **목적:** 중복 카드와 잘못된 옛 일정 알림 방지.
3. **사용자 행동:** 일반 중복에는 행동 없음. S08에서 기존/새 값 비교 후 ‘변경 적용’, ‘기존 유지’. 연결 대상 없으면 ‘새 일정으로 저장’ 또는 무시.
4. **시스템 처리:** 동일 이벤트 revision은 hash로 멱등 처리. 의미 중복은 아이·kind·정규화 제목·날짜/시각·items·기관이 모두 같고 충돌 없을 때만 병합, source_refs 추가. 명시적 change/cancel와 기존 후보가 있을 때 변경 후보 생성. 기존 후보가 여러 개면 사용자가 고름. 선택/처리까지 해당 후보 Action들 reminder_hold=true.
5. **입력값:** normalized_hash, semantic_exact_key, change_type(RESCHEDULE/CANCEL/REPLACE), old/new fields, 선택한 target_action_id.
6. **출력값:** 단일 Action 또는 전후 비교 후보. 적용은 old version 보관·new version 갱신·이전 예약 취소. 취소 적용은 CANCELLED. 휴강+보강은 원 수업 CANCELLED와 새 EVENT 생성, 동일 change_group_id로 연결.
7. **필요 데이터:** Action, ActionRevision, Candidate.target_ids, Reminder, SuppressionHash, source_refs.
8. **예외 상황:** 신규 근거가 사용자 수정과 충돌→항상 확인. DONE 항목의 새 준비/마감 변경도 확인 후 OPEN 재개 여부를 명시. 무시/만료는 기존 값 유지·hold 해제. 단독 취소+대상 없음은 확정 일정 생성 금지. 날짜를 모르는 유사 항목은 자동 병합 금지.
9. **권한 조건:** 자동 처리 C, 사용자 적용은 F08 조건. 선택된 대상만 갱신; 다른 아이/설치 대상 참조 거부.

### F10. 오늘·기억 목록·상세 조회

1. **기능명:** 핵심 목록과 상세.
2. **목적:** 지금 챙길 것과 저장된 모든 판단을 짧게 확인.
3. **사용자 행동:** S05 오늘 목록, S09 기억 목록, 카드→S06 상세.
4. **시스템 처리:** A5 표시 규칙 적용. 모든 상세에 출처·수신 시각·확정/수정 여부·근거·다음 알림 표시. 확인 후보는 Action 개수에 포함하지 않음.
5. **입력값:** 화면, 필터(예정/완료·취소), action_id. 별도 검색·달력 입력 없음.
6. **출력값:** 로컬 최신 목록, 상세, 종료/변경 상태. 목록 30개씩 추가 로드.
7. **필요 데이터:** Action, Source labels, Reminder, Candidate count, 처리 상태.
8. **예외 상황:** 0건은 미설정/첫 수신 대기/실제 할 일 없음/오늘 완료를 구분. 원문 만료와 AI 실패는 별도 문구. DB 오류 시 오류·재시도, ‘오늘 할 일 없음’으로 표시하지 않음.
9. **권한 조건:** 로컬 데이터가 있으면 동의 철회 전까지 조회 가능. 발송/수집 권한 꺼짐은 배너이며 화면 차단 아님.

### F11. 완료·완료 취소

1. **기능명:** 행동 처리 상태 기록.
2. **목적:** 끝난 일의 알림을 중단.
3. **사용자 행동:** S06 ‘완료했어요’(TODO/PREPARE), ‘확인했어요’(EVENT); 완료 상태에서 ‘완료 취소’.
4. **시스템 처리:** OPEN/SNOOZED→DONE, completed_at 저장, 모든 해당 예약·표시 알림 취소. EVENT 완료는 참석 보장이 아닌 확인 의미를 UI에 설명. 취소 시 OPEN, 미래 기본 알림만 재계산.
5. **입력값:** action_id, version, complete/reopen.
6. **출력값:** DONE 상세·목록 즉시 갱신·하단 ‘취소’ 피드백. 과거 마감이면 재개 시 ‘기한 지남’.
7. **필요 데이터:** Action.status, completed_at, Reminder.
8. **예외 상황:** 이미 DONE 재클릭→같은 결과. CANCELLED는 완료 취소 불가; 잘못된 취소는 S07 수정 후 재개 확인. 변경 hold 중에도 완료 가능하나 변경 후보는 자동 해결되지 않음.
9. **권한 조건:** 같은 설치 로컬 항목. 네트워크/알림 권한 불필요.

### F12. 미루기·미루기 취소

1. **기능명:** 다음 리마인더 변경.
2. **목적:** 지금 처리 못 하는 일을 원하는 때 다시 확인.
3. **사용자 행동:** S06→S13 ‘1시간 뒤’/‘오늘 20시’/‘내일 07시’/직접 일시, 저장. S06에서 미루기 취소.
4. **시스템 처리:** 원래 마감은 유지, SNOOZED와 snoozed_until 저장. 그 시각 전 기본 예약만 억제. 시각이 지나면 발송 성공 여부와 독립적으로 OPEN으로 전환한다. 기기가 꺼져 있으면 다음 실행 때 즉시 상태를 정리한다. 실제 작업이 예정 시각+15분 이내이고 R이 유효할 때만 snooze 1회 발송; 권한/Memory OFF 또는 15분 초과 지연은 SKIPPED 처리하고 미래 기본 규칙만 복원한다. 미루기 시각 전 Memory를 다시 켠 경우에는 남은 미래 snooze를 복원한다.
5. **입력값:** 미래 시각(현재+1분 이후~30일 이내), action_id, version.
6. **출력값:** ‘마감은 9/18, 다음 알림은 9/17 20시’ 등 두 시각 분리 표시.
7. **필요 데이터:** snoozed_until, Reminder(kind=SNOOZE), Action.
8. **예외 상황:** 이미 지난 프리셋 비활성화. 마감 뒤 선택은 경고와 ‘그래도 이때 알림’ 확인. Memory/발송 권한 OFF이면 저장 가능하되 현재 푸시 불가 표시. 변경 hold 동안은 미루기 비활성화·변경 확인으로 안내. 완료/삭제/변경 적용은 snooze 취소.
9. **권한 조건:** OPEN/SNOOZED만 가능. 예약 저장 자체는 발송 권한 불필요; 실제 발송은 R.

### F13. 수정·잘못된 정보 처리

1. **기능명:** Action 정정.
2. **목적:** AI 오류를 적은 행동으로 바로잡음.
3. **사용자 행동:** S06 ‘수정’ 또는 ‘잘못된 정보예요’→S07, 값 변경/관련 없음 선택, 저장.
4. **시스템 처리:** 사용자 수정 필드를 보호 표시하고 버전 증가. 날짜/시간 변경 시 미루기와 기존 예약 취소 후 미래 규칙 재계산. kind 변경은 상태 유지. DONE/CANCELLED 수정은 자동 재개하지 않고 ‘다시 챙기기’ 체크 기본 OFF.
5. **입력값:** title 1~100자, kind 3종, local_date 선택/미정, time 선택/모름, items 0~30개·각 1~80자, location 0~120자, 오류유형(date/child/not_action/already_done/other). PREPARE는 item ≥1개 또는 명확한 준비 제목 필수.
6. **출력값:** 저장된 S06와 ‘사용자가 수정함’. 아이 틀림/행동 아님→F14 삭제 확인; 이미 끝남→F11 완료. other는 추가 자유문구 없이 수정 가능.
7. **필요 데이터:** ActionRevision, user_edited_fields, 선택적 ErrorFeedback(type only).
8. **예외 상황:** 날짜 미정으로 바꾸면 예약 모두 취소·확인 표시. 과거 날짜 저장 경고. 최신 버전 충돌은 A2. 원문에 없는 사용자 수정은 ‘원문에서 찾음’으로 표현하지 않음.
9. **권한 조건:** 같은 설치 데이터. 원문/수정값을 피드백 학습 데이터로 자동 전송하지 않음.

### F14. Action 삭제

1. **기능명:** 기억한 항목 영구 삭제.
2. **목적:** 필요 없거나 잘못된 저장 정보를 제거.
3. **사용자 행동:** S06 더보기→삭제→S14 범위 확인→삭제.
4. **시스템 처리:** Action·revision·근거·연결 후보·예약 제거. 연결 후보의 다른 대상 hold 해제. 같은 알림이 재수신되어도 30일간 재생성하지 않도록 기기 내부 keyed hash만 보관. 내용이 달라진 새 공지는 새 판단 가능.
5. **입력값:** action_id, version, delete confirmation.
6. **출력값:** 삭제 성공 후 이전 목록; ‘이 항목을 삭제했어요’. 복원 기능 없음.
7. **필요 데이터:** Action cascade, Reminder, Candidate, SuppressionHash(expires_at).
8. **예외 상황:** 저장 실패 시 항목 유지·실패 표시. 공유 원문/근거 중 다른 Action이 참조하는 내용은 그 Action 보관 정책 적용. 삭제 전 이 범위를 안내. 진행 중 AI 응답이 삭제 기록을 되살리지 않도록 hash/epoch 재검사.
9. **권한 조건:** 사용자 명시 확인. OS 권한 불필요.

### F15. 출처·근거 보기와 원래 앱 열기

1. **기능명:** AI 판단의 근거 확인.
2. **목적:** 잘못된 요약을 검증하고 필요한 제출을 원래 서비스에서 수행.
3. **사용자 행동:** S06/S08에서 근거 펼치기, ‘출처 앱 열기’.
4. **시스템 처리:** 구조화 근거 발췌 최대 300자·민감 패턴 마스킹. 유효한 원래 알림 PendingIntent가 있으면 사용자 탭으로만 실행; 없으면 검증된 package의 실행 화면 열기. 다른 임의 URL을 자동 실행하지 않음.
5. **입력값:** action/candidate id, open source click.
6. **출력값:** 원문 일부와 보관 기한 또는 ‘원문 발췌 보관 기간이 끝났어요’; 원래 앱 화면. 정확한 공지 화면 도착은 보장하지 않음.
7. **필요 데이터:** Source labels, Evidence(excerpt, captured_at, expires_at), 기기 내 임시 source intent handle.
8. **예외 상황:** 앱 미설치/intent 만료→설치 앱 열기 시도, 둘 다 실패하면 앱 이름과 ‘직접 열어 확인해주세요’. 전송·제출·결제 완료 여부는 외부 앱에서 자동 감지하지 않음.
9. **권한 조건:** 명시적 사용자 탭. 외부 앱 로그인/결제는 해당 앱이 처리. 별도 접근성 권한 사용 금지.

### F16. 리마인더 생성·발송·복원

1. **기능명:** 필요한 시점 알림.
2. **목적:** 정보를 다시 찾아보지 않아도 행동 시점을 알림.
3. **사용자 행동:** 알림 탭→단일 항목 S06, 여러 항목 S05, 변경/확인 S08.
4. **시스템 처리:** A4 일정표와 R 적용. 동일 묶음 키는 한 번 발송. OS 예약 호출 성공은 ‘전달됨/읽음’이 아니라 `POST_ATTEMPTED`로 기록. 앱 복귀·재부팅 후 다음 실행 가능 시 DB로 재계산.
5. **입력값:** Action version/status/due, Candidate, local clock, R, due reminder IDs.
6. **출력값:** 일반 하루 최대 2개 묶음, 필요 시 한 번의 변경 안내·사용자 지정 snooze. 잠금 화면에는 아이 이름/학교/준비물 대신 ‘챙길 일이 있어요’.
7. **필요 데이터:** Reminder(id, entity_id, entity_version, scheduled_at, bucket_key, state, attempted_at), Outbox.
8. **예외 상황:** OFF/완료/삭제/hold인 항목은 직전 재검사 후 제외. 지연 실행 시 A4 따라 유효 항목만 다음 묶음, 마감 지난 알림을 ‘곧 마감’으로 발송하지 않음. 테스트 기기에서 실제 도착과 시각을 별도로 검증.
9. **권한 조건:** R. 정확 알람 특별 권한 없이 구현하며 절전·강제종료 지연을 제품에서 인정.

### F17. 도움 평가·베타 지표

1. **기능명:** Saved Mom Moment 기록.
2. **목적:** 실제 수고/누락 감소를 측정.
3. **사용자 행동:** S06 하단 ‘이 알림이 없었다면 놓치거나 다시 찾아봤을까요?’에 ‘도움 됐어요’/‘아니요’; 변경 가능.
4. **시스템 처리:** 항목당 현재 응답 1개 유지. yes 최초 전환 시만 해당 Action의 사건 기록, no로 바꾸면 집계에서 제외. 응답 팝업 강제 없음.
5. **입력값:** action_id, yes/no, 응답 시각.
6. **출력값:** 선택 상태·짧은 감사 문구. 수신 알림/완료를 자동으로 도움 인정으로 세지 않음.
7. **필요 데이터:** MomentFeedback, 선택 동의 시 가명 실험 ID·행동 코드·시각·무작위 Action event key. 원문·이름·기관·날짜 내용은 분석 서버에 미전송.
8. **예외 상황:** 오프라인이면 선택 동의 범위의 이벤트만 최대 7일 큐. 측정 미동의 사용자는 로컬 응답만 저장. 베타 KPI는 별도 연구 동의한 모집 코호트로 측정하고 동의 철회/측정 누락 수를 보고.
9. **권한 조건:** 로컬 응답은 서비스 이용자, 외부 지표 전송은 별도 선택 동의. 미동의로 기능 제한 없음.

### F18. Memory 일시정지·원문 보관·동의 철회

1. **기능명:** 데이터와 수집 통제.
2. **목적:** 서비스가 기억하는 범위를 사용자가 제어.
3. **사용자 행동:** S12 Memory ON/OFF, 원문 24시간 보관 OFF/ON, 선택 측정 철회, 필수 동의 철회.
4. **시스템 처리:** Memory OFF→수집·추출·모든 발송 중단, 미처리 원문 삭제, 기존 Action/후보는 보관·조회 가능. ON→그 시점 이후 수집·미래 예약만 재개. 원문 보관 OFF 전환→보관 원문 즉시 제거. 필수 동의 철회→F19 전체 초기화와 서버 삭제 절차.
5. **입력값:** memory_enabled, keep_raw_24h, metrics_consent, withdraw consent.
6. **출력값:** 멈춤 배너·각 옵션 효과·삭제 진행. 단순 Memory OFF는 기존 기억 삭제가 아님을 토글 주변에 표시.
7. **필요 데이터:** Preferences, Consent, epochs, RawEnvelope, Reminder, 선택 지표 deletion job.
8. **예외 상황:** 원문 보관 ON은 이후 알림부터 적용, 과거 원문 복구 안 함. 중지 중 완료·수정·삭제 가능. 재개해도 중지 기간 알림 소급 처리 없음.
9. **권한 조건:** 로컬 본인. 필수 동의 철회/전체 초기화는 범위 확인 후 실행, 선택 동의 철회는 서비스 지속.

### F19. 아이 삭제·전체 초기화·설치 폐기

1. **기능명:** 삭제 생명주기.
2. **목적:** 개인정보를 지우고 수집/추출이 되살아나지 않도록 함.
3. **사용자 행동:** S11 아이 삭제 또는 S12 전체 데이터 삭제→S14 범위 읽기·확인.
4. **시스템 처리:** 먼저 수집 중지·epoch 증가·설치 토큰 폐기 요청 생성. 아이 삭제는 아이/Source/선택 초안/Action/후보/원문/예약/관련 평가 삭제 후 S03부터 재설정, 필수 동의 유지. 전체 초기화는 동의·설정·가명 측정 데이터 포함 삭제 후 S01. 설치 토큰은 아이 삭제 후에도 폐기하고 새 설정 때 새 키 발급.
5. **입력값:** scope(CHILD/ALL), confirmation, deletion_request_id.
6. **출력값:** ‘이 기기 삭제 완료’와 ‘서버 설치 접근 폐기 확인’ 상태 분리. 자격증명이 유효한 정상 경로는 폐기/선택 지표 삭제 요청 확인 전 새 설정 차단; 원격 요청만 남으면 상태 화면과 재시도 제공. 토큰 폐기 성공은 공급자 메모리까지 즉시 삭제됐다는 뜻이 아니므로 추출 처리 잔여 한도 최대 5분과 실제 공급자 정책을 별도 표시한다.
7. **필요 데이터:** DeletionJob(scope, local_state, remote_state, request_id), 폐기용 단기 credential. 삭제 대기함에는 이름·원문·Action 내용 없음.
8. **예외 상황:** 네트워크 없음→로컬 삭제 먼저, 서버 폐기는 다음 연결 시 재시도. 서버 요청 재실행 멱등. 전체 삭제는 suppression hash도 삭제, 이후 새 동의 뒤 새로 온 동일 내용은 재생성될 수 있음. 앱 제거만으로 원격 삭제 요청 성공을 보장하지 않음(A6). 키 손실 또는 복구 불가능한 설치 proof 오류는 remote_state=UNVERIFIABLE로 구분한다. S14에서 원격 즉시 폐기 미확인·토큰 최대24시간/인증 레코드 마지막 사용+30일/선택 가명 이벤트90일 만료를 알리고 ‘이 기기를 초기화하고 새로 시작’으로 예외 재설정을 허용한다. 원격 삭제 완료로 표시하지 않는다. 단순 네트워크 오류는 이 예외에 해당하지 않는다.
9. **권한 조건:** 본인 설치 인증으로 그 설치만 폐기. 계정이 없으므로 ‘회원 탈퇴’ 버튼은 제공하지 않음. 다른 설치 조회/삭제 금지.

### F20. 추출 실패·재시도·운영 상태

1. **기능명:** 자동 처리 장애 복구.
2. **목적:** 자동 처리 중단을 숨기지 않고 복구.
3. **사용자 행동:** S05 배너→S10 상태 확인, ‘다시 시도’ 또는 권한 설정.
4. **시스템 처리:** 30초 요청 timeout. 네트워크/429/5xx는 1분·5분·30분·2시간 간격 최대 4회 추가 시도, Retry-After가 더 길면 준수하되 24시간 TTL 초과 금지. schema 오류는 1회만 재시도. 401은 F01 갱신 한 번. 미처리 내용 삭제 이후 재시도는 비활성화.
5. **입력값:** job id, retry click, network state, error code.
6. **출력값:** ‘분석 대기 N건’, ‘자동 처리가 지연돼요’, ‘본문을 보관하지 않아 다시 분석할 수 없어요’ 등 상태와 원래 앱 확인 경로.
7. **필요 데이터:** ProcessingJob(status, attempt_count, next_retry_at, expires_at, error_code), Source 상태 카운터.
8. **예외 상황:** 재시도 연타→진행 작업 1개. 로컬 용량 부족→저장 실패·수집 중단·해결 후 재개, 실패를 성공으로 표시하지 않음. 서버 장애 중 기존 알림 예약은 로컬에서 계속.
9. **권한 조건:** 전송은 C와 유효 토큰, 상태 열람은 로컬. 앱 원문을 운영 로그에 남겨 디버깅하지 않음.

## A3. 날짜·대상·변경 확정 규칙

| 입력/상황 | 결정 |
|---|---|
| ‘내일/모레’ | 수신 처리 시간이 아닌 원래 posted_at의 서울 날짜 +1/+2 |
| ‘이번 주 금요일’ | 월요일 시작 주의 금요일. 이미 지난 날이면 다음 주로 밀지 않고 확인 후보 |
| ‘다음 주 화요일’ | posted_at이 속한 월요일 +7일+1일 |
| ‘오는 금요일’ | 다음 도래 금요일 후보; 게시일이 금요일이거나 문맥 충돌이면 확인 |
| 연도 없는 ‘9월 18일’ | 게시 연도의 날짜가 게시일~180일 후 안이면 후보 확정 가능. 그 외 연말 이월 등은 확인; 연도를 추측해 자동 등록하지 않음 |
| 명시적 과거 날짜 | 변경의 이전 날짜 참조로 사용 가능. 신규 행동의 마감이면 확인 후 과거 저장 |
| 시각 없음 | DATE 유지. ‘오후 6시’→18:00; 오전/오후 없는 6시 등 애매한 시각은 확인 |
| 날짜 없음 | 날짜 미정 Action으로 자동 확정하지 않음. 사용자 확인 후 미정 저장은 가능, 자동 시간 알림 없음 |
| 주말/공휴일 | 사용자가 받은 날짜 그대로. 공휴일이라는 이유로 다음 영업일로 이동하지 않음. ‘다음 영업일’은 확인 필요; 휴일 API는 V0 제외 |
| ‘매주/격주’ | 반복 일정 자동 생성 안 함. 명시된 이번 회차 날짜만 확정, 회차 불명확은 확인 |
| 아이 이름/기관/학년 불일치 또는 근거 없음 | Source가 연결됐거나 이름만 입력됐다는 이유로 등록 아이에게 확정 금지. 관련 없음 또는 해당 후보 사용자 확인. 선택 프로필 누락은 null이며 모델 점수로 대체하지 않음 |
| 동일 알림에 원 일정과 새 일정 | change payload로 분리, 새 날짜만 단독 Action으로 중복 생성하지 않음 |

confidence 경계: 0.80 포함 자동 후보, 0.60 포함 확인 후보. 자동 후보라도 날짜·대상·근거 중 하나라도 검증 실패면 확인 상태가 우선한다. 원문에 없는 필드는 null이다.

## A4. 알림 규칙과 상태 전이

### 기본 일정표 — 모두 Asia/Seoul

| 종류 | 기본 예정 시각 |
|---|---|
| PREPARE | 날짜 D-1 20:00, D 07:00 |
| TODO(납부 포함) | D-1 20:00, D 07:00 |
| EVENT | D-1 20:00, D 07:00 |
| 확정 못 한 후보 | 다음 07:00/20:00 일반 묶음에 최초 1회, 이후 홈 확인함에만 유지 |
| 변경/취소 후보 | 07:00~21:00 수신은 5분 묶음 후 1회. 그 외 다음 07:00. 생명·안전 긴급 알림 서비스 아님 |
| 사용자 미루기 | 사용자가 지정한 시각 1회; 기본 묶음과 5분 이내 겹치면 하나로 합침 |

- 일반 묶음은 같은 슬롯의 모든 유효 항목을 한 알림으로 발송한다. 두 후보 알림이 같은 묶음에 들어가면 중복 발송 금지. 변경과 일반 슬롯이 5분 이내 겹쳐도 하나로 합친다.
- D-3 알림은 V0에서 제거한다. 기본 알림 개인화는 없으며 미루기만 제공한다.
- 생성/변경 시점보다 과거인 예약은 생성하지 않는다. 아직 마감 전인 당일 신규 행동은 다음 일반 슬롯이 마감 전일 때 그 슬롯에 포함; 남은 슬롯이 없으면 07~21시 내 5분 묶음으로 최초 1회 알린다. 이는 ‘마감 임박’ 예외 알림이며 일반 2회와 별도 집계한다.
- 명시 마감 시각 이후의 예약은 취소한다. DATE만 있으면 그날 23:59:59까지 유효하되 마감 시각처럼 사용자에게 표기하지 않는다. EVENT도 시작 후 ‘예정’ 푸시를 보내지 않는다.
- 미루기를 마감 뒤로 명시 확정한 경우만 기한 지난 상태로 1회 알린다. 일반 overdue 반복 푸시는 없다.
- 앱/기기 재시작 후 누락 슬롯은 연달아 재발송하지 않는다. 여전히 유효한 항목만 다음 슬롯/당일 임박 예외에 합친다. 변경 미확인은 다음 슬롯에 최초 안내가 아직 없을 때만 포함.
- snooze 만료 시각은 상태 판단 기준이며 발송 여부에 종속되지 않는다. 만료된 SNOOZED는 OPEN으로 정리한다. 15분을 넘긴 과거 snooze는 SKIPPED, 미래 기본 예약만 복원한다. 일반 지연 알림 규칙으로 과거 snooze를 다시 발송하지 않는다.
- Memory OFF는 모든 예약 중단. ON은 미래만 복원. Source OFF는 기존 확정 기록의 예약 유지. 완료·삭제·취소는 해당 예약 제거.
- `bucket_key = installation + 서울 날짜/슬롯 + channel`, `reminder_key = entity_id + version + rule + scheduled_at`를 unique 처리. 실제 전송 직전 Action 버전/상태 및 R 재검증.

## A5. 화면 목록 선택·정렬 규칙

- S05 상단 순서: 작동 중단/장애 배너 → 확인 필요 N건 → 오늘 챙길 것 → 앞으로 7일 → 날짜 미정 → 기억 목록.
- 오늘: OPEN/SNOOZED 중 기한 지남, 오늘 예정/마감, 내일 준비(PREPARE), 오늘 알림 대상, 변경 확인 중 Action. 같은 Action은 한 번만 표시한다.
- 정렬: 기한 지남→오늘 마감/일정(시각 오름차순, 시각 미상은 그날 마지막)→내일 준비→나머지. 동률은 created_at 오름차순.
- ‘앞으로 7일’은 내일~오늘+7일, 오늘 영역에 나온 Action 제외. 그 이후는 S09에만 표시.
- 설정 관련 홈 안내는 한 번에 하나만 펼친다. 우선순위는 동의/삭제 차단→사용자가 선택한 자동 챙김 일시정지→앱 선택→아이 이름→읽기 권한→연결 장애→자체 알림 받기→기타 분석 지연. CTA는 해당 단계로 바로 이동하고 성공 후 다음 미완료 단계로 이어진다. 일시정지는 오류로 취급하거나 자동 해제하지 않는다. 전체 상태는 S10에서 열람 가능하며, 기록과 확인 후보는 배너 아래 계속 보인다.
- 읽기 허용 후 아직 실제 공지가 없으면 ‘설정됐어요. 새 알림이 오면 챙길게요’로 표시. 자체 알림 미허용은 ‘현재 앱 안에서만 확인할 수 있어요’ 보조 문구. 발송 권한을 먼저 켜려면 이 문구의 ‘알림 받기’로 직접 진입할 수 있다. 데모를 실제 결과로 간주해 자동 권한 안내를 띄우지 않음.
- 날짜 미정 OPEN/SNOOZED는 독립 영역, 자동 시간 알림 없음. DONE/CANCELLED는 S09 완료·취소 필터에서만 보임.
- 오늘 0건이지만 미래/확인 후보가 있으면 ‘오늘 확정된 할 일은 없어요’로 표현. ‘모든 공지를 확인했어요’라고 하지 않는다.
- 홈 문구는 실제 상태 기반: ‘오늘 챙길 것 N개’, ‘확인이 필요한 알림 N개’. 예시 데이터는 ‘예시’ 라벨과 별도 메모리 화면만 사용, 실제 건수/지표 제외.

- 추출 서버는 요청 본문/응답을 DB·캐시·일반 로그에 저장하지 않는 동기 API로 설계한다. 작업 메모리/timeout 한도 최대 5분. 공급자의 별도 저장·학습 여부는 배포 전 실제 계약·설정으로 검증해야 한다. ‘공급자도 즉시 삭제’를 확인 없이 주장하지 않는다.

## C. MOM PROBE 전용 추가 기능 — G0 빌드에서만 사용

V0 화면에 디버그 뷰어·내보내기 메뉴를 노출하지 않는다. G0는 F02~F06, F18~F20 중 로컬 수집·삭제 부분을 재사용하고, F07~F17 AI/Action 기능은 실행하지 않는다. P01/P02는 연구 도구 별도 화면이다.

G0는 서버 설치 등록·AI·외부 사용성 이벤트 전송을 하지 않는 로컬 전용 빌드다. F01/F19/S14를 재사용할 때 원격 폐기 단계는 `NOT_APPLICABLE`로 생략하며 로컬 삭제 성공 즉시 초기 화면으로 이동한다. 연구 동의·14일 보관·반출 동의가 소비자 V0의 AI 동의·24시간 원문 규칙보다 우선하는 명시적 빌드 변형이다.

### P01. 수집 상태·원문 검토

1. **기능명:** MOM PROBE 수집 뷰어.
2. **목적:** 앱/기기별 실제 본문 노출과 중복 확인.
3. **사용자 행동:** SP01에서 앱별 수신 건수/상태, 개별 알림 필드 확인·개별 삭제.
4. **시스템 처리:** 동의한 앱 알림만 로컬 저장. 원문 자동 TTL 수집+14일; 참가자 테스트 종료/삭제 시 더 빨리 제거. Source OFF는 신규 수집 중단 및 대기 데이터 폐기, 이미 연구 저장된 원문은 사용자가 삭제하거나 TTL까지 보관한다는 연구 전용 문구 표시.
5. **입력값:** Canonical 필드 전체, 앱 필터, 선택 record id.
6. **출력값:** 수집/빈 본문/중복 revision 건수, 상세 필드. AI 정확도 지표는 표시 안 함.
7. **필요 데이터:** ProbeRecord, ParticipantConsent, 무작위 연구 device alias; 실제 영구 기기 식별자 미수집.
8. **예외 상황:** 권한 철회/용량 부족/앱 재시작 상태를 기록·표시. 수집 0건과 연결 실패 구분. 개별 삭제 확인 후 영구 제거.
9. **권한 조건:** 별도 연구 동의와 읽기 접근. 자체 알림 보내기 권한은 필수 아님. V0의 AI 전송 동의는 G0에서 요청하지 않음.

### P02. 연구 데이터 검토·내보내기

1. **기능명:** 가명 처리 JSON/CSV 내보내기.
2. **목적:** 수집 가능성과 오프라인 추출을 평가할 자료 확보.
3. **사용자 행동:** SP02 기간/앱 선택→로컬 자동 마스킹→미리보기에서 텍스트 추가 가림/행 제외→별도 외부 반출 동의→파일 저장 또는 시스템 공유.
4. **시스템 처리:** JSON 배열/UTF-8 CSV 동일 레코드, 이름·전화·연락처·계좌 등 탐지 마스킹, 기관·아이 별칭 유지. 자동 처리만으로 익명화 완료라고 표시하지 않음. 사용자/연구 담당자가 남은 재식별 가능 내용을 검토한 파일만 평가 입력.
5. **입력값:** date range, source ids, selected fields, redaction edits, export consent, format(JSON/CSV).
6. **출력값:** 미리보기·레코드 수·‘가명 처리된 연구자료’ 경고·사용자 선택 위치의 파일. CSV는 =,+,-,@로 시작하는 문자열을 안전한 텍스트로 내보내기.
7. **필요 데이터:** ProbeRecord, 별칭 매핑(기기 내), export manifest(수량·기간·스키마·동의 버전), export audit(내용 제외).
8. **예외 상황:** 빈 범위→버튼 비활성화; 취소→임시파일 즉시 삭제; 저장 실패→원본 유지. 성공 후 앱 임시파일 1시간 TTL. 외부 저장 사본은 앱 전체 삭제로 회수 못 하므로 저장 전 고지, 연구 담당 사본은 평가 종료 후 30일 내 삭제하는 운영 조건.
9. **권한 조건:** 수집 동의와 별도 반출 동의 모두 필수. 자동 이메일·클라우드 업로드 없음. 파일 위치/공유 대상은 사용자가 OS UI에서 선택.

### P03. Android 앱 연결

1. **기능명:** 앱 스위치 연결·첫 수신 검증.
2. **기능 목적:** 엄마가 고른 설치 앱의 새 알림만 에이전트가 확인하도록 가장 짧게 설정.
3. **사용자가 하는 행동:** 연결 목록에서 앱 스위치 ON→이유 팝업 확인→Android 알림 접근 허용→필요하면 원 앱을 열어 로그인.
4. **시스템이 처리하는 내용:** 권한 전에는 선택을 확정하지 않는다. 복귀 후 실제 권한을 재조회하고 선택·수집 상태를 저장한다. 원 앱 로그인 여부를 읽지 않고 첫 새 알림 수신 때 ‘알림 연결 확인됨’으로 바꾼다.
5. **입력값:** package_id, switch_enabled, notification_listener_access.
6. **출력값:** OFF / 첫 알림 기다리는 중 / 알림 연결 확인됨, 원 앱 실행 결과.
7. **필요한 데이터:** 허용 package 집합 최대 2개, 최근 수신 package, 권한 상태, collection_enabled.
8. **예외 상황:** 권한 거부·설정 열기 실패는 OFF 유지. 앱 삭제는 선택 제거. 원 앱 실행 불가는 앱명과 직접 로그인 안내. 과거 알림으로 연결 성공을 만들지 않는다.
9. **권한 조건:** 앱 ON과 원문 저장에는 필수 동의·자녀·해당 package 선택·알림 접근이 모두 필요. 원 앱 열기 자체에는 추가 권한 없음.

### P04. 사이트 로그인 세션 연결

1. **기능명:** 공식 사이트 WebView 로그인·세션 유지.
2. **기능 목적:** 엄마가 한 번 직접 로그인한 뒤 사이트가 허용하는 기간 동안 다시 로그인하는 수고를 줄임.
3. **사용자가 하는 행동:** 사이트 스위치 ON→공식 화면에서 로그인→로그인 뒤 ‘로그인 유지 시작’. OFF면 해당 사이트 세션 해제.
4. **시스템이 처리하는 내용:** HTTPS 허용 도메인만 WebView 안에서 열고 쿠키·웹 저장소 세션을 유지한다. 비밀번호·OTP·인증서 필드를 앱 데이터로 읽거나 저장하지 않는다. 로그인 추정 후 SESSION_READY, 실제 읽기 어댑터의 시험 요청 성공 후 CONNECTED.
5. **입력값:** site_id, 현재 URL, 사이트 쿠키/웹 세션, 사용자 완료 선택.
6. **출력값:** CONNECTING / SESSION_READY / CONNECTED / REAUTH_REQUIRED / ERROR, 마지막 확인 시각.
7. **필요한 데이터:** 허용 호스트, 시작 URL, 세션 저장소, 암호화 연결 메타데이터. 계정 비밀번호 필드 없음.
8. **예외 상황:** HTTP·외부 도메인·혼합 콘텐츠 차단. 로그인 취소는 연결 제거. 세션 만료는 REAUTH_REQUIRED. CAPTCHA·2단계 인증은 사용자가 공식 화면에서 수행하며 자동 우회하지 않는다.
9. **권한 조건:** 필수 동의와 자녀 프로필. 개인자료 읽기는 제공자 약관·공식 위임 또는 별도 승인이 확인된 커넥터만 허용.

### P05. 학교 공식명 확인

1. **기능명:** 나이스 학교 검색·공식명 정규화.
2. **기능 목적:** 사용자가 학교명을 정확히 외워 입력하지 않아도 올바른 공개 학교정보와 연결.
3. **사용자가 하는 행동:** 학교 이름을 2자 이상 입력하고 나이스 학교정보 스위치를 ON.
4. **시스템이 처리하는 내용:** 나이스 공식 OpenAPI에서 검색한다. 정확 일치가 있으면 우선하고, 검색 결과가 하나뿐이면 그 공식 이름·주소·교육청·학교코드로 정규화한다.
5. **입력값:** 학교 검색어, 선택적 지역 힌트, 학년.
6. **출력값:** 공식 학교명·주소·학교급·교육청코드·학교코드 또는 후보 다수/없음 오류.
7. **필요한 데이터:** 자녀 프로필, NEIS schoolInfo 응답, 운영 API 키는 서버 보안 저장.
8. **예외 상황:** 후보 0개는 철자/지역 안내, 2개 이상은 지역명을 추가하도록 안내. 위치 기반 주변 학교는 별도 선택 권한과 후보 선택 UI 구현 전 자동 사용하지 않는다.
9. **권한 조건:** 공개 API 검색은 위치 권한 불필요. 주변 학교는 사용자가 기능을 눌렀을 때만 대략적 위치 권한을 요청하고 거부해도 수동 검색 유지.

### P06. 에이전트 브리핑·행동 알림

1. **기능명:** 중요도별 알림과 아침·저녁 브리핑.
2. **기능 목적:** 공지를 보여주는 데서 끝내지 않고 준비·구매·완료까지 그 자리에서 처리.
3. **사용자가 하는 행동:** heads-up 알림이나 브리핑에서 준비물 보기·가격 비교·30분 뒤·완료를 선택.
4. **시스템이 처리하는 내용:** 즉시 변경만 개별 알림으로 보내고 오늘 행동은 07:00/20:30 브리핑에 묶는다. ‘봤다’와 ‘완료’를 분리하고 미완료 항목은 홈에 유지한다.
5. **입력값:** Action, 중요도, 마감, 완료 상태, snooze 시각, 사용자의 알림 시간·공개 범위.
6. **출력값:** heads-up 또는 묶음 알림, 최신 Action 상세 딥링크, 멱등 완료/미루기 결과.
7. **필요한 데이터:** Action/Reminder/Outbox, notification_id, version, operation_id, 잠금화면 공개 설정.
8. **예외 상황:** 알림 권한 OFF면 앱 홈에만 유지. 오래된 알림 탭은 최신 상태를 표시. 완료·취소·변경 시 이전 예약을 모두 무효화. 일반 공지에 전체화면 Intent를 사용하지 않는다.
9. **권한 조건:** Android 알림 발송 권한. 전체화면 권한은 전화·알람 요건을 충족하는 별도 기능이 검증되기 전 요청하지 않는다.

## D. 수용 기준 연결

각 F/P 기능의 구현 완료는 `05-통합검수.md`의 해당 AC 항목을 충족하고 연결 화면·흐름이 존재할 때만 인정한다. 현재는 설계만 검수했으며 앱 테스트가 실행됐다는 뜻이 아니다.
