# 나는 엄마다 — Low-fidelity 텍스트 Wireframe

버전 1.2 · 2026-09-13 · 통합 연결 목록과 상황별 권한 요청 반영. 색상·폰트·일러스트·개발 코드 없는 정보 구조 설계.

후속 개발에서 G0 화면에 **클레이모피즘**을 적용했다. 이 문서는 정보 구조 기준으로 유지하며, 실제 색상·카드·버튼 기준은 [클레이 디자인 구현](../mom-agent/android/design/implementation.md)에 기록한다.

## 공통 배치 원칙

- `[]` 버튼/입력, `()` 라디오, `□` 체크박스, `>` 이동. 위에서 아래로 읽는 순서다.
- 기본 탭은 **오늘 / 기억 / 설정** 3개. 상세·편집·온보딩에서는 뒤로가기로 돌아오며 중복 하단 탐색을 제거한다.
- Header→상태 안내→주요 정보→입력→CTA→결과 순서. 삭제는 주 CTA 옆에 크게 놓지 않고 더보기/설정 아래에 배치한다.
- 로컬 조회에 네트워크 로딩을 걸지 않는다. 저장 중 CTA 중복 실행 금지. 오류는 문제가 생긴 영역 가까이에 표시한다.
- 텍스트 줄바꿈과 시스템 글자 크기를 수용한다. 아이 이름·제목을 잘라 핵심 의미를 숨기지 않는다. 읽기 순서는 화면 배치 순서와 같다.
- 아래 10개 항목은 모든 화면/시트에 명시했다. 입력이 없는 화면은 ‘없음’을 표시한다. 같은 화면의 Empty/Loading/Error는 주 콘텐츠 영역을 대체하며 Header와 탈출 경로는 유지한다.
- 첫 방문 표시 순서는 S01→S02→S10→S05다. S04는 앱 스위치를 처음 켤 때만 뜨는 팝업과 OS 화면이다. 한 화면에서 한 가지 결정을 우선하고 선택 정보·진단은 접는다.
- 사용자 문구에서 Source/Memory/리스너를 쓰지 않는다. 앱 아이콘+이름·큰 선택 행·문장형 안내·명확한 다음 버튼을 사용한다. OS 권한 화면과 복귀까지 실제 기기에서 사용성 검증한다.

## S01. 시작·동의

```text
┌────────────────────────────────┐
│ 나는 엄마다                     │ Header
│ 학교·학원 알림에서               │ Main
│ 준비물·마감·변경을 챙겨드려요.   │
│                                │
│ 이 기기에 도착한 알림만 읽어요. │
│ 자녀 1명 · 앱 2개 · 무료 베타   │
│ 재설치/기기 변경 시 복구 안 됨  │
│                                │
│ [수집·보관·삭제 설명 펼치기]     │
│ □ 필수: 개인정보 처리 동의     │ Input
│ □ 필수: AI 분석 전송 동의      │
│ [선택 설정 펼치기]             │ 선택 측정 기본 OFF
│ [이 기기에서 시작]              │ CTA
│ 저장 결과/오류                  │ Result
└────────────────────────────────┘
```

1. **화면 목적:** 서비스 범위와 데이터 처리를 이해하고 가입 없이 시작.
2. **Header:** 서비스명만.
3. **Navigation:** OS 뒤로→종료. 설명 펼침은 화면 내, 닫으면 원위치.
4. **Main Content:** 자동 수집 가치·지원 제한·복구 제한·무료 범위.
5. **Input:** 필수 동의 2개 기본 OFF. 선택 측정 동의는 ‘선택 설정’ 안에 접어두고 기본 OFF 유지.
6. **CTA:** ‘이 기기에서 시작’; 필수 미선택 비활성.
7. **Result 영역:** 동의 저장 후 S03 설치된 지원 앱 선택, 저장 실패는 버튼 아래.
8. **Empty State:** 최초 설명과 미선택 동의가 기본 상태.
9. **Loading State:** 동의 저장 중 ‘설정 중…’, 다시 누르기 차단.
10. **Error State:** 저장 실패·재시도. 설명 버전 검증 실패는 서비스 시작 불가 안내.

## S02. 아이 등록·편집 폼

```text
┌────────────────────────────────┐
│ < 자녀 정보                    │ Header / Navigation
│ 누구의 소식을 챙기면 될까요?   │ Main
│ [이름 또는 별칭____________]    │ Input
│ [학교 이름________________]     │ 짧게 입력 가능
│ [학년 선택________________]     │
│ 연결 때 공식 학교명으로 확인   │
│ [자녀 정보 저장]               │ CTA
│ 필드 오류 / 저장 결과          │ Result
└────────────────────────────────┘
```

1. **화면 목적:** 자녀 1명의 소식과 공개 학교정보를 정확히 연결.
2. **Header:** 최초·편집 모두 ‘자녀 정보’.
3. **Navigation:** 최초 뒤로 S01, 편집 뒤로 S12. 미저장 변경 폐기 확인.
4. **Main Content:** 이름·학교·학년이 필요한 이유와 기기 내 암호화 보관 안내.
5. **Input:** 이름/별칭 1~20자, 학교 검색어 2~60자, 초등 1~6학년. 생년월일·반·번호는 받지 않음.
6. **CTA:** ‘자녀 정보 저장’→S10, 편집은 저장→S12.
7. **Result 영역:** 나이스 검색 결과가 하나면 공식 학교명으로 정규화. 여러 곳이면 지역명을 추가하도록 안내.
8. **Empty State:** 이름과 ‘예: 성남정자초등학교’ placeholder. 실제 샘플값 자동 저장 안 함.
9. **Loading State:** 저장 중 CTA 잠금, 입력 내용 유지.
10. **Error State:** 공란·길이·학년 범위 오류는 필드 아래, 학교가 여러 곳이면 지역명 추가 안내, 저장 실패는 하단 재시도.

## S03. 이전 Source 선택 화면

```text
┌────────────────────────────────┐
│ S10 통합 연결 화면으로 이동     │
└────────────────────────────────┘
```

1. **화면 목적:** v1.2에서 S10 통합 연결 화면으로 흡수되어 신규 동선에서는 사용하지 않음.
2. **Header:** 없음.
3. **Navigation:** 모든 이전 S03 진입을 S10으로 리다이렉트.
4. **Main Content:** 없음.
5. **Input:** 없음.
6. **CTA:** 없음.
7. **Result 영역:** S10 표시.
8. **Empty State:** 없음.
9. **Loading State:** 없음.
10. **Error State:** S10 오류 정책 사용.

## S04. 앱 활성화 시 알림 접근 팝업

```text
┌────────────────────────────────┐
│ [앱 이름] 알림을 챙길까요?      │ Header
│ Android는 모든 알림 접근이라고 │ Main
│ 표시하지만 켠 앱만 저장해요.   │
│ [취소] [허용하러 가기]          │ CTA
├────────────────────────────────┤
│ 첫 실제 결과에서 별도 시트     │ 읽기 안내와 동시 노출 안 함
│ 이 내용을 필요한 때           │
│ 알려드릴까요?                  │
│ [알림 받기] [나중에]           │
└────────────────────────────────┘
```

1. **화면 목적:** 앱 스위치를 켠 맥락에서 필요한 권한 하나만 설명.
2. **Header:** ‘[앱 이름] 알림을 제가 챙길까요?’.
3. **Navigation:** 팝업 취소는 S10, OS 복귀 후 허용 성공은 앱 로그인 안내→S05, 거부는 S10.
4. **Main Content:** Android의 넓은 권한 문구와 실제 앱별 저장 제한을 한 문단으로 설명.
5. **Input:** OS 허용/거부. 앱이 대신 클릭하지 않음.
6. **CTA:** ‘허용하러 가기’, ‘취소’. 별도 온보딩 계속 버튼 없음.
7. **Result 영역:** 복귀 즉시 재검사. 성공하면 선택 저장, 실패하면 스위치 OFF 유지.
8. **Empty State:** 별도 화면이 아니므로 없음.
9. **Loading State:** OS 복귀 후 짧은 확인 중 상태만 표시.
10. **Error State:** 설정 열기 실패 시 일반 알림 접근 경로 안내. 거부를 오류처럼 반복 압박하지 않음.

## S05. 오늘 — 핵심 홈

```text
┌────────────────────────────────┐
│ 나는 엄마다           [연결 상태]│ Header
│ [설정 이어하기: 가장 필요한 1개]│ Result / recover
│ [확인 필요 2개 >]              │
│ 오늘 챙길 것 3개               │ Main
│ ┌ 체험학습 동의서             ┐│
│ │ 오늘까지 · 학교 앱       > ││
│ └────────────────────────────┘│
│ ┌ 내일 미술 준비             ┐│
│ │ 물감·붓·스케치북         > ││
│ └────────────────────────────┘│
│ 앞으로 7일                     │
│ 토요일 11시 수학 보강       >  │
│ 날짜 미정 1개               >  │
│                                │
│ [오늘]      [기억]      [설정] │ Navigation
└────────────────────────────────┘
```

1. **화면 목적:** 현재 행동과 확인이 필요한 것에 바로 도달.
2. **Header:** 서비스명·연결 상태 버튼.
3. **Navigation:** 오늘/기억/설정 탭; 카드 상세 S06, 확인함 S08.
4. **Main Content:** 가장 먼저 해결할 설정/장애 1개→확인함→오늘→앞으로 7일→날짜 미정. 우선순위와 정렬은 기능명세 A5. 해결하면 다음 필요한 안내로 바뀌며 여러 권한 배너를 쌓지 않음.
5. **Input:** 없음. 카드/날짜 미정 항목은 탭만.
6. **CTA:** 카드 보기, 확인 필요 해결, ‘이어서 설정하기’는 빠진 단계로 바로 이동. 첫 실제 결과에서는 S04 발송 시트 1회. 자체 알림 미허용 보조 문구의 ‘알림 받기’로 직접 허용도 가능. 새로운 할 일 추가 버튼 없음.
7. **Result 영역:** 실제 개수와 갱신된 카드. 완료 항목은 오늘에서 제거.
8. **Empty State:** 미연결=‘고른 앱을 챙기려면 설정을 이어주세요’; 첫 수신=‘설정됐어요. 새 알림이 오면 챙길게요’+인라인 예시 보기; 읽기 허용됐지만 연결 전이면 ‘연결 준비 중’; 실제 없음=‘오늘 확정된 할 일이 없어요’; 오늘 완료=‘오늘 챙길 일을 처리했어요’. 미래·미확인 건수는 계속 표시. 미허용 발송은 ‘현재 앱 안에서만 확인할 수 있어요’.
9. **Loading State:** 최초 로컬 조회만 자리 표시. AI 처리 대기는 기존 목록 위 ‘분석 대기 N건’.
10. **Error State:** 로컬 조회 실패 전체 재시도; AI/네트워크 실패는 기존 목록 유지+상태 배너.

## S06. Action 상세

```text
┌────────────────────────────────┐
│ < 챙길 일                 [⋯] │ Header
│ 체험학습 준비                  │ Main
│ 상태: 챙기는 중 / 사용자 수정  │
│ 날짜 9/18(금) · 시간 정보 없음  │
│ 준비물: 도시락 · 물 · 모자      │
│ 출처 학교 앱 · 9/13 수신       │
│ [근거 펼치기] [출처 앱 열기]    │
│ 다음 알림 9/17 20시            │
│                                │
│ [완료했어요]                   │ CTA
│ [나중에 알려줘] [수정]         │
│ [잘못된 정보예요]              │
│ 이 알림이 없었다면 놓치거나     │
│ 다시 찾아봤을까요?             │
│ [도움 됐어요] [아니요]         │ Input
│ 완료/저장/평가 결과            │ Result
└────────────────────────────────┘
```

1. **화면 목적:** 행동에 필요한 정보·근거 확인과 처리.
2. **Header:** 뒤로·화면명·더보기(삭제).
3. **Navigation:** 진입 목록 복귀; 원래 앱은 사용자 탭으로만 이동.
4. **Main Content:** 제목·상태·날짜/시각·items·장소(있을 때)·출처·근거·다음 알림. 변경 적용된 항목은 ‘변경 내역’ 펼침과 이전/이후. 휴강/보강은 연결 카드.
5. **Input:** 도움 평가 두 버튼; 직접 편집은 S07.
6. **CTA:** OPEN은 완료/미루기/수정. SNOOZED는 다음 알림 시각 아래 ‘미루기 취소’·‘시간 변경’과 완료/수정. EVENT는 ‘확인했어요’와 ‘일정을 확인한 것으로 기록해요’. DONE은 완료 취소. CANCELLED는 수정. 변경 hold는 ‘변경 먼저 확인’과 미루기 비활성화.
7. **Result 영역:** 상태 즉시 갱신·저장 결과·도움 응답 선택 표시.
8. **Empty State:** 항목 없음은 삭제/만료 안내 후 오늘로. 근거만 만료면 나머지 상세 유지.
9. **Loading State:** 로컬 상세 조회, 액션 저장 중 해당 버튼 잠금.
10. **Error State:** 저장 실패는 기존 상태 유지·재시도. 출처 열기 실패는 앱명과 직접 확인 안내.

## S07. 수정·오류 신고 폼

```text
┌────────────────────────────────┐
│ < 정보 수정                    │
│ 무엇이 잘못됐나요? (선택)      │
│ [날짜] [아이] [행동 아님]       │
│ [이미 완료] [기타]             │
│ [제목____________________]    │
│ [종류: 준비/할 일/일정    v]   │
│ [날짜____] □ 날짜 미정         │
│ [시간____] □ 시간 모름         │
│ [준비물 행____] [+] [행 제거]  │
│ [장소(선택)_______________]   │
│ □ 다시 챙기기 (종료 상태만)    │
│ [저장]                        │
│ 필드 오류 / 변경 충돌          │
└────────────────────────────────┘
```

1. **화면 목적:** 추출 오류 수정 또는 후보 확인 후 저장.
2. **Header:** Action ‘정보 수정’, Candidate ‘확인 후 저장’.
3. **Navigation:** 뒤로 호출 화면, 미저장 변경 폐기 확인.
4. **Main Content:** 추출된 필드와 사용자 수정 설명. 아이 오류는 등록 아이에 억지로 다시 연결하지 않음.
5. **Input:** 제목·종류·날짜/미정·시각/모름·items·장소·오류유형. 필드 제한 F13.
6. **CTA:** 저장. 아이 틀림/행동 아님은 삭제 확인 S14, 이미 완료는 F11. 후보의 관련 없음은 후보 종료.
7. **Result 영역:** 검증·변경 충돌·성공 후 S06.
8. **Empty State:** 모르는 값은 공란/null, 빈 폼으로 새 Action을 생성하는 진입 경로 없음.
9. **Loading State:** 저장 중 입력 유지·중복 제출 차단.
10. **Error State:** 필드 오류 바로 아래; 새 버전 충돌은 최신값 재검토 안내; DB 실패는 재시도.

## S08. 확인함·후보 상세·변경 비교

```text
┌────────────────────────────────┐
│ < 확인이 필요한 알림 (2)       │
│ [날짜 확인: 동의서 제출   >]   │ 목록
│ [변경 확인: 수학 수업     >]   │
├────────────────────────────────┤
│ < 변경 확인                    │ 상세 변형
│ 어떤 일정인가요? [대상 선택 v]│ 여러 대상일 때만
│ 기존: 목요일 18시 수업         │
│ 새 공지: 목요일 휴강           │
│          토요일 11시 보강      │
│ 출처/수신 시각/근거            │
│ 확인 전 기존 반복 알림은 멈춤  │
│ [변경 적용] [기존 유지]        │
│ [출처 앱 열기]                 │
│ 처리 결과 / 다음 확인 항목     │
└────────────────────────────────┘
```

1. **화면 목적:** 불확실한 정보와 변경을 한곳에서 해결.
2. **Header:** 목록은 건수, 상세는 날짜/아이/변경/원문 확인 사유.
3. **Navigation:** 목록 뒤로 S05, 상세 뒤로 확인 목록. 딥링크 상세 뒤로도 목록.
4. **Main Content:** 목록 카드; 상세 근거·불확실한 필드. 변경은 기존/새 값, 취소 결과, hold 설명. 내용 부족은 ‘내용이 없어 판단할 수 없어요’.
5. **Input:** 맞음/관련 없음, 필요할 때 기존 대상 선택; 필드 수정은 S07. 내용 부족에는 날짜 추측값을 표시하지 않음.
6. **CTA:** 일반 ‘맞아요/수정 후 저장/무시’; 변경 ‘변경 적용/기존 유지’; 대상 없는 새 일정 ‘새 일정으로 저장’; 내용 부족 ‘출처 앱 열기/확인했어요’.
7. **Result 영역:** 확정 후 S06, 무시는 다음 후보, 모두 해결하면 빈 상태. 대상 DONE이면 재개 여부 확인 체크 기본 OFF.
8. **Empty State:** ‘확인이 필요한 알림이 없어요’와 오늘로. 만료 후보 딥링크는 만료 안내.
9. **Loading State:** 로컬 후보 조회/적용 중, 대상별 변경 동시 저장 중 중복 클릭 차단.
10. **Error State:** 최신 Action과 충돌 시 재검토, 만료/Source OFF로 사라진 후보는 해결된 척하지 않고 없음 안내.

## S10. 연결 앱·작동 상태

```text
┌────────────────────────────────┐
│ < 연결                         │
│ 제가 확인할 곳을 골라주세요.   │
│ 켜둔 곳만 확인해요.            │
│ 앱                            │
│ e알리미      첫 알림 대기 [ON] │
│ 하이클래스              [OFF] │
│ 사이트                        │
│ 나이스 학교정보  학교 일정[ON] │
│ 나이스 개인자료  준비 중 [---] │
│ e알리미 웹      로그인 연결[ON]│
│ 하이클래스 웹    로그인 연결[OFF]│
│ 공식 화면 로그인·세션 유지 안내│
└────────────────────────────────┘
```

1. **화면 목적:** 앱과 사이트를 한 목록에서 켜고 연결 상태를 즉시 이해.
2. **Header:** ‘연결’과 ‘제가 확인할 곳을 골라주세요’.
3. **Navigation:** 최초 S02에서 진입하고 연결 하나가 준비되면 S05로 자동 이동. 설정에서는 뒤로 S12.
4. **Main Content:** 앱/사이트 두 섹션의 아이콘·이름·짧은 상태·스위치. 가져온 정보는 이 화면에 표시하지 않음.
5. **Input:** 앱 최대 2개, 사이트 스위치. 앱 첫 ON은 S04, 사이트 첫 ON은 공식 로그인 WebView. OFF는 해당 수집/세션만 해제.
6. **CTA:** 행의 스위치만 사용. ‘연결 설정 계속’과 별도 저장 버튼 없음.
7. **Result 영역:** 앱은 ‘첫 알림 기다리는 중/알림 연결 확인됨’, 사이트는 ‘로그인 중/로그인 유지됨·정보 확인 준비/정보 확인됨/다시 로그인 필요’.
8. **Empty State:** 설치된 지원 앱이 없으면 앱 섹션 한 줄 안내. 사이트 목록은 유지.
9. **Loading State:** 해당 행만 잠그고 상태를 ‘연결 중’으로 바꿈.
10. **Error State:** 권한·로그인 취소는 OFF 복원. 세션 만료는 REAUTH_REQUIRED, 정보 읽기 실패는 ERROR로 구분.

## S14. 삭제 확인·진행·부분 실패

```text
┌────────────────────────────────┐
│ < 삭제 범위를 확인해주세요     │
│ 대상: [항목 / 아이 / 전체]     │
│ 지워지는 정보:                 │
│ 기억 · 관련 근거 · 예약 알림   │
│ 전체면 아이·앱·동의도 포함     │
│ 이 작업은 되돌릴 수 없어요.    │
│ [취소]          [삭제]         │
├────────────────────────────────┤
│ 이 기기 삭제: 완료             │ Result 변형
│ 서버 설치 접근 폐기: 연결 대기 │
│ [다시 시도] [닫기]             │
│ 완료되면 처음 설정으로 이동    │
└────────────────────────────────┘
```

1. **화면 목적:** 정확한 삭제 범위 확인과 완료/실패 표시.
2. **Header:** 대상별 ‘항목 삭제/아이 삭제/전체 데이터 삭제’.
3. **Navigation:** 실행 전 취소는 호출 화면. 실행 후 닫기는 앱 종료/삭제 상태 유지이며 새 설정은 원격 완료 후. 키 손실/영구 인증 실패 예외는 미확인 안내 후 로컬 새 시작을 허용한다. 연구 빌드는 원격 단계가 없다.
4. **Main Content:** 항목은 관련 내용·예약과 공유 근거 제한; 아이는 Source 포함 관련 전체; 전체는 설정·동의 포함. Probe 외부 내보내기 사본은 회수 불가 문구.
5. **Input:** 명시적 삭제 확인 클릭. 불필요한 비밀번호 입력 없음.
6. **CTA:** 취소/삭제, 실패 시 재시도, 성공 시 해당 다음 화면으로 이동.
7. **Result 영역:** 로컬 삭제와 서버 설치 접근 폐기/지표 삭제 요청 확인을 구분. 접근 폐기는 공급자 처리 데이터 즉시 삭제와 다르며 최대 처리 시간/고지 정책을 별도 표시. 항목 삭제·연구 빌드는 원격 폐기 단계 없음.
8. **Empty State:** 이미 삭제된 대상이면 ‘이미 삭제된 항목’ 후 이전 목록.
9. **Loading State:** ‘수집 중단 중→이 기기 삭제 중→서버 확인 중’, 진행 중 중복 실행 차단.
10. **Error State:** 로컬 실패는 완료라고 표시 안 함. 원격 대기는 로컬 삭제 완료 표시+네트워크 재시도. 키 손실/영구 인증 실패는 ‘원격 즉시 폐기를 확인할 수 없어요’·토큰24시간/인증 레코드30일/선택 이벤트90일 자동 만료 안내와 ‘이 기기를 초기화하고 새로 시작’. 이 예외를 원격 삭제 완료로 표시하지 않는다.

```text
│ 반출 수량 / 저장 결과          │
└────────────────────────────────┘
```

1. **화면 목적:** 외부 평가용 자료에서 식별 정보를 검토하고 명시 반출.
2. **Header:** ‘연구자료 내보내기’.
3. **Navigation:** 뒤로 SP01, OS 파일/공유 UI 후 복귀.
4. **Main Content:** 앱·기간·레코드 수·가림 미리보기·외부 사본 삭제 한계.
5. **Input:** 기간/앱/필드/형식, 추가 가림 선택·행 제외, 반출 동의 기본 OFF.
6. **CTA:** 미리보기 준비 후 ‘파일 저장/공유’. 0건/미동의 비활성.
7. **Result 영역:** 생성 수량·OS 저장/공유 호출 결과. 공유 UI를 열었다는 이유만으로 수신자 전달 성공 주장 안 함.
8. **Empty State:** 선택 범위 데이터 없음, 기간/앱 바꾸기.
9. **Loading State:** 로컬 가림 처리·파일 생성 진행, 취소 가능.
10. **Error State:** 파일 생성/저장 실패 재시도, 취소 시 임시파일 제거·원본 유지.

## OS 소유 화면의 처리

알림 접근 설정, 알림 발송 허용 다이얼로그, 출처 앱, 파일 저장/공유 화면은 OS/외부 앱 소유다. 레이아웃을 새로 설계하지 않는다. 우리 앱에는 진입 이유·복귀 처리·취소·거부·호출 실패 상태만 구현한다. 사용자 외부 제출/결제 성공을 관측한 것처럼 UI를 바꾸지 않는다.

## 와이어프레임 검수 범위

이 산출물은 텍스트 배치와 상태/동선 검수다. 기준 이미지·구현 스크린샷이 없으므로 픽셀 유사도 점수나 시각 구현 통과 판정을 만들지 않았다. 실제 UI 제작 후 별도 글자 크기·터치 영역·스크린리더·OS별 화면 QA가 필요하다.
