# 나는 엄마다 — 전체 User Flow

버전 1.2 · 2026-09-13 · 스위치 중심 연결과 상황별 권한 요청 반영. 화면 ID는 Wireframe과 동일하다.

## 전체 구조

```text
첫 실행 S01 시작·동의 → S02 자녀·학교 → S10 앱·사이트 연결
   ├─앱 ON→ S04 권한 이유 팝업 → OS 알림 접근 → 복귀 → 원 앱 로그인 안내 → S05
   ├─사이트 ON→ 공식 로그인 화면 → SESSION_READY → S05
   ├─나이스 학교정보 ON→ 공식 학교명 확인·공개 API 검증 → CONNECTED → S05
   └─권한/로그인 취소→ 스위치 OFF 유지 → S10
   └─거부→ 시작 유지/종료

새 알림 → 허용 검사 → 자동 분석 → 확정 → S05 오늘 → S06 상세
                            ├─불확실→ S08 확인함 ─확인/수정→ S06
                            ├─변경→ S08 전후 비교 ─적용→ S06
                            ├─참고/광고→ 노출 없음
                            └─실패→ S05 상태 배너 → S10 연결·복구

S06 → 완료 / S13 미루기 / S07 수정 / S14 삭제 / 원래 앱
S05 ↔ S09 기억 목록 ↔ S12 설정·데이터
S12 → S10 연결 / S11 아이 / S14 전체 삭제

재방문 → 상태 복원 → S05
알림 탭 → 단일 S06 / 묶음 S05 / 확인 S08
```

아래 표의 한 행은 **화면 → 사용자 행동 → 시스템 반응 → 다음 화면**이다. 자동 처리도 사용자의 추가 행동이 없음을 명시했다.

## U01. 첫 진입과 로그인 분기 — F01/F02/F03/F04/F05

| 화면 | 사용자 행동 | 시스템 반응 | 다음 화면 |
|---|---|---|---|
| 실행 진입 | 앱 실행 | 설치 상태 없음 확인. 로그인 여부를 묻지 않음 | S01 |
| S01 시작·동의 | 필수 동의 후 ‘이 기기에서 시작’ | 동의 저장·설치 키 생성 | S02 |
| S01 | 동의하지 않거나 뒤로 | 수집·AI 전송·추적 시작하지 않음 | S01/종료 |
| S02 자녀 | 이름/별칭·학교 이름·학년 입력 후 ‘저장’ | 자녀 프로필을 기기에 암호화 저장 | S10 |
| S02 | 학교명을 짧게 입력 | 나이스 결과가 하나면 공식 이름으로 고쳐 저장. 여러 곳이면 지역명을 추가하도록 안내 | S10 또는 S02 오류 |
| S10 연결 | 설치된 앱 스위치 ON, 알림 접근 없음 | 아직 ON으로 저장하지 않고 선택한 앱 이름이 포함된 이유 팝업 표시 | S04 상황별 팝업 |
| S04 상황별 팝업 | ‘허용하러 가기’→OS에서 허용→뒤로 | 실제 권한 재조회, 선택 저장·수집 시작·초기 설정 완료 | 앱 로그인 안내→S05 |
| 앱 로그인 안내 | ‘앱 열기’ | 설치된 원 앱 실행. 로그인 상태를 읽지 않고 첫 새 알림으로 연결 검증 | 원 앱→재방문 S05 |
| S10 연결 | 사이트 스위치 ON | CONNECTING 저장 후 허용 도메인만 여는 앱 내 공식 로그인 화면 표시 | 사이트 로그인 |
| 사이트 로그인 | 로그인 완료 후 ‘로그인 유지 시작’ | 쿠키 세션 유지·SESSION_READY 저장. 실제 정보 읽기 전 CONNECTED로 표시하지 않음 | S05 |
| S10/로그인 | 취소·거부 | 선택/연결을 저장하지 않거나 CONNECTING 제거 | S10 |
| S02~S10 | 중간 앱 종료 후 재실행 | 저장된 자녀와 완료된 연결만 복원. 미완료 연결은 다시 시작 | S10 |
| S05 설정 미완료 | ‘연결하기’ | S02 또는 S10 중 필요한 화면으로 이동 | S02/S10 |

**로그인 분기 결정:** 나는 엄마다 자체 회원가입은 V0에 없다. 외부 사이트 로그인은 제공자 공식 화면에서만 하며, 비밀번호 대신 해당 WebView의 사이트 세션을 유지한다. 세션 만료는 REAUTH_REQUIRED로 바꾸고 해당 연결만 다시 로그인한다.

## U02. 권한 부분 허용과 첫 수신 대기 — F04/F05/F06/F10

| 화면 | 사용자 행동 | 시스템 반응 | 다음 화면 |
|---|---|---|---|
| S04 상황별 팝업 | 읽기 거부 | 앱 스위치 OFF 유지. 사이트·공개 API 연결은 계속 사용 가능 | S10 |
| OS 복귀 | 읽기 허용, 보내기 아직 요청 안 함 | 선택 앱 수집 가능. 첫 실제 알림 전에는 ‘첫 알림 기다리는 중’ | 앱 로그인 안내→S05 |
| S05/S06/S08 | 첫 실제 Action 또는 확인 후보를 앱에서 처음 봄 | foreground에서 발송 안내를 한 번만 표시. 이미 허용이면 생략 | 같은 화면 S04 발송 안내 시트 |
| S04 발송 안내 | ‘알림 받기’→OS 허용 | 실제 권한 재조회, 미래 예약 재계산. 지난 푸시 일괄 발송 없음 | 원래 화면 S05/S06/S08 |
| S04 발송 안내 | ‘나중에’/OS 거부 | 자동 재팝업 안 함, 기록 사용 유지·현재 앱 안에서만 확인 표시 | 원래 화면 |
| S05 첫 수신 대기 | 아무 행동 없이 일상 사용 | 새 알림이 올 때까지 빈 상태 유지. 가짜 실제 카드 생성 안 함 | S05 |
| S05 | ‘어떻게 챙기는지 보기’ | 로컬 예시 1개를 예시 라벨로 펼침, DB/알림/지표에 미반영 | S05 인라인 예시 |
| S05 | ‘연결 상태 확인’ | 권한·Source·마지막 수신 확인 | S10 |
| S05 | 첫 공지 전에 보조 문구 ‘알림 받기’ 선택 | 사용자가 원할 때 발송 허용 안내 제공 | S04 발송 안내 시트 |
| S10 | ‘테스트 알림’ | 자체 발송 상태만 검증; Source 수집 성공으로 간주 안 함 | S10 |

## U03. 핵심 경험: 자동 발견→확인→완료 — F06/F07/F10/F11/F16/F17

| 화면 | 사용자 행동 | 시스템 반응 | 다음 화면 |
|---|---|---|---|
| 원래 학교/학원 앱 또는 앱 미사용 | 새 공지를 받음. 우리 앱에 입력하지 않음 | 허용한 알림 정규화·AI 추출·날짜 검증 | 백그라운드 |
| 백그라운드 | 추가 행동 없음 | 충분한 근거와 검증 통과 시 Action 저장·예약 | S05에 카드 반영 |
| 기기 알림 | 일반 묶음 또는 단일 알림 탭 | 로컬 대상 최신 상태 확인 | 여러 개 S05 / 하나 S06 |
| S05 | 카드 탭 | 제목·날짜·준비물·출처·근거·다음 알림 조회 | S06 |
| S06 | ‘출처 앱 열기’ 후 원래 앱에서 동의서 제출 | 원래 앱이 제출 처리. 우리 앱은 완료를 자동 추정 안 함 | 원래 앱 |
| 원래 앱 | 뒤로 또는 우리 앱 재실행 | 상세 복귀 또는 오늘 목록 복원 | S06/S05 |
| S06 | ‘완료했어요’ | DONE 저장, 후속 리마인더 취소 | S06 완료 상태 |
| S06 | 선택적으로 ‘도움 됐어요’ | 항목당 명시적 가치 경험 1회 기록 | S06 |
| S06 | 뒤로 | 완료 카드는 오늘 목록에서 빠짐 | S05 |

첫 Action도 자동 확정 조건을 통과하면 추가 승인 없이 보인다. ‘첫 알림부터 확인’은 상세의 근거와 수정 경로를 알려주는 의미이며 일괄 확인 강제 단계가 아니다.

## 동선 결정

- 온보딩은 시작·자녀 정보·통합 연결 목록 3개 앱 화면이다. 별도 알림 접근 페이지와 ‘연결 설정 계속’ 버튼은 없다. 앱 스위치를 처음 켤 때만 이유 팝업과 OS 설정을 보여주고, 사이트 스위치는 공식 로그인 화면으로 바로 이어진다.
- 반복 핵심 경험은 **알림 탭 → 상세 → 완료**다. 정답인 추출은 확인 버튼을 한 번 더 요구하지 않는다.
- 예외는 별도 설정 탐색 없이 홈 배너/확인함에서 해결한다. 사용자에게 조치를 요구할 수 없는 자동 처리 내부 단계는 독립 화면으로 만들지 않는다.
