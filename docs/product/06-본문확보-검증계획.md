# 푸시에 본문이 없을 때 — 공지 원문 확보 경로

2026-09-13 · 상태: 공식 자료 조사 완료 / 실제 보호자 화면 검증 대기

**후속 요구 반영:** 사용자가 평소 원래 앱/웹을 열어야 하는 방식은 핵심 해법에서 제외했다. 현재 최우선 기준은 [자동 원문 연동 제품 기준](07-자동원문연동-제품기준.md)이다. 아래 화면 읽기·공유·OCR 조사는 기술 진단/선택 보조 후보로만 유지한다.

## 이번 결정

사용자가 ‘알림으로 열린 앱의 내용을 크롤링하거나 분석해 가져오는 방법을 찾아달라’고 요청했다. 기존 명세의 접근성 기반 읽기 제외를 **기술 실험 후보 범위에서 재검토**한다. 제품 핵심인 반복 입력 최소화와 사용자 범위 통제는 유지한다.

현재 배포 파일 `mom-probe-0.1.0-debug.apk`는 새 알림 수집만 수행한다. 이 문서는 새 화면 접근 권한이 기존 APK에 추가됐거나, 실제 학교 앱 본문 확보에 성공했다는 뜻이 아니다.

**결론: 푸시에 본문이 없어도 다른 원문 확보 경로는 있다. 열린 화면의 글자, 공식 사용자 웹, 공유·첨부, 허용된 화면 이미지가 후보다. 실제 서비스별로 읽기·자동화·최신성·배포 가능성을 따로 입증해야 한다.**

## 경로 비교

| 경로 | 동작 | 사용자의 추가 행동 | 확인 수준 | 먼저 검사할 실패 조건 |
|---|---|---|---|---|
| 알림 확장 본문 | NLS의 title/text/bigText/textLines 확보 | 최초 설정 후 없음 | 수집 APK 구현, 실앱 미측정 | 제목만 있음, 새 공지 누락, 변경 알림 없음 |
| 열린 앱의 화면 글자 | 허용된 AccessibilityService로 공지 화면의 접근성 노드 텍스트 읽기 | 최초 별도 동의·OS 설정, 공지는 직접 열어야 함 | Android API 존재 확인, 각 앱에서의 노출 미검증 | 이미지 본문, 가상/비노출 노드, 민감 화면 차단, 화면 밖 본문 누락 |
| 공식 사용자 웹 | 본인이 로그인한 공식 웹에서 공지 본문/허용된 첨부 열람 | 초기 웹 로그인·필요한 재인증 | 여러 서비스 공식 웹 근거 확인 | 보호자 웹 미지원, 이미지 전용, 세션 만료, 공지/URL 매칭 실패, 자동 접근 조건 불충족 |
| 공식 링크·파일 전달 | 앱이 제공하는 공유/첨부 저장을 받아 파싱 | 앱별 공유·저장 동작 발생 | 일부 기능 문서 확인, 보호자 메뉴 실측 필요 | 특정 역할만 다운로드 가능, 링크 만료, 접근 불가, 반복 입력 부담 |
| 허용된 화면 이미지+OCR | 선택한 앱 화면을 OS 동의 후 캡처해 한국어 OCR | 캡처 세션 시작 때 동의, 화면을 열어야 함 | 플랫폼 캡처·한국어 OCR API 확인 | 캡처 보호, 화면 밖 내용, 글자/표/날짜 인식 오류, 잠금 후 세션 종료 |

공유/캡처를 매일 필수 작업으로 만드는 것은 기존 자동 수집 목표와 다르다. 이 경로의 성공을 ‘엄마가 공지를 열지 않아도 되는 완전 자동화’로 계산하지 않는다.

## 1. 열린 앱 화면 읽기

Android는 접근성 서비스에 UI 계층을 읽는 기능을 제공한다. `canRetrieveWindowContent`를 선언하고 허용받은 뒤 이벤트/노드의 텍스트를 읽을 수 있다. [Android 공식 구현 문서](https://developer.android.com/guide/topics/ui/accessibility/service)

제안하는 실험은 사용자가 공지 하나를 열었을 때 **그 앱과 그 공지 화면에 한정해** 제목·본문·날짜·첨부 안내를 읽는 것이다. 별도 타이핑은 요구하지 않는다. 화면에 나타나지 않거나 대상 앱이 노출하지 않은 내용은 ‘확보하지 못함’으로 기록한다.

실험용 서비스가 필요하면:

- 읽을 패키지와 목적을 별도 화면에서 명시하고 사용자가 활성화한다.
- 선택 앱이 전면에 있는지 검사하고, 다른 앱/키보드/시스템 알림창으로 전환되면 즉시 수집하지 않는다.
- 비밀번호·편집 입력 필드·동의되지 않은 개인 대화는 제외한다.
- 원문과 수집 시각·출처·일부/전체 여부를 연결하며, 다른 공지를 마지막 푸시에 잘못 연결하지 않는다.
- 첫 실험은 자동 클릭·제출 없이 노출 텍스트 확보부터 확인한다. 길게 스크롤하는 글은 실제로 확인한 구간만 저장하고 전체 확보로 표시하지 않는다.

민감한 화면은 일반 접근성 서비스의 읽기를 차단할 수 있다. 범용 엄마 비서를 장애인 보조 도구라고 잘못 선언해 차단을 해제하지 않는다. [Android의 민감 화면 보호](https://developer.android.com/blog/posts/enhancing-android-security-stop-malware-from-snooping-on-your-app-data)

Google Play 정책은 일반 앱의 접근성 사용을 일괄 금지하지 않지만, 해당 용도의 신고·명확한 고지·동의·심사가 필요하다. 자율적으로 행동을 시작·계획·실행하는 자동화와 사람이 정한 결정적 규칙의 자동화를 구분한다. 따라서 ‘LLM이 임의로 여러 앱을 돌아다니며 처리’하는 구조를 배포 전제로 삼지 않는다. 읽기 실험 성공만으로 심사 통과를 주장하지 않는다. [Google Play 접근성 정책](https://support.google.com/googleplay/android-developer/answer/10964491?hl=es)

## 2. 공식 웹·본문 링크·첨부

| 서비스 | 공식 자료에서 확인한 사실 | 아직 확인하지 못한 것 |
|---|---|---|
| 학교종이 | 공식 웹 매뉴얼에 학교/학급·안내문·알림장 메뉴가 있음. 교직원 중심 설명이 포함됨 | 보호자에게 같은 메뉴가 제공되는지, 실제 본문 DOM·첨부·글별 주소 |
| e알리미 | 개별 알리미/설문 링크를 SMS에 넣는 옵션, 클래스 파일/사진 다운로드, 한글문서 본문 삽입을 안내 | 그 링크가 보호자 앱에서 공유되는지, 수신자 인증/만료 조건, 보호자 다운로드 범위 |
| 하이클래스 | 공급자가 웹·앱 기반 알림장/가정통신문 서비스를 설명 | 실제 부모 계정의 웹 본문·첨부·공유·주소 구조 |
| 클래스노트 | 공식 가이드에 PC/Mobile 이용과 PC Web 경로, 첨부 다운로드 FAQ가 있음 | 부모 역할 메뉴와 공지 전문·첨부의 실제 접근 범위 |

근거: [학교종이 웹 매뉴얼](https://schoolbell-e.oopy.io/webmanual), [e알리미 기능소개](https://www.ealimi.com/Promotion/Promotion), [하이클래스 제품소개](https://i-screammedia.com/www/business_hiclass.html), [클래스노트 빠른 가이드](https://www.with-classnote.com/quickguide), [클래스노트 파일 FAQ](https://www.with-classnote.com/faq/6).

이는 본문이 존재할 수 있는 정상 열람 경로의 근거다. 공개 API, 무인 크롤링 허용, 보호자 권한, 상업적 재사용을 모두 증명하는 자료가 아니다. 앱의 로그인 세션이 다른 앱이나 브라우저로 자동 공유된다고 가정하지 않는다. 웹 경로를 실험할 때는 사용자가 공식 사이트에 직접 로그인하고, 본인에게 제공되는 공지로 확인한다.

웹 경로가 성립하면 글별 식별자·버전/수정 시각·삭제/권한 만료까지 추적할 수 있는지를 본다. 텍스트가 확보되더라도 인증이 자주 끊기거나 매번 수동 공유해야 한다면 자동 처리율에 그대로 반영한다.

## 3. 이미지·PDF·화면 OCR

Android MediaProjection은 사용자 동의를 받은 화면 캡처를 지원하며 Android14 이상에서는 특정 앱 화면만 선택할 수 있다. 캡처는 세션별 동의가 필요하고 잠금/사용자 중지 등에 의해 종료될 수 있다. [공식 화면 캡처 문서](https://developer.android.com/media/grow/media-projection)

한국어 텍스트 인식은 ML Kit의 한국어 모델을 후보로 사용할 수 있다. 화면 캡처 성공과 OCR 정확성은 별개이므로 원문 날짜·준비물과 비교한다. [한국어 OCR 문서](https://developers.google.com/ml-kit/vision/text-recognition/v2/android)

앱이 `FLAG_SECURE`로 보호한 화면은 캡처가 비거나 제한될 수 있다. 해당 경로는 미지원으로 기록하고 공식 웹·공유·제휴 경로를 확인한다. [Android 화면 보호](https://developer.android.com/security/fraud-prevention/activities)

다운로드 가능한 PDF는 텍스트 PDF인지 이미지 PDF인지 나눈다. HWP/HWPX·표·서명 양식도 별도 사례로 취급하며 ‘첨부 파일을 받음’과 ‘그 안의 준비물/날짜를 정확히 읽음’을 같은 성공으로 세지 않는다.

## 4. 지금 할 가장 작은 실험

**부모 계정 하나 × 실제 사용하는 앱 하나 × 공지 3건**으로 시작한다. 표본은 짧은 텍스트·긴 본문·이미지 또는 문서 첨부 각1건이다. 처음 3건은 기술 탐색이며 G0의300건 검증이나 제품 성공 판정을 대체하지 않는다.

1. S23의 USB 디버깅 연결을 완료한다. 현재 Windows의 S23 USB 인식은 확인했지만 ADB 연결은 아직 없다.
2. 사용자가 실제 사용하는 학교/학원 앱을 확인한다. 앱 이름을 추정하여 개인 공지를 열지 않는다.
3. 선택된 공지에서 알림 payload와 상세 화면의 내용을 대조한다.
4. 상세 화면의 노출 텍스트를 확인한다. ADB 도구에서 읽혀도 일반 배포 앱의 권한으로 읽힌다는 증거는 아니므로 별도 사용자 허용 서비스로 재현해야 한다.
5. 같은 공지를 공식 웹에서 볼 수 있는지, 텍스트/첨부를 확보할 수 있는지 검사한다. 최초 로그인은 사용자가 직접 한다.
6. 텍스트가 없으면 사용자에게 제공된 이미지/파일 또는 허용된 화면 캡처로 OCR 정확도를 측정한다.
7. 같은 글의 재열람·수정/취소 정보·세션 만료·사용자가 열지 않은 새 공지 한 건을 확인해 지속 동작 가능성을 구분한다.

기록할 결과:

| 항목 | 기록 |
|---|---|
| 출처 | 앱명/버전·OS·보호자 역할·공지 별칭 |
| 원문 정답 | 해당 아이·행동·날짜·시각·준비물, 없으면 없음 |
| 확보 방식 | 알림/화면 노드/공식 웹/공유파일/OCR |
| 완전성 | 전체/일부/없음, 화면 밖/첨부 누락 명시 |
| 사용자 수고 | 새로 필요했던 탭·스크롤·공유·로그인·승인 횟수 |
| 최신성 | 재조회 가능, 수정/취소·권한 만료 감지 가능 여부 |
| 판정 | 자동 수집 후보/열어본 공지만 지원/수동 보조/해당 경로 불가 |

화면·원문은 검증에 필요한 최소 범위만 사용한다. 제3자에게 메시지 전송, 학교 제출, 구매·결제, 교사·학교 계정 생성은 실험에 필요하지 않다.

## 5. 제품 판단

열린 공지의 자동 기억은 진단/선택 보조 경험이다. **사용자가 공지를 열지 않은 상태에서 원문을 확보하는 경로**를 먼저 검증한다. 열린 화면 읽기만 성공한 결과는 핵심 제품 기준 통과로 계산하지 않는다.

더 강한 자동 경험은 알림의 본문 또는 허용된 지속 웹/공식 연동에서 원문을 확보할 수 있을 때 성립한다. 두 유형의 자동 처리율과 사용자 수고 감소를 따로 계산한다. 편리한 한 앱 연결부터 입증하고 지원 앱을 늘린다.

현재 근거로 ‘불가능’ 또는 ‘어떤 앱이든 완전 자동’이라고 결론 내리지 않는다. 공식 API 미발견은 읽기 경로 전체가 없다는 뜻이 아니다. 다음 의사결정은 실제 보호자 공지의 노출·정확성·유지 비용을 기준으로 한다.
