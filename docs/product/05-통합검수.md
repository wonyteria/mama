# 나는 엄마다 — 통합 검수와 최종 개발 인계

버전 1.2 · 2026-09-13 · 스위치 중심 연결과 상황별 권한 요청 반영. 검수 대상: PRD, 기능명세서, User Flow, Wireframe.

이 문서는 설계 단계의 검수 기록이다. 이후 사용자의 개발 요청으로 G0 앱을 구현했으며, APK·자동 테스트·실기기 미검증 범위는 [구현 검증 결과](../mom-agent/android/VERIFICATION.md)에서 확인한다. 아래 V0 수용 기준 전체가 구현됐다는 뜻은 아니다.

## 판정

**네 문서를 하나의 V0 설계로 정리했다. 지금 수행한 것은 설계 검수이며 앱 구현·실기기 검증·사업 검증은 아니다.**

핵심 동선은 ‘허용한 새 알림 자동 수집 → 챙길 일 확정 → 필요한 때 알림 → 완료/미루기’다. 사람 확인이 필요한 오류 경로, 설정 복구, 저장·수정·삭제까지 기능·화면·흐름을 연결했다.

V0 구현 착수 조건은 G0 수집 검증 + G1 오프라인 AI 평가 통과다. 현재 자료에는 실제 검증 결과가 없으므로 통과 상태를 부여하지 않는다. 선행 개발 작업은 MOM PROBE에 한정한다.

## 4. 최종 구현 순서와 산출물

1. **G0만 먼저:** 연구 동의·아이/Source·읽기 권한·정규화·로컬 수집·SP01/SP02·삭제. 산출물은 APK, 앱/기기별 수집 증거, 검토된 평가 파일, 정보 확보율 보고서.
2. **G1 오프라인 평가:** 정답 라벨·날짜 Resolver 규칙·추출 스키마·중복/변경 평가. 원문 자동 가림으로 충분하다고 가정하지 않는다. 산출물은 분모가 명확한 지표와 지원 Source 목록.
3. **게이트 통과 후 V0 수직 구현:** S01→S05 수집·추출→S06 완료, 이어 S08 불확실/변경, S13 미루기·S07 수정·S14 삭제·S10 장애·S12 데이터 통제.
4. **실기기/베타:** AC 기준·정확성·보관/삭제 검증, 30명 4주 제품 평가. 기준 미달이면 기능 확대보다 Source/정확성/사용 부담을 수정.

기술 선택의 최소 방향은 Kotlin·Compose·Room 기반 로컬 기록과 별도 AI 추출 API다. 데이터베이스 Graph·클라우드 사용자 기록·다중 AI 라우터는 현 범위에 불필요하다. 구체 SDK 버전·공급자는 구현 시작 시 검증해 결정한다.

## 6. 설계 검수 결과 기록

- PRD의 8개 요청 항목 작성.
- V0 20개 기능과 Probe 2개 기능에 목적/행동/처리/입출력/데이터/예외/권한을 포함한 9개 필드 작성.
- 소비자 14개 화면/시트와 연구용 2개 화면에 10개 배치·상태 항목 작성.
- 첫 방문·무가입·권한 부분 허용·자동 처리·수정/완료/미루기·변경·삭제·재방문·장애·무료 분기 연결.
- 기능/화면/흐름/수용 기준 추적표 작성. 코드 변경·APK 생성·실기기 테스트는 수행하지 않음.
- 별도 읽기 전용 검수에서 발견한 5개 상태/화면 문제를 수정하고 AC32~AC35와 S06 버튼에 반영했다. 연구 빌드 삭제 예외도 명시했다.
- 문서 구조 검사: 기능 22개 모두 9개 필드, 화면 16개 모두 10개 필드 확인. 텍스트 와이어프레임 코드 블록 짝과 한글 인코딩 이상 문자 없음 확인. 기능별 동작 및 사용성 수용 기준은 AC01~AC40으로 정의했다.
- v1.1에서 앱 먼저 선택·이름만 입력·한 권한씩 안내·자동 복귀 검사·첫 결과 후 발송 안내·설정 이어하기를 교차 반영했다. 학교/학원 null의 정확성 저하 가능성은 확인 후보와 G1/G2 자동 처리율로 검증하며, ‘쉬워졌다’는 실사용자 결과는 아직 없다.

설계 핵심: **더 많은 가족 기능을 만들기 전에, 엄마가 입력하지 않아도 한 가지 일을 정확하게 찾아 챙겨주는 경험부터 검증한다.**
