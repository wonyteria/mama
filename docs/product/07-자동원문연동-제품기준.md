# 최초 연결 뒤에는 ‘나는 엄마다’만 보는 제품

2026-09-13 · 사용자 요구에 따른 기준 확정 · 실제 자동 원문 연동은 미검증

**후속 실측:** 실제 S23에서 e알리미 단일 공지의 제공 링크→HTML→본문 PDF→텍스트 추출 경로를 확인했다. [실기기 검증 보고서](../mom-agent/device-tests/2026-09-13-results.md). 아직 새 공지/링크를 사용자 조작 없이 발견하는 단계는 미검증이다.

## 바뀌지 않는 제품 기준

**엄마는 최초 계정 연결·동의를 마친 뒤, 평소에는 우리 앱에서 준비물·마감·변경을 확인한다.** 새 공지를 얻기 위해 원래 앱/웹을 직접 열거나, 복사·붙여넣기·캡처·공유하는 절차를 일상 사용의 필수 조건으로 두지 않는다.

이 기준은 `06-본문확보-검증계획.md`의 ‘열어본 공지 자동 기억’을 첫 제품 경험으로 삼자는 제안보다 우선한다. 열린 화면 읽기/OCR은 기술 진단이나 선택 보조 기능에만 사용할 수 있다. 이를 핵심 자동 수집 성공으로 계산하지 않는다.

제출·회신·결제처럼 외부에 효력이 생기는 행동은 원문 확보와 별개다. 사용자 승인 없이 수행하지 않는다. 특정 제출에 원래 서비스가 필요한지 여부는 실제 연동 권한을 검증한 뒤 정의하며, 현재 ‘모든 학교 업무까지 우리 앱에서 끝남’을 약속하지 않는다.

## 가장 먼저 검증할 구조

```text
최초: 사용자가 공식 서비스에 직접 로그인·연결 동의
                ↓
허용된 세션을 사용하는 서비스별 읽기 전용 커넥터
                ↓
새 공지 목록 자동 확인 → 본문·허용된 첨부 확보
                ↓
글 식별자·판본·수정/삭제/권한 상실 확인
                ↓
아이와 연결 → 준비물·마감·변경 추출 → 우리 앱에 표시

휴대폰 푸시 수신은 새 공지 확인을 앞당기는 보조 신호
엄마가 푸시를 누르는 것은 수집의 시작 조건이 아님
```

우선순위는 제공되는 공식 API/피드 → 실제 허용된 보호자 웹의 지속 열람 → 해당 제공자와의 원문 연동이다. 공개 API 문서를 찾지 못했다고 사용자 웹의 정상 자동 열람까지 불가능하다고 결론내리지 않는다.

웹 경로는 실제 본인 계정과 해당 서비스의 접근 조건에서 먼저 확인한다. 로그인된 휴대폰 앱의 세션/비밀번호를 다른 앱이 자동 가져올 수 있다고 가정하지 않는다. 첫 공식 웹 로그인은 사용자가 직접 하며, 세션 유효기간·재인증 빈도도 검증한다. 인증 만료/추가 확인이 생기면 연결 문제로 표시하고 자동 수집이 계속되는 척하지 않는다.

## 첫 실험의 성공 조건

대상: 실제 사용하는 앱 하나·보호자 계정 하나. 첫 연결 후 아래 과정에서 사용자에게 원래 앱/웹 방문을 요구하지 않는다.

1. 커넥터가 스스로 현재 공지 목록을 가져오고 글 식별자를 얻는다.
2. 텍스트 공지·긴 본문·첨부 공지 각1건에서 핵심 내용이 확보된다.
3. 최초 설정 후 새로 도착한 공지 한 건을 사용자 탭/공유 없이 발견한다.
4. 커넥터 프로세스를 재시작하고 하루 이상 유휴 후에도 허용된 세션으로 다시 읽을 수 있는지 확인한다.
5. 원문 변경·삭제·권한 만료를 구분한다. 변경 표본이 없으면 그 항목은 미검증으로 남긴다.
6. 수집 중단·계정 연결 해제 시 작업과 저장 세션이 중단/제거되는지 확인한다.

처음 몇 건의 성공은 기술 가능성 신호다. 기존 300건 원문 충분성 검증·AI 정확도·사용자 가치 실험을 대신하지 않는다. 날짜/준비물을 사람이 보완한 건은 자동 처리 성공에서 제외한다.

자동 동작의 허용 지연 시간은 원문 접근이 확인된 뒤 정한다. 푸시가 왔는데 본문을 아직 못 가져왔다면 ‘원문 확인 중/연결 문제’를 표시하고 내용을 추정하지 않는다. 목록에서 잠깐 사라진 글을 즉시 취소로 단정하지 않으며, 로그인 만료를 공지 삭제와 구분한다.

## 운영 가능한지 별도로 볼 조건

- PC에서 실험한 커넥터가 작동해도 일반 엄마에게 PC 상시 실행을 요구하지 않는다. 정식 제품에서는 서버 등 관리 가능한 실행 환경으로 옮길 수 있는지 검증한다.
- 현재 G0 APK는 인터넷 권한 없는 로컬 수집 앱이다. 원문 커넥터를 붙이면 인증·세션·서버·동기화·보관 정책이 달라지므로 실제 연동 성공 후 기능명세/동의 화면을 갱신한다. 현재 APK에 그 기능이 구현돼 있다고 표시하지 않는다.
- 세션은 사용자별 격리하고 인증 정보를 로그·채팅·분석 데이터에 넣지 않는다. 원문 수집/AI 처리의 실제 데이터 흐름을 사용자에게 설명한다.
- 원문 자동 열람이 학교 측 ‘읽음’으로 기록되는지 확인한다. ‘Agent가 확인’과 ‘엄마가 실제 확인/제출 완료’를 우리 앱에서 구분한다.
- 앱/웹 화면 변경 때 연결이 조용히 깨지지 않도록 실패 감지, 마지막 성공 시각, 재시도, 지원 버전 관리를 둔다.
- 매 공지마다 캡처/공유/외부 앱 열기를 해야 하거나, 인증이 지나치게 자주 끊기면 이 제품 기준 미달이다. 기능을 덧붙여 통과로 포장하지 않는다.

## 휴대폰 디버깅 상태

이번 점검에서 ADB 서버 실행, S23(SM-S911N)의 정상 USB 인식, 서명된 Samsung USB Composite 드라이버 설치를 확인했다. ADB 기기 목록은 비어 있고 디버깅 인터페이스는 나타나지 않았다. Windows 장치 재검색은 현재 프로세스의 관리자 권한 부족으로 실행되지 않았다.

Android는 USB 디버깅 활성화와 이 컴퓨터의 RSA 연결 허용을 휴대폰에서 요구한다. 허용 전에는 컴퓨터에 그 설정을 대신 조작할 ADB 연결 자체가 없다. 따라서 이 기기 내 최초 승인 단계는 사용자가 완료해야 한다. 이후 설치·검사·로그 확인은 위임 범위에서 진행한다. [ADB 연결 요구사항](https://developer.android.com/tools/adb)

USB 디버깅은 개발 검증을 위한 절차이며, 일반 사용자에게 요구할 제품 초기 설정에는 포함하지 않는다.
