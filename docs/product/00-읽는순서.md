# 나는 엄마다 — 제품 설계 문서

홈 위젯·떠다니는 캐릭터·알림 강도·웹 주기 조회의 후속 설계는 [13 홈 화면 요정 비서와 자동 확인](13-홈화면-요정비서-자동확인.md)에서 확인한다. 현재 APK 구현 완료를 뜻하지 않는다.

최신 검수: [11 최종 점검·비서 알람·연결 유지](11-최종점검-비서알람-연결유지.md), [12 추가 기능 백로그](12-추가기능-백로그.md). 현재 쿠키 저장은 로그인 자동 갱신을 보장하지 않으며 실제 개인 웹 수집·비서 알람 엔진은 미구현이다. 이 검수의 상태 판정과 알림·갱신 설계가 이전 설명보다 우선한다.

2026-09-13 · 사용자 제공 마스터 명세서를 핵심 문제 중심으로 재구성한 설계안입니다. 이후 개발 요청에 따라 G0 설치형 앱을 구현했습니다. V0 자동 챙김은 선행 검증 뒤 개발합니다.

현재 구현: [MOM PROBE 소스·설치 안내](../mom-agent/android/README.md), [클레이모피즘 구현 기준](../mom-agent/android/design/implementation.md), [코드 검증 결과](../mom-agent/android/VERIFICATION.md).

최신 제품 요구: **최초 연결 후에는 엄마가 원래 앱/웹을 열지 않아도 우리 앱에서 필요한 정보를 확인해야 합니다.** [자동 원문 연동 기준](07-자동원문연동-제품기준.md)이 이후 수집 구조 검증의 우선 기준입니다. 현재 v0.2 APK는 e알리미·하이클래스 공식 로그인 화면과 세션 유지의 프로토타입까지 포함하며, 로그인 뒤 개인자료 자동 읽기는 아직 검증 전입니다.

개인 비서의 확장 방향은 [엄마 개인 비서 제품 방향](08-개인비서-제품방향.md)에 기록했습니다. 가족의 필요를 구매 목록과 선호 판매처의 비교·구매 링크 준비까지 연결하되, 실제 데이터 접근과 자동 수집 검증을 선행합니다.

앱·사이트 통합 목록, 자녀 정보, 계정/토큰 보관 원칙과 v0.2 실기기 결과는 [연결 및 인증 명세](09-연결및인증명세.md)에 기록했습니다.

에이전트의 아침·저녁 브리핑, 중요 알림, 완료·미루기·구매 링크 실행 기준은 [에이전트 알림 UX](10-에이전트-알림-UX.md)에 기록했습니다.

**선택한 학교·학원 앱의 새 알림에서 준비물·마감·일정 변경을 자동으로 찾아, 필요한 때 알려주고 처리할 때까지 기억합니다.**

| [01 PRD](01-PRD.md) | 서비스 정의, 타깃, 문제, 가치, 핵심 기능, MVP, 제외 범위, 성공 기준 |
| [02 기능명세서](02-기능명세서.md) | V0 20개·Probe 2개 기능의 9개 항목, 상태 전이, 데이터·날짜·알림·삭제 계약 |

읽는 순서는 PRD → 기능명세서 → User Flow → Wireframe → 통합 검수입니다. 실제 동작의 최종 기준은 기능명세서이며, 정책 변경 때 나머지 문서도 함께 수정합니다.

v1.2에서는 **자녀·학교 정보 → 앱·사이트 통합 연결 목록**으로 시작합니다. 앱 스위치를 처음 켤 때만 알림 접근 이유를 설명하고 OS 설정에서 돌아오면 원 앱 로그인 안내로 이어집니다. 사이트 스위치는 공식 로그인 화면을 열고 세션을 유지합니다. 별도 알림 접근 페이지와 ‘연결 설정 계속’ 버튼은 없습니다.

범위를 줄이기 위해 제안한 주요 결정은 자녀 1명, 검증된 앱 최대 2개, 로그인 없는 단일 기기 기록, 무료 V0입니다. 일정 변경은 사용자 확인 후 적용하며, 결제·AI 채팅·가족 공유·문자/카카오톡은 제외했습니다. 계정·백업이 없으므로 재설치·기기 변경 시 기록 복구도 지원하지 않습니다.

**다음 개발 단계는 전체 V0가 아니라 MOM PROBE입니다.** 자동 수집 실측과 별도 AI 정확도 평가를 통과한 뒤 V0를 구현합니다. 문서 작성·교차 검수 완료가 기술/시장 검증 완료를 뜻하지 않습니다.
