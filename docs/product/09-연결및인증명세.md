# 나는 엄마다 — 앱·사이트 연결 및 인증 명세

후속 코드 검수에서 로그인 URL 추정·세션 만료 감지 부재·웹 저장소 삭제 누락을 발견했다. ‘로그인 세션 프로토타입’은 실제 유지 보장이 아니다. 최신 수정 기준은 [11 최종 점검](11-최종점검-비서알람-연결유지.md)을 따른다.

2026-09-13 · v0.2 실기기 반영

## 제품 원칙

연결할 곳은 앱과 사이트를 같은 목록에서 보여준다. 사용자는 자녀별로 정보원을 연결하고, 우리 앱은 각 정보원의 상태·마지막 확인 시각·다시 연결 필요 여부를 관리한다.

**비밀번호를 범용 금고처럼 보관해 임의 사이트에 자동 로그인하지 않는다.** 우선순위는 공식 API/OAuth → 공식 위임 토큰 → 서비스 약관과 제공자 승인을 받은 세션 연결이다. 인증서·간편인증·2단계 인증·CAPTCHA는 우회하지 않는다.

나이스 공식 OpenAPI 문서는 인증키가 필요하다고 안내한다. 개발 검증에서는 허용된 키 없는 5건 샘플 범위를 사용했고, S24+에서 학교 검색과 일정 5건 응답을 확인했다. 운영 앱은 발급받은 서비스 API 키를 앱에 직접 넣지 않고 서버에서 관리해야 한다. [나이스 개발자 가이드](https://open.neis.go.kr/portal/guide/apiGuidePage.do)

## 회원가입·첫 설정

1. 개인정보 수집·보관·외부 연결 목적에 동의한다.
2. 자녀 이름/별칭, 학교 정식 이름, 학년을 입력한다. 생년월일·반·번호는 해당 기능에 반드시 필요해질 때 별도로 받는다.
3. 연결할 Android 앱이나 사이트의 스위치를 켠다. 별도 ‘계속’ 버튼은 두지 않는다.
4. 앱을 처음 켰고 알림 접근이 없으면 이유 팝업을 먼저 보여준 뒤 Android 설정으로 이동한다. 돌아오면 선택을 자동 저장한다.
5. 앱을 켠 뒤 해당 앱 로그인 안내를 보여준다. 앱을 열 수는 있지만 제3자 앱의 로그인 상태를 몰래 읽지 않는다. 첫 실제 알림 수신을 연결 검증으로 사용한다.
6. 사이트를 켜면 앱 안의 공식 사이트 화면에서 사용자가 직접 로그인한다. 비밀번호는 우리 앱 데이터 모델에 저장하지 않고 사이트 세션만 유지한다.
7. 연결 하나가 준비되면 홈으로 이동한다. 로그인·권한을 취소하면 스위치도 꺼진 상태로 되돌린다.

사이트 연결이 하나뿐이어도 진행할 수 있다. 앱 알림 읽기를 거부해도 공개 API 연결은 작동한다. 각 연결을 해제해도 다른 정보원은 유지된다.

## 자녀 데이터

V0는 자녀 1명을 지원한다. `child_id`를 앱 Source와 사이트 Connector에 공통으로 연결한다.

필수: 이름/별칭, 학교 이름, 학년. 짧게 입력해도 나이스 검색 결과가 하나면 공식 학교명으로 고쳐 저장한다. 결과가 여러 곳이면 지역명을 추가하도록 안내하고, 후속 버전에서는 주소/교육청 선택 화면에서 사용자가 확정한다. 위치 기반 ‘주변 학교’는 선택 기능으로 설계하며 위치 권한을 거부해도 학교명 검색은 사용할 수 있어야 한다.

학교·학년 변경 시 기존 일정은 출처 스냅샷을 유지하고, 학교정보 연결을 다시 확인한다. 기존 아이의 정보를 새 학교 데이터로 조용히 덮어쓰지 않는다.

## 인증 보관 등급

| 등급 | 저장 대상 | 저장하지 않는 것 | 만료/삭제 |
|---|---|---|---|
| PUBLIC_API | connector ID, 학교코드·교육청코드, 마지막 확인 시각 | 부모 계정 | 연결 해제 시 코드 삭제 |
| OAUTH | provider, 암호화 refresh/access token, scope, expiry | 비밀번호·인증서·OTP | 만료 시 refresh, 실패 시 REAUTH_REQUIRED, 해제 시 revoke+삭제 |
| APPROVED_SESSION | 제공자가 허용한 암호화 세션 토큰, 만료·scope | 원문 비밀번호·OTP·CAPTCHA 답 | 제공자 정책에 따른 만료, 해제 시 폐기 |
| UNSUPPORTED | 연결 희망 상태·설명 | 계정·비밀번호·쿠키 | 공식 경로 확보 전 수집 없음 |

세션/토큰은 로그·분석 이벤트·URL·지원 티켓에 넣지 않는다. 사용자별·자녀별 격리, 전송·저장 암호화, 키 회전, 접근 감사, 연결 해제를 지원한다. 현재 v0.2는 PUBLIC_API 메타데이터만 Android Keystore로 암호화해 기기에 저장한다. 서버 토큰 금고는 아직 없다.

## 연결 상태

- DISCONNECTED: 연결 전.
- CONNECTING: 사용자가 연결을 시작했으나 완료 확인 전.
- SESSION_READY: 공식 로그인 화면을 통과해 세션을 유지 중이나 실제 정보 읽기는 아직 확인 전.
- CONNECTED: 허용 범위와 최신 확인이 유효함.
- REAUTH_REQUIRED: 토큰/세션 만료 또는 추가 인증 필요. 새 수집 중단, 기존 기억 유지.
- ERROR: 네트워크·형식·제공자 변경 등. 오류를 ‘새 정보 없음’으로 표시하지 않는다.

SESSION_READY와 CONNECTED를 구분한다. 로그인 화면을 지나간 것만으로 CONNECTED라 하지 않는다. 읽기 전용 시험 요청이 실제 데이터를 반환하고 대상 자녀/학교와 연결됐음을 확인한 뒤 CONNECTED로 올린다.

## 나이스에 대한 결정

개인자료 사이트는 아이디·비밀번호, 간편인증, 공동인증서를 제공하지만 제3자 부모 OAuth/API는 공식 자료에서 확인되지 않았다. 약관에는 계정의 제3자 이용 방지, 이용 종료 시 로그아웃, 사전 승인 없는 취득 정보 복제·영리 이용 제한이 있다. 따라서 서버가 부모 비밀번호를 보관해 무인 로그인하는 기능은 KERIS의 공식 위임 연동을 확보하기 전 구현하지 않는다. [나이스 약관](https://parents.neis.go.kr/terms1.html)

대신 지금은 나이스 교육정보 개방포털로 공개 학교정보를 자동 연결한다. 성적·출결·건강·학교생활 개인자료는 ‘공식 연동 준비 중’으로 정직하게 표시한다.

## 쇼핑 연결

쿠팡·네이버도 동일한 연결 원칙을 적용한다. 사용자가 선호 판매처를 선택하고, 상품 검색·가격·배송 정보를 가져오는 공식 API/파트너 경로를 먼저 사용한다. 쇼핑 계정 비밀번호·결제수단을 맡아 자동 구매하는 기능은 현재 범위에 없다.

구매 후보는 규격·수량·배송비·도착 가능일을 맞춰 비교하고, 확인한 후보 중 조건에 맞는 총액을 표시한다. 마지막 실행은 사용자가 구매 링크를 선택해 해당 판매처에서 확인한다.

## v0.2 실기기 검증

- Galaxy S24+ SM-S926N, Android16에서 설치·실행 성공.
- e알리미·하이클래스 설치 감지 성공.
- 자녀 테스트 프로필과 ‘앱·사이트 연결’ 화면 표시 성공.
- 나이스 공식 학교 검색 성공, 학교코드·교육청코드를 암호화 저장.
- 해당 학교의 향후 30일 학사일정 응답 및 화면 표시 성공.
- 나이스 서버가 `Accept: application/json`에 HTTP500을 반환하고 `Accept: */*`에 정상 응답하는 호환성 문제를 실측하여 수정.
- 연결 화면의 중복 ‘계속’ 버튼 제거. 앱 스위치에서 권한 설명 → Samsung 알림 접근 → 자동 복귀 → 해당 앱 로그인 안내 동선을 확인.
- e알리미 앱 실행 연결을 패키지 수준에서 확인. 개인 화면 내용은 읽지 않음.
- e알리미 웹의 공식 로그인 화면을 앱 내 WebView에서 표시하고, 로그인 완료 전 확인 버튼이 비활성화되는 것을 확인. 취소 시 연결 상태가 남지 않음을 확인.

이는 공개 학교정보와 로그인 진입 동선의 증거다. 웹 로그인 후 세션 장기 유지, 로그인된 개인자료 읽기, 운영 API 키, 급식/시간표 UI, 백그라운드 주기 동기화는 아직 미검증이다.
