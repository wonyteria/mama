# 나는 엄마다 — V0 PRD

버전 1.2 · 2026-09-13 · 상태: 쉬운 첫 설정 반영 / G0 검증 앱 구현, V0는 선행 검증 대기

근거: 사용자가 제공한 「나는 엄마다 — V0 개발 마스터 명세서」. 아래 범위·수치 중 원문에 없는 세부 규칙은 이번 설계에서 제안한 결정이다. 검증된 실적을 뜻하지 않는다.

## 1. 서비스 한 줄 정의

**선택한 학교·학원 앱의 새 알림과 연결한 공식 사이트에서 아이의 준비물·마감·일정 변경을 찾아, 필요한 때 알려주고 처리할 때까지 기억하는 Android 비서.**

제품 약속은 연결이 확인된 정보원만 자동으로 확인해 우리 앱에서 행동에 필요한 내용을 보여주는 것이다. 알림에 본문이 없으면 제공자가 허용한 공식 API·OAuth·로그인 세션 커넥터를 사용하며, 승인되지 않은 화면 자동 조작이나 인증 우회는 하지 않는다.

## 2. 타깃 사용자

- 초등학교 1~6학년 자녀의 학교·학원 공지를 주로 챙기는 엄마.
- 개인 프로필의 Galaxy Android 13~16 사용, 학교와 학원 앱을 함께 사용.
- 첫 베타에서는 자녀 **1명**, 검증을 통과한 Source 앱 **최대 2개**를 연결한다. 자녀가 여러 명인 가정도 한 명만 등록한다는 제한을 사전에 알린다.
- 알림 본문 제공이 확인된 Source를 사용하는 사람을 모집한다. 앱 이름만 보고 지원을 확정하지 않는다.

학교종이·e알리미·하이클래스·키즈노트·클래스노트는 **조사 후보**다. 최초 지원 목록과 실제 packageName은 MOM PROBE 결과로 확정한다. 문자·카카오톡은 V0에서 제외한다.

## 3. 사용자가 겪는 핵심 문제

**여러 앱에 흩어진 공지를 읽고, 그중 내가 행동해야 하는 내용을 골라 기억하고, 변경까지 다시 확인하는 일이 반복된다.**

| 상황 | 현재의 부담 | V0가 해결할 부분 |
|---|---|---|
| 평범한 공지 사이에 준비물이 섞임 | 모든 공지를 다시 읽음 | 준비물과 날짜만 추출 |
| 동의서 마감이 며칠 뒤임 | 기억하거나 따로 기록 | 마감 전 알림과 미완료 유지 |
| 학원 시간이 뒤늦게 변경됨 | 이전 일정과 새 공지를 대조 | 이전/이후를 한 카드에서 확인 |
| 이미 처리했는데 다시 알림 | 불필요한 확인 반복 | 완료하면 후속 알림 중단 |

V0에서 풀지 않는 문제: 일정 직접 작성, 가족 간 업무 배분, 구매·결제 실행, 모든 가족 정보의 통합 검색.

## 4. 핵심 가치

1. **입력할 필요가 적다:** 최초 설정 후 새 알림을 자동 처리한다. 복사·붙여넣기나 캡처 업로드를 일상 경로로 만들지 않는다.
2. **봐야 할 정보가 줄어든다:** 참고·광고는 재알림하지 않는다. 일반 알림은 하루 두 번으로 묶는다.
3. **놓칠 가능성을 줄인다:** 미완료, 가까운 마감, 변경 사실을 유지한다.
4. **믿고 고칠 수 있다:** 출처·판단 근거·불확실성을 보여주고 수정·삭제·중단할 수 있다.

## 5. 핵심 기능

**허용한 앱·사이트 연결 → 원문 확보 → 행동 추출 → 정확성 검사 → 오늘 챙길 것 → 리마인드 → 완료/미루기**.

| 기능 | 반드시 필요한 이유 |
|---|---|
| 자녀 1명·학교 공식명 확인 | 공지와 공개 학교정보를 같은 아이에게 정확히 연결하기 위해 |
| 앱·사이트 통합 연결과 상태 확인 | 자동 수집 범위를 사용자가 스위치로 통제하기 위해 |
| 준비·할 일·일정 추출 | 원문에서 행동을 분리하기 위해 |
| 날짜 검증·확인 필요 상태 | 추측한 날짜를 사실처럼 알리지 않기 위해 |
| 중복 억제·일정 변경 확인 | 같은 일을 여러 번 만들거나 옛 일정을 알리지 않기 위해 |
| 오늘 목록·상세·완료·미루기·수정·삭제 | 발견한 정보를 실제 행동으로 연결하기 위해 |
| 기억 목록·일시정지·데이터 삭제 | 저장 정보와 수집을 통제하기 위해 |

## 6. MVP에 필요한 기능

### 범위 결정

- 저장 모델은 **Action 하나**로 통일한다. kind는 PREPARE(준비), TODO(제출·신청·납부 포함), EVENT(일정) 세 가지다.
- CHANGE는 독립적인 할 일이 아니라 기존 Action의 변경 제안이다. INFO는 Action을 만들지 않는다.
- 납부는 ‘납부할 일이 있음’만 TODO로 기억한다. 금액·계좌 수집이나 결제 수행은 하지 않는다.
- 일정은 준비물의 날짜 근거와 변경 대응에 필요한 범위만 저장한다. 캘린더 편집기·월간 달력은 만들지 않는다.
- 변경/취소는 기존 항목을 자동 덮어쓰지 않고 사용자가 전후 차이를 확인한 뒤 적용한다. 확인 대기 동안 기존 항목의 반복 알림을 중단하고 ‘변경 확인 필요’로 표시한다.
- 확정할 수 없는 정보는 확인함으로 보낸다. 내용이 너무 짧으면 ‘원문 확인 필요’로 남기며, 없는 날짜·준비물을 생성하지 않는다.
- 회원가입·로그인 없이 **이 기기에서 시작**한다. 기록은 기기 내 저장, AI 서버는 일시적인 추출 처리만 담당한다. 재설치·기기 변경 시 복구 불가를 시작 화면에 표시한다.
- 모든 V0 베타 사용자는 동일한 무료 범위다. 결제·구독·페이월은 구현하지 않는다.
- Android 알림 읽기 접근과 ‘나는 엄마다’ 알림 보내기 허용은 별도로 요청한다. 하나를 거부해도 가능한 기능을 이용할 수 있다.

### 처음 쓰는 사람도 혼자 끝내는 설정

첫 동선은 **시작·동의 → 자녀·학교 정보 → 앱·사이트 통합 연결 → 오늘**이다. 별도 ‘계속’ 버튼은 두지 않고 앱이나 사이트 스위치를 켜는 행동 자체가 연결을 시작한다.

- 지원 앱 중 기기에 설치된 앱과 지원 사이트를 아이콘·이름·상태·스위치로 보여준다. 기본 선택은 없으며 앱은 최대 2개다.
- 최초 직접 입력은 아이 이름/별칭·학교 이름·학년이다. 학교 검색 결과가 하나면 나이스 공식 이름으로 고쳐 저장하고, 여러 곳이면 지역을 추가하도록 안내한다.
- 앱 스위치를 처음 켰고 알림 접근이 없을 때만 S04 팝업에서 이유를 설명한다. OS 설정에서 복귀하면 실제 권한을 확인하고 선택을 자동 저장한 뒤 해당 앱 로그인 안내를 보여준다.
- 사이트 스위치는 허용 도메인의 공식 로그인 화면을 연다. 비밀번호를 앱 데이터로 보관하지 않고 사이트 세션만 유지한다. 로그인 세션 준비와 실제 정보 읽기 성공을 다른 상태로 표시한다.
- 자체 알림 보내기 권한은 첫 실제 Action 또는 확인 후보를 앱 안에서 보여준 뒤 ‘이 내용을 필요한 때 알려드릴까요?’로 한 번 안내한다. 권한을 받기 전에는 기기 밖 알림이 없음을 홈에 표시한다. 일찍 켜려는 사용자는 설정에서 언제든 허용 가능하다.
- 준비물·마감·일정 변경 챙김과 기본 알림 규칙은 시작 시 기본 사용한다. 사용자에게 기능 선택 화면을 만들지 않는다. 원문 추가 보관과 선택 측정은 계속 기본 OFF다.
- ‘Source·Memory·리스너·동기화’는 사용자에게 표시하지 않는다. ‘챙길 앱·자동 챙김·연결 상태·새 알림 기다리는 중’으로 설명한다.
- 설정이 끊기면 가장 먼저 해결할 문제 하나와 ‘이어서 설정하기’ 버튼만 보여준다. 이미 저장한 앱·이름과 허용한 권한은 다시 묻지 않는다. 전체 상태는 설정에서 펼쳐볼 수 있다.

출시 전 사용성 목표(새 제안): 대상 엄마 5명 중 4명 이상이 직원 설명 없이 첫 설정을 완료하고, 완료자의 중앙 설정 시간 3분 이내. 시간은 S01 시작부터 S05 읽기 허용 완료까지이며 OS 설정 왕복 포함, 실제 공지 대기 시간 제외. 실패·거부자는 별도 보고해 완료율 분모에서 빼지 않는다. ‘3분 설정’을 실측 전 광고 문구로 쓰지 않는다.

## 8. 성공했다고 판단할 기준

모든 비율은 분자/분모와 실제 표본 수를 함께 보고한다. 작은 베타의 기준은 의사결정 가설이며 통계적으로 시장 성공을 증명하지 않는다.

### 기술 기준: G0·G1

| 지표 | 계산 및 측정 방법 | 목표 |
|---|---|---|
| 알림 정보 확보율(G0) | 수집 본문만으로 행동·대상·명시된 날짜를 판별할 수 있는 중요 알림 / 조사자가 원본 앱 공지와 기기 알림을 대조해 정답 처리한 중요 알림. 앱에서 알림을 아예 안 보낸 중요 공지도 분모에 포함 | ≥80% |
| 중요 행동 자동 포착률(G1) | 사용자 확인 없이 정확한 Action으로 추출한 정답 행동 수 / 원본 공지 기준 전체 정답 행동 수. 한 공지의 여러 행동을 각각 셈 | ≥80% |
| 날짜/시간 정확도(G1) | 자동 확정한 날짜·시간이 정답과 모두 일치한 행동 / 날짜 또는 시간이 자동 확정된 행동. 애매한 정답은 별도 보류 집계 | ≥98% |
| 잘못된 Action 생성률(G1) | 틀린 행동·대상·날짜·추가 중복 중 하나가 있는 자동 생성 Action / 전체 자동 생성 Action | ≤5% |
| 중복 억제 재현율(G1) | 올바르게 추가 생성을 막은 중복 건 / 정답 중복 건 | ≥90% |
| 잘못된 병합(G1) | 서로 다른 행동을 합친 건수 | 평가셋 0건 |

300건은 전체 최소 수집량이다. 미리 고정한 홀드아웃에 중요 행동 ≥100개, 자동 확정 날짜/시간 ≥100개, 중복 ≥30건, 변경/취소 ≥20건이 없으면 추가 모집한다. 앱별 결과를 분리하고, 실패한 앱은 지원에서 제외한다. 기준 조정에 쓴 데이터로 통과 판정을 하지 않는다. 사람이 명확한 정답을 붙일 수 없는 내용은 자동 확정을 금지한다.

### 제품 기준: G2

| 지표 | 정확한 정의 | 목표 / 조치 |
|---|---|---|
| 7일 Activation | 베타 시작일부터 7일 안에 실제 Action 상세에서 ‘도움 됐어요’를 1회 이상 누른 사람 / 베타를 시작한 전체 30명. 설정 실패·도중 이탈도 분모 포함 | ≥70% |
| Saved Mom Moment | ‘이 알림이 없었다면 놓치거나 다시 찾아봤을 것’이라고 사용자가 명시적으로 인정한 Action. 사람×Action당 1회 | North Star의 사건 단위 |
| Saved Mom Moments / WAU | 해당 주 인정된 서로 다른 Action 수 / 해당 주 상세 조회·확인·완료·미루기·수정 중 한 행동 이상 수행한 사용자 수 | 추세 관찰. 초기 절대 목표를 임의로 만들지 않음 |
| 4주 유지율 | 첫 사용 후 22~28일에 위 핵심 행동을 1회 이상 한 사람 / 전체 베타 시작자 | ≥50%; <25%면 가치 재검토 |
| 자동 처리율 | 확인·수정 없이 올바르게 저장되고 7일간 정답 검수된 Action / 전체 정답 행동. 누락과 확인 대기도 실패로 포함 | ≥80%; <50%면 수집/분석 경로 재설계 |
| 알림 부담 | 일반 묶음 외 알림 수 및 중복 리마인드 결함 | 일반 묶음 하루 ≤2회, 동일 키 재발송 0건 |

일괄 ‘완료’ 클릭을 Saved Mom Moment로 간주하지 않는다. D7 인정 사용자 <30%이면 원문 Kill Criteria에 따라 핵심 문제와 메시지를 재검토한다. 목표와 중단 기준 사이는 원인 수정 후 한 번 더 베타를 수행한다.

### 사업 기준

V0에서는 결제를 받지 않으므로 실제 결제율을 측정하거나 사업 GO를 선언할 수 없다. 제품 검증 뒤 별도 유료 파일럿에서 실제 결제자/실제 구매 기회를 받은 적격 사용자 ≥10%를 가설 목표, <2%를 가격·BM 재설계 기준으로 적용한다. 요금·상품·해지·환불 명세는 그 단계의 별도 산출물이다.

## 개발 가능성 및 제품 문구의 한계

- NotificationListenerService는 기기에 게시된 알림 콜백을 제공한다. 앱 내부 문서 접근을 보장하지 않는다. 개인 프로필만 V0 테스트 대상으로 삼는다. [Android 알림 리스너](https://developer.android.com/reference/android/service/notification/NotificationListenerService)
- Android 13 이상에서 알림을 보내는 권한은 별도다. 읽기 허용만으로 사용자에게 리마인더를 보낼 수 있다고 간주하지 않는다. [알림 권한](https://developer.android.com/develop/ui/compose/notifications/notification-permission)
- 예약 알림은 OS 절전·사용자 설정으로 지연될 수 있다. V0는 정확 알람 권한을 요구하지 않으며 ‘정각 보장’·‘절대 놓치지 않음’이라고 표현하지 않는다. [알람 예약](https://developer.android.com/develop/background-work/services/alarms)
