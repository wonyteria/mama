# 똑닥에서 배울 ‘필수 앱’의 조건

확인일: 2026-09-13 (KST). 사용자가 말한 ‘똑딱’을 병원 접수·예약 앱 **똑닥(ddocdoc, 운영사 비브로스)**으로 해석했다. 공식 앱스토어·병원 운영 문서·회사 자료만으로 제품 구조를 검토했다. 가입·병원 접수·외부 연락은 하지 않았다. 가격·매출·유지율의 미확인 항목은 추정으로 채우지 않았다.

**똑닥에서 가져올 핵심은 ‘엄마가 자주 보는 앱’이 아니라 ‘필요한 일이 생겼을 때 실제 처리를 끝내는 도구’라는 점이다.** 다만 똑닥의 병원 공급망·전자차트 연동을 가진 사업 구조와, 저비용 1인 창업으로 시작할 엄마 비서는 출발 조건이 다르다. 똑닥의 성공을 근거로 우리 사업의 성공을 단정할 수 없다.

## 이전 가능한 원리와 이전할 수 없는 자산

아래는 공식 기능 구조를 바탕으로 한 사업적 **해석**이다.

| 원리 | 엄마 비서에 이전하는 방법 | 필요한 조건 |
|---|---|---|
| 필요가 생기는 순간 바로 쓰임 | ‘오늘 무엇을 챙기죠?’뿐 아니라 ‘이 가족 일을 맡길게’라는 요청을 받아 진행 상황과 끝난 결과를 보여준다. | 대상 업무의 시작·완료를 명확히 정의하고 실제 맡김을 측정 |
| 사용 결과가 눈에 보임 | 준비 목록, 신청 초안, 일정 확정, 완료 확인 등 엄마의 다음 행동을 줄이는 결과 제공 | ‘초안 작성’과 ‘제출 완료’를 혼동하지 않는 상태 표시 |
| 이미 준 정보를 반복해서 묻지 않음 | 동의한 가족 맥락·기존 준비·선호를 재사용해 계획과 실행 준비를 개선 | 동의·수정·삭제 가능하고 오래된 맥락을 확인하는 절차 |
| 진행 상태를 확인할 수 있음 | 접수 번호에 대응하는 우리 제품의 증거는 출처, 담당, 다음 단계, 승인 필요 여부, 실제 완료 확인 | 처리 결과를 확인할 수 있는 데이터 또는 사용자 확인 |
| 사용 빈도보다 필요 시 재선택 | 매일 앱 방문을 강요하기보다 가족 업무가 다시 생겼을 때 자발적으로 맡기는지 측정 | 업무 발생 기회를 분모로 한 반복 위임 지표 |

반면 **EMR 업체와의 공동 개발, 병원 도입 영업, 현장 설정·교육·장애 지원, 접수 재고와 순서를 실제로 바꾸는 권한**은 사업자가 별도로 확보해야 하는 자산이다. 사용자의 알림 접근 권한이나 범용 AI만으로 생기지 않는다. 병원용 공식 안내·운영 매뉴얼이 보여주는 이 구조를 고려하면, 저비용 1인 창업에서 공급자 네트워크 전체를 먼저 만드는 선택은 큰 운영 부담을 가져올 가능성이 높다. 이는 정확한 자본 소요액을 추정한 결과가 아니라 업무 구조에 대한 판단이다. [EMR 연동 안내](https://hospital.ddocdoc.com/signin), [병원별 운영 설정](https://blog.hospital.ddocdoc.com/post/story15)

엄마 비서가 반드시 ‘알림 앱’에 머물 필요는 없다. **파악 → 계획 → 필요한 준비 → 사용자 승인 → 가능한 실행 → 결과 확인**까지가 비서의 일이다. 초기에는 외부 제휴 없이도 명확한 결과를 낼 수 있는 부분을 선택하고, 실제 예약·납부·제출처럼 외부 상태를 바꾸는 부분은 해당 서비스가 허용한 연결과 사용자 승인을 확보한 범위에서만 다룬다. 학교 업무, 지출 확인, 가족 행사 중 무엇이 먼저인지는 실사용 증거로 고른다.

## 1인 창업자가 따라 하지 말아야 할 것

1. **‘필수 기능이 있으니 주변 기능도 붙이면 팔린다’는 가정.** 공식 iOS 버전 기록에는 똑닥쇼핑 종료(2025-04), 커뮤니티 종료(2025-06), 약국·복약관리·서류보관함 종료(2025-09)가 나온다. 종료 원인은 확인되지 않았다. 다만 큰 사용자 기반과 핵심 효용이 주변 모든 기능의 지속을 보장하지 않는다는 점은 분명하다. [공식 버전 기록](https://apps.apple.com/kr/app/id1014889755)
2. **낮은 구독료만 복사하기.** 똑닥의 현재 요금도 이번 조사에서 완전히 확인하지 못했다. AI 비용·사람 개입·고객지원·데이터 연동 유지비가 다른 제품에 같은 가격을 붙일 근거가 없다.
3. **병원·학교·금융·커머스 공급망을 동시에 만들기.** 1인이 그 연결을 모두 확보하기 전까지 고객 가치를 내지 못하는 구조는 초기 검증 비용이 커진다. 기존 서비스를 활용할 수 있는 업무부터 비교하되, 단순 링크 모음 이상의 순절감을 증명해야 한다.
4. **고객의 불안이나 접근 제약을 필수성으로 착각하기.** ‘안 쓰면 놓칠 것 같다’는 불안, 반복 확인, 보상 포인트 때문에 앱을 열 수 있다. 자발적으로 시간을 돌려받아 선택하는 제품인지 따로 확인한다.
5. **처리 불가능한 일까지 맡겼다고 표현하기.** 신청서 초안이나 병원 링크를 만들었을 뿐인데 접수·제출이 끝났다고 표시하면 비서 신뢰가 무너진다. 완료 증거 없는 항목은 진행 중으로 남긴다.

## ‘없으면 불편하다’를 입증할 증거

현재 아래 항목의 실측 결과는 없다. 개발 전 검토를 마치는 것과 고객 필수성을 검증하는 것은 별개다.

| 확인할 질문 | 필요한 관찰 | 피해야 할 대체 지표 |
|---|---|---|
| 같은 종류의 일이 또 생겼을 때 다시 맡기는가? | **다시 맡긴 업무 수 ÷ 맡길 수 있는 해당 업무가 발생한 수**. 아이 병원·행사처럼 주기가 긴 업무는 발생 시점 기준으로 본다. | DAU, 단순 앱 실행 |
| 맡긴 후 직접 챙기는 일이 줄었는가? | 검색·정리·질문·정정·재확인 시간을 포함한 순절감, 완료된 업무 수 | AI가 만든 카드 수 |
| 결과를 믿고 다음 행동을 할 수 있는가? | 완료 근거 확인, 정정률, 중요한 실패, 복구 시간. 실제 밖에서 처리된 결과와 맞는지 확인 | “AI가 똑똑해요” 만족도 |
| 대안보다 가치가 있는가? | 기존 방법/무료 도구와 동일 업무 비교, 중단을 선택한 이유, 동의하에 안전한 비긴급 업무에서 기존 방식으로 돌아갔을 때 부담 비교 | 서비스를 몰래 끊고 불편·실패 유도 |
| 비용을 계속 지불할 만큼 필요한가? | 할인·보상에 의존하지 않는 첫 결제와 실제 다음 갱신, 취소 이유 | ‘월 얼마면 쓰겠다’ 응답만 수집 |
| 대표의 손이 빠져도 돌아가는가? | 가구당 예외 처리·지원 시간, 원가, 처리 불가 업무 비율 | 뒤에서 사람이 전부 해결한 체험을 완전자동 성과로 기록 |

‘매우 아쉽다’는 설문은 보조 자료로만 쓰고, 작은 표본에서 특정 응답 비율을 넘었다고 필수 앱을 선언하지 않는다. 비서형 제품의 핵심 검증은 **다음에도 맡김 + 맡긴 후 노동 감소 + 확인 가능한 결과 + 자발적 갱신 + 감당 가능한 운영비**가 함께 성립하는지다.

개발 전 결론: 똑닥은 좋은 참고 사례이지만 동일 사업 모델의 복제 대상은 아니다. 엄마 비서의 첫 성공 조건은 ‘모든 가족 정보 통합’이라는 범위가 아니라, **어떤 가족 업무를 맡겼을 때 원래보다 확실히 수월하게 끝나는가**를 구체적으로 증명하는 것이다. 이 결과를 알림·챗봇·캘린더 중 어떤 형태로 전달할지는 그다음 결정이다.
