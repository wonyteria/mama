# 추가 기록 없는 엄마 비서 — 다음 결정

기준: 2026-09-13. 사용자는 엄마에게 새로운 메모·기록 습관을 요구하는 방향을 거부했다. 이 조건을 앞선 ‘새 부탁 한 번’ 제안보다 우선한다.

## 결정

일상적인 기록을 요구하지 않아도 가치가 생기는 비서 가설을 유지한다. 직접 부탁·공유는 선택 보조 기능이며 핵심 효용이나 실험 성공의 필수 조건으로 삼지 않는다. 아직 모든 가족 업무를 자동으로 파악할 수 있다고 검증되지 않았으므로 본제품 개발을 시작하지 않는다.

다음 단계는 앱 완성 대신 **원천 정보 충분성 검증**이다. 대상은 교육·납부·가족 행사 중 기존 휴대폰 정보에 실제로 드러나는 준비·마감·변경이다. 영역을 넓게 약속하기 전에 소스·업무 종류 단위로 지원 가능성을 판단한다.

## 실제 증거를 얻는 가장 작은 절차

1. 초기 참여자 5명의 동의를 받고, 기종·OS·실제 사용하는 소스·알림 설정을 확인한다. 특정 제조사나 소스가 있다고 가정하지 않는다.
2. 본제품 개발 여부와 분리한 최소 읽기 실험을 명시적으로 정한다. 처음에는 추천·알림을 보내지 않고 관찰만 하며 기존 공지 확인 방식을 유지한다. 현재 SDK/JDK·실기기·동의 데이터가 없어 이 실험은 미실행이다.
3. 7~14일을 초기 관찰 기간 후보로 두되 업무가 충분히 발생하지 않으면 판정을 보류한다. 참여자에게 매일 메모·캡처·업로드를 요구하지 않는다.
4. 끝에 연구용으로 짧게 원문과 수신 정보를 대조한다. 원문 확인은 동의한 기기에서 필요한 범위만 수행한다. 이 대조는 제품의 정상 입력 흐름으로 옮기지 않는다. 학교 등 관계자와의 계정·원문 접근이 필요한 경우 별도 권한 없이 접근하지 않는다.
5. 준비·마감·변경 각각에 대해 원문 업무 존재 / 실제 수신 / 필요한 내용 존재 / 최신 변경 감지 / 추가 사용자 입력 필요를 기록한다. 받은 알림만을 분모로 삼지 않는다.
6. 원천이 충분한 업무만 독립 정답과 비교하는 추출 시험으로 넘긴다. 원천 부족을 AI 정확도 문제로 오인하거나 추론으로 채우지 않는다.

관찰 주기·참여자 수는 운영 제안이며 통계적 성공 기준이 아니다. 제품이 전혀 관측하지 못한 머릿속 일까지 분모를 완전하게 아는 방법은 없으므로 측정 범위를 명시한다.

## 사전에 정할 판단

- **계속:** 반복적으로 필요한 업무 종류에서 원천과 변경을 자동 확보하고, 추가 기록 없이 유용한 업무를 생성할 근거가 생긴다. 그 소스·업무만 지원하는 제한 제품을 검토한다.
- **연동 경로 변경:** 내용은 필요하지만 알림에 없거나 최신 상태를 추적하지 못한다. 공급자가 허용한 공식 원문 API·동기화·제휴가 가능할 때만 그 조건과 운영비를 검토한다. 계약 가능성은 현재 미확인이다.
- **중단 또는 보류:** 충분한 자동 정보도 없고 저비용으로 유지할 수 있는 정당한 연결 경로도 없다. 핵심 기능을 수동 기록에 의존하도록 바꾼 뒤 동일 가설이 성공했다고 주장하지 않는다.

기본 판단은 ‘받은 100건을 잘 요약했다’가 아니라 **‘원래 챙겨야 하는 일 가운데 어떤 종류를 기록 없이 믿고 맡길 수 있는가’**다. 별도 반복 위임은 선택 기능으로 둘 수 있지만 핵심 가치 검증에서 제외한다.

## 제품 후보

충분한 소스가 입증되면 첫 제품은 ‘준비할 것·마감·변경을 자동 발견해, 필요한 순간에 묶어 알려주는 비서’로 제한한다. 초기 설정과 완료/미루기 표시를 제외한 반복 기록을 요구하지 않는다. 완료 표시의 부담도 측정하고 중요 상태를 관찰 없이 자동 완료로 만들지 않는다.

같은 정보를 매번 다시 읽게 만드는 경우, 미확인 질문이 과도한 경우, 원문을 여전히 모두 확인해야 하는 경우에는 순부담 감소가 미검증으로 남는다.

## 현재 끝낸 일과 남은 의존성

공식 API·공급자 문서 조사, 경쟁·수요·1인 경제성 검토, 합성 상태·수식 검사, 이 결정 절차의 문서화는 완료했다. 실제 소스 수신·최신성·고객 도움은 미검증이다. 사람의 동의나 실제 데이터 없이 이 결과를 만들어낼 수 없다. 이번 문서는 최소 실험을 실제로 수행했다거나 개발 승인을 받았다는 뜻이 아니다.
