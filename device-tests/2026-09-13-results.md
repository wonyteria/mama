## e알리미에서 확인한 원문 경로

1. 기존 보호자 로그인 상태에서 공지 목록을 열 수 있었다. 일반 공지와 홈페이지 연동 공지가 구분되어 있었다.
2. 대표 사례로 ‘2026학년도 2학기 학습준비물 안내’ 한 건을 열었다. 제출·회신·결제·외부 메시지 전송은 하지 않았다.
3. Android 화면 노드에서는 제목·발행일을 읽었지만 문서 본문은 텍스트 노드로 나오지 않았다. 화면에서는 문서 이미지처럼 보였다.
4. 공식 ‘전달하기’ 메뉴에 ‘링크 주소 복사’가 있었고, 해당 공지에 대해 앱이 제공한 단일 링크를 확인했다. 다른 문서 ID나 수신자 ID를 추측하지 않았다.
5. 그 링크를 PC에서 비밀번호·쿠키 없이 해당 공식 서버에 GET했을 때 HTTP200, 정확한 공지 제목을 얻었다. 링크는 접근 자격을 포함할 수 있어 공개 문서/검색/배포물에는 싣지 않는다.
6. 반환 HTML의 `#EditorHtml`에 PDF 객체가 있었고, 페이지가 직접 제공한 PDF 참조 한 건을 따라갔다.
7. PDF도 HTTP200으로 읽혔다. 73,589바이트, 1페이지, 암호화되지 않은 PDF였다.
8. pypdf로 본문1,334자를 추출했다. 제목·학교 지원 물품이라는 문구·학년별 표·발행일이 확인됐다. Poppler로 전체 페이지를 렌더링하여 휴대폰에서 본 문서와 대조했다.

**이 문서는 OCR이 필요하지 않았다.** 화면 노드에 글자가 없다는 것만으로 원문을 읽지 못한다고 판정하면 안 된다. PDF 안의 텍스트를 직접 얻는 것이 더 정확한 경로였다.

이 링크가 쿠키 없이 열렸다는 사실은 계정 전체가 공개되었다는 뜻이 아니다. 앱이 제공한 특정 공지의 링크만 사용했으며, 알지 못하는 문서 주소·토큰을 탐색하지 않았다.

## 의미 해석에서 발견한 위험

제목에 ‘학습준비물’이 있지만 본문 표는 **학교에서 지원하는 물품 목록**이다. 이를 부모가 사거나 챙겨야 하는 할 일로 변환하면 오탐이다. 발행일9월9일도 제출 마감으로 해석하면 안 된다.

이 사례의 제안 분류는 INFO이며, 개인 준비 요구가 별도로 확인되지 않는 한 구매/준비 Task를 만들지 않는다. 날짜·품목 추출뿐 아니라 **누가 무엇을 해야 하는지**를 원문에서 확인하는 평가 항목이 필요하다.

## 하이클래스 및 공개 홈페이지 확인

- 하이클래스는 실행되어 기존 계정의 홈·내 소식·학교 관련 영역이 표시됐다.
- 동적인 홈에서 UIAutomator가 안정적인 계층 덤프를 만들지 못했다. 화면 캡처는 가능했으며, 이를 보안상 텍스트 접근 금지로 단정하지 않는다.
- 개별 하이클래스 공지 본문·첨부·웹 세션·새 글 자동 발견은 미검증이다. 클래스 탭 이동도 확인 완료로 기록하지 않는다.
- 학교의 공식 공개 홈페이지에서 같은 제목·날짜·본문의 준비물 문서를 찾지 못했다. 1학기 준비물 안내는 다른 문서여서 대체 근거로 사용하지 않았다. 따라서 공개 학교 홈페이지만으로 해당 e알리미 공지를 대체할 수 있다는 증거는 없다.

## 단말에 남아 있는 상태와 미완료 작업

연결이 끊기기 전 마지막 확인 상태는 **도우미만 선택·수집 ON·시험 별칭·합성 알림1건**이다. 실제 e알리미·하이클래스의 지속 수집 설정으로 전환하는 작업은 아직 하지 못했다. 도우미 앱과 합성 알림 정리도 연결 복구 후 진행한다.

추가 미검증: 실제 기기 재부팅, 화면 잠금/장시간 절전, 실제 학교 앱의 신규 푸시 본문, 중복 callback의 실기기 재현, 전체 삭제·키 폐기, 반출 저장 UI, 여러 공지의 PDF/이미지/HWP 처리, 세션 유지·변경/삭제 감지.

읽기 진단 중 e알리미의 선택한 공지가 열람 처리됐을 수 있다. ‘모두 열람’·제출·회신 버튼은 누르지 않았다. 비밀번호 변경 알림은 서비스가 제공한 ‘다음에 변경하기’로 닫았으며 비밀번호를 변경하지 않았다.

## 다음 개발 판단

‘알림 수집 → 알려진 공지 링크 → HTML → PDF → 텍스트’ 중 **알려진 링크 이후 원문 확보**는 단일 실제 사례에서 성립했다. 핵심 미해결 구간은 **최초 계정 연결 후 새 공지 목록과 각 원문 링크를 자동으로 얻는 부분**이다.

다음 실험은 공식 보호자 웹에 최초1회 로그인한 세션에서 목록·문서 링크를 읽고, 이후 사용자가 원래 앱/웹을 열지 않아도 새 글·본문을 가져오는지 확인하는 것이다. 매번 수동 공유를 시키는 흐름으로 바꾸지 않는다.
